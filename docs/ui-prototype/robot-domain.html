接入第二个领域（化工）时：

领域 / 节点 / 词表 的关系

领域（插件包）往 vocab.py 这张全局表里加几个 kind；节点是本体里的实例，全局唯一，不属于任何领域。

一个领域贡献若干 kind（不是一对一）：机器人贡献 device function skill。

② 这一轮的改动：编译入口搬家

上一版把「编译为行为树」挂在技能节点上——语义不对，因为一棵树的主语是「一次任务编排」，不是某个技能。

上一版（错）

技能节点 → 点「编译为行为树」→ 出一棵树
  • 技能只是树的一部分 —— 缺参数、缺条件、缺实体绑定，编译不出完整的树
  • 把「编译」显得像轻量操作，实际上它是整条构建链
  • 同一棵树的入口分散在每个技能节点上

这一版（对）

本体构建页 → Tab「编排行为树」→ 输入自然语言 → 出一棵完整的树
  • 输入 = 自然语言描述 + 已建好的本体（技能 / 实体 / 条件 / 参数全部从本体引用）
  • 产物 = 一次任务编排（任务 + 树 + 编译清单），落在产物库
  • 技能节点上只保留只读的「被哪些任务引用」

为什么放进「本体构建」而不是新开一页

环节构建本体编排行为树是否复用

来源采集什么裁决依据

不能把行为树 XML 当"表"去算值域重叠 —— 那会产出看起来可信、实则伪造的 verified。
