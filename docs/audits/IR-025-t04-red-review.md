### 1. 保存、浏览和应用使用分开

在真实离线构建和脚本模型 TBox/ABox 构建期间，将应用评估入口设为“调用即失败”。
要求两类本体仍能构建入库，目录、详情、图谱、compatibility GET 均不运行应用检查。
首次点击行为树入口才创建检查报告；无历史显示尚未检查，不把合法但不完整的本体拒之库外。

### 2. 接口只信任后端取得的事实

拒绝空／重复引用、latest、跨资产版本、不存在任务、额外字段、伪造 ready、摘要、契约版本、执行器或策略。
复用 Host、Origin、JSON 和体积限制；错误请求不登记报告，不运行检查器或修复器。
未知入口为 400，缺少资产／任务为 404，未接通应用或关闭功能为 503。
有效请求发现缺项、不可支持、内容冲突或检查器错误，应保存可读诊断报告，而不是返回“成功且可生成”。

### 3. 报告可恢复，旧结论不会自动变成新许可

同一 request_id、相同输入重放原报告；相同 ID 不同输入返回冲突。
新 request_id 才产生新报告；历史报告自身不改写，当前读取视图另标 current／stale／unknown。
任务、环境、生命周期修订变化后，重放不重新检查，也不刷新旧报告为有效。
单独 Python 进程能读取原报告且不执行检查；老库 GET 不建库或迁移，写初始化才允许增量升级。
用 SQLite 故障触发器确认报告和幂等记录原子提交，不留下孤立报告或虚假 check_id。

### 4. 修复动作必须对应缺项和正确资源

只有报告中该 issue 提供且后端已注册的 action 才能执行。
本体版本、报告号和设计会话 revision 不能混用；目标资源变化／报告过期要拒绝修复。
动作携带原本体引用和任务上下文，支持修复后返回原任务。
顺序重放和并发重复只产生一次本地事务效果；失败回滚，重试身份不被污染。
GET 修复 URL 不执行动作；未实现处理器返回 unavailable，不能产生可点击死链接。

### 5. 直接生成仍有后端守卫

直接 POST 旧 generate API，不能靠 ready、旧 check_id、其他 application_id 或客户端策略绕过。
即使曾有 ready 报告，服务也必须重新读取事实并重新检查。
在真实任务 HTTP 链路中注入阻塞／不可用／存储故障，验证不会创建生成运行或候选 XML。
另有正向用例：守卫通过后运行真实原编译器，独立解析输出 XML，并核对运行绑定的本体固定版本。

### 6. UI 行为通过真实浏览器验证

使用本机 Chrome、隔离 Gunicorn 和真实数据库，没有拦截应用 API 来伪造成功响应。
详情与图谱入口都必须保留；点击后检查固定应用，显示缺项，不能提前受理生成任务。
刷新、重启服务后显示同一个 check_id，不能重复 POST 或调用模型。
可准备任务不等于已可生成，更不等于现场执行已验证。

## 本轮结果

T04 的 101 项中：96 项预期失败、5 项通过；0 收集错误、0 跳过。
失败来自缺少 CheckService／Blueprint、宿主路由未接入和仍存在的旧 UI／即时检查行为。
5 项通过为真实字节解析夹具基线及旧生成接口的 4 项防伪造基线。
另外运行的原 80 项核心测试和 53 项未迁移设计 HTTP 用例全部通过。
定向 lint／类型检查通过；结构化结果见 [T04 RED 记录](IR-025-t04-red-results.json)。

RED 用例中的后续断言尚需 T05 实现后实际走通；目前失败位置不是全部预期行为已获验证的证明。
本轮没有运行全量回归，预期失败未通过 skip、xfail 或空实现掩盖。
