## 调整后的交付

最终成功结果固定保存一份 design.json，内嵌 TBox、ABox、来源与证据、词表、用户消息、能力问题、澄清项、确认记录、覆盖报告、校验结果及版本／模型追溯信息。
用户下载该 JSON 即可读取全部业务内容，不需要拼接其他 JSON。
总 JSON 与 candidate.owl 同次提交且不可变；下载返回已登记的原始字节，不临时拼装当前状态。
不再分别保存 abox.json、coverage.json、validation.json 作为成功结果的业务工件。
manifest.json 继续作为平台内部的文件摘要登记，不承载总 JSON 缺失的业务内容，也不要求用户配套下载。
原始 XML 作为输入文件保留，JSON 包含来源信息、摘要与解析证据；此要求不扩展为嵌入原始上传字节。
TBox 阶段也提供该阶段完整 JSON；最终抽取新增包含实例和报告的完整快照，不覆盖确认骨架时的历史 JSON。
UI 主要下载项为“完整 JSON”和“OWL”，T07 实现存储与导出接点，T08/T09 验证及接入页面。

## 测试调整

仅修改尚未获覆盖确认的两份 T06 文件，没有修改 T03/T05 已审阅测试。
`test_robotics_design_assets.py` 检查完整 JSON 内嵌的实例、报告、来源证据、消息、词表和模型版本信息与实际结果一致。
用完整 JSON 自身的骨架、实例及证据重新导出 RDF，并与同版本 OWL 比较图同构，防止“总 JSON”只是一张分片文件索引。
导出接口必须返回磁盘登记的完整 JSON 字节；后续设计产生新版本，旧 JSON 下载字节保持不变。
缺口报告直接在完整 JSON 中校验；篡改覆盖字段会使整个文件校验失败。
`test_robotics_design_failures.py` 将原 ABox JSON 和覆盖 JSON 两个故障点合并为总 JSON 写入故障点，继续验证事务回滚、无可见假资产及显式重试。
因此用例从 83 调整为 82，覆盖要求没有通过删除失败断言来规避。
