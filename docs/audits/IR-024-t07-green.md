## 实现范围

`ontology_assets/design_schema.py` 显式迁移 schema5 至 schema6，保留旧运行、事件、工件、任务会话和历史文件字节。
新 runs.design_input 与旧 build_input 分开，SQL CHECK 禁止混合输入或借设计输入创建其他 operation。
新增会话、修订、操作回执、准入回执及执行领取记录；只读访问不迁移、不恢复、不探测模型。

`domain_runs/robotics_design_service.py` 实现统一来源准入、等待建模要求、分轮建模、类别／骨架确认、返回编辑、显式重试和中断恢复。
会话冻结来源、词表、模型身份与有效修订；操作重放返回原回执，不重复调用模型。
模型网络等待不持有数据库写事务或 RDF 锁；最终 RDF 语义复验在 SQLite 写事务前完成。
提交时再次核对固定运行和来源，恢复后的迟到工作进程不能覆盖新重试。
磁盘或数据库提交失败时事务回滚，不出现可见假成功资产；不可记录失败时保留运行供显式恢复。

`domain_runs/robotics_design_contracts.py` 验证固定来源、确认状态和实际 JSON／RDF 的一致性。
模型修订及本地确认保存不可变快照；最终 ABox 确定性抽取保存新的完整结果，不覆盖确认骨架时的旧快照。
完整 design.json 包含 TBox、ABox、证据、词表、消息、能力问题、澄清项、确认记录、覆盖及校验结果、模型与版本信息。
成功结果只登记完整 design.json、candidate.owl 和内部 manifest；不再分散存储 ABox／覆盖／校验业务 JSON。
文件摘要与输出版本同次事务登记，下载返回固定字节；后续编辑形成同一本体的子版本。

`ontology_assets/robotics_design.py` 提供候选详情、通用图谱、完整 JSON／OWL 读取及固定版本兼容性结果。
真实旧 UR 候选仍可支持应用；有效通用设计但不满足旧 UR 契约时为 unsupported，损坏文件或修订关联为 invalid。
既有 TaskService 和任务 HTTP 继续执行真实消费检查，不能用伪造 supported 元数据绕过。

`BuildService` 共用原准入指纹校验并支持内部模型会话分流；旧离线算法及其完成契约保持不变。
`RunStore` 扩展设计运行的读取、来源复验和 manifest，旧 manifest 不添加新字段或改写字节。
`_extractor.py` 在重建 XML 节点时规范化属性顺序，消除证据经 JSON 落盘后字典顺序变化对抽取数组顺序的影响，流程子节点顺序保持原语义。

## 当前验证

首轮 82 项：79 通过、3 失败。
两项失败来自成功回执包含空 error 字段，修正为仅失败时提供 error；另一项来自 JSON 往返后的属性遍历顺序差异，修正抽取器确定性。
没有修改已审阅测试或迁移夹具。
修正并调整最终 RDF 校验锁顺序后，82 项新测试与此前 141 项测试共 223 项通过，0 失败、0 跳过，用时 44.32 秒。
全量运行期间复核出本地确认快照的进程异常退出边界：数据库提交前遗留的固定路径文件可能阻塞再次确认。
将本地快照文件放在每次写入独立的目录下，保留数据库修订唯一约束；原注册下载不变，不把遗留文件视为有效版本。
实际子进程在完成 JSON 写入后 os._exit(71)，数据库行保持不变，相同请求重试成功，遗留文件不参与有效下载。
这项局部修复后再次运行全部 223 项定向检查，全部通过，用时 44.95 秒。
全量单元进程此前已加载旧版服务；最终代码以全量检查的未变部分、修复后的 223 项定向检查及实际进程退出诊断共同验证，不将旧源码摘要冒记为最终摘要。

## 边界

本阶段只在内部服务层提供完整模型设计能力；HTTP 模型上传仍明确返回 model_build_pending，capabilities 的 build_ready=false。
这避免在设计 HTTP、宿主后台调度和页面工作区接好前向用户开放一个无法完成的流程。
T08/T09 继续覆盖设计端点、公开下载与资格展示、真实后台运行和浏览器闭环；T10 执行真实模型试运行与人工语义评阅。
本轮模型响应均为明确的合成替身，没有调用真实模型或声称验证了自然语言建模质量。
