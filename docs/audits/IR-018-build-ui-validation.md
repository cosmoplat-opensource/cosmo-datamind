| 重试和历史 | failed/interrupted 才能重试；新 run 保留原来源和 retry_of；重试也检查容量/幂等，旧结果不改；读取与重启不重跑终态任务 | 可以追溯“第一次失败、第二次重试”，刷新不会重复构建 |

### 本次实现

- `BuildService` 在同一写事务内检查 request_id 和容量、登记两份来源、创建 queued 运行和初始事件、保存去重关联。重发跨进程/重启有效，输入冲突 409、容量满 429；重试创建固定输入的新运行，保留原历史。

- `BuildExecutor` 使用本地 flock 独占执行权，spawn 启动计算子进程，避免继承宿主锁和 RDF/SQLite 线程状态。父进程核对结果并持久提交；超时回收子进程，故障记录失败报告并释放名额。

- 下载按 run/artifact 登记校验路径、长度和实际摘要；拒绝符号链接、跨运行或损坏文件，响应不暴露内部路径。旧图谱只读引用与登记资产明确区分，不在 GET 时自动注册。
- 使用指南补充隔离 Gunicorn 启动、双 XML 上传、查询/下载/重试及配置命令，见 [机器人构建 API](../robotics-build-api.md)。

### 实现与页面入口

| 文件 / 入口 | 本批行为 |
|---|---|
| `ui/modules/robotics-build.js` / 本体构建 | 默认保留数据配方；能力读取完成后开放机器人表单；两角色独立上传、本地输入检查、单次在途提交、稳定重发编号；按真实阶段轮询、离页清理、终态停止、显式重试 |

| 同上 / 作业中心与下载 | 分组显示持久构建历史，20 项分页、深链回查；先检查 HTTP 状态再保存文件，409 完整性错误在页面提示 |
| `ui/index.html` / `ui/styles/robotics.css` | 沿用原导航、页面和样式；新模块独立加载，保留旧 graph/obj 深链；1440/768/390 宽度、键盘操作和恶意文本转义 |
| `scripts/check.py` | 在原九段检查之后新增 robotics-browser；该程序自建实际启用机器人功能的服务和临时根，不复用旧回归服务；原覆盖率和超时预算不变 |

机器人功能通过服务端 DATAMIND_ROBOTICS_ENABLED 开关控制；关闭时页面隐藏机器人配方，既有历史仍可只读回查，UI 没有新增管理员开关。
构建成功保持 candidate；不新增自动发布、补充业务证据、在线图谱编辑或任务生成 UI。
