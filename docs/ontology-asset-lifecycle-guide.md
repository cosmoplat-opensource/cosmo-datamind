# 本体回收站与恢复（DR-157 / IR-029）

本体库的“展示”可以切换“本体目录”和“回收站”；领域筛选同时适用于两者。
目录卡片或固定版本详情中的“移到回收站”先显示影响预览，点击确认才删除；取消不改变状态。
内置示例不显示删除操作；有任务正在排队或运行时，需要等任务结束后重新预览。

删除后，本体从默认目录和新的应用选择中移除，旧会话停止写入。
版本、原始来源、历史运行和下载文件保留，固定版本页面标记“已移到回收站”。
在回收站点击“恢复”，核对预览后确认；原本体 ID、版本和摘要保持不变。
恢复后请明确选择版本并重新检查或新建任务；旧会话和旧 ready 缓存不会自动复活。
若预览已过期、关联任务变化或同时有其他操作，弹窗保留错误并提供“重新检查”。

旧数据构建侧栏保留两次点击防误触，随后进入同样的确认预览。
旧 built／forged 文件仍存在不代表可以绕过删除状态；已迁移系统以固定版本和生命周期记录为准。
以前已经物理删除且没有快照的本体不能恢复，不会自动生成一份空本体。

## 部署与迁移

应用正常启动默认启用生命周期迁移（`DATAMIND_LIFECYCLE_ENABLED=1`）；升级前保留整个存储根和旧图谱／编辑文件备份。
迁移将数据库从 schema 8 升到 9，保留原有行和文件，为旧 key 另建固定版本与绑定。
GET 仅查询，不负责迁移；操作员也可在已配置相同存储环境的服务进程调用 `server.init_asset_lifecycle()`。
显式关闭启动开关只用于尚未启用的旧宿主；已持久化的生命周期守卫不能通过关闭开关撤销。
迁移失败时保留保护并记录“迁移未完成”，修复来源后重新显式初始化；不要手工删除状态表或扫描原文件重新导入。
schema 9 回退应使用支持该版本的代码或完整备份，不建议把数据库强制降级成 schema 8。

API：`POST /api/ontology-assets/<id>/deletion-preview` 或 `restoration-preview` 发送 `{}`。
确认向 `/delete` 或 `/restore` 发送预览的 `expected_revision`、`impact_sha256`、新的 `request_id`、`confirmed:true`；可附 `reason`。
同一请求重试复用 request_id，修改输入或重新预览使用新的 request_id。
不提供永久擦除接口。

IR029 已于 2026-11-17 完成最终人工验收及全量回归；本轮技术演练只操作临时工作副本，未重启原用户服务或迁移原用户数据库。

显式设置 `DATAMIND_ROBOTICS_ENABLED=0` 的旧宿主默认不自动创建域库存储；需要独立启用数据本体生命周期时明确设置 `DATAMIND_LIFECYCLE_ENABLED=1`。已持久化的绑定和删除守卫不受此启动默认值影响。
