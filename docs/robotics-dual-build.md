# 机器人本体双路径构建 — DR-070 / IR-024

IR-024 已于 2026-11-11 经用户确认交付；本指南描述本轮已实现的范围。
入口为“本体构建”中的“行为树 XML → 机器人本体”，地址 `#build?recipe=robotics`。
必须上传主行为树 XML、节点模型 XML；本轮没有仅凭自然语言建模的入口。

## 路径如何选择

服务端复用平台模型设置和已注册运行时判定路径，页面显示实际构建方式，没有手动模式切换。
未配置可用模型时走旧 `ur_pick_place` 离线构建；建模要求不参与离线算法，模型网络调用数为零。
配置了可支持的模型时走模型辅助设计；平台已有设置即可，不需要 Yang 工程的单独端点或服务。
配置不完整、不支持或调用失败时明确报错，不自动换模型或切换旧算法。
会话冻结模型身份和来源；中途改变配置后，旧会话可能拒绝继续，应恢复原配置或新建构建。
模型辅助设计通过平台运行时访问模型，使用外部端点时需要相应网络；旧构建算法可以离线运行。

## 模型路径操作

1. 填写名称，上传两份 XML，填写建模要求后提交。
   未填要求时会话等待输入，不自行开始模型设计。
2. 查看类别设计、能力问题和待明确项；需要补充时继续发送建模要求。
3. 点击“确认类别”。这是本地确认操作，进入关系与属性阶段，不会自动请求模型。
4. 点击“开始关系与属性设计”，或输入具体要求再发送，显式触发属性设计。
5. 核对关系、属性和待明确项；需要改变类别时使用“返回类别修改”，重新确认后再设计属性。
6. 点击“确认骨架并构建实例”。程序按照已确认 TBox 和 XML 规则生成 ABox，这一步不调用模型。
7. 完成后进入本体详情，查看结构、实例和覆盖报告，下载完整 JSON 和 OWL。

建模要求应说明业务用途和需要回答的问题，例如：

> 描述上传 XML 中的抓移放流程，区分原子技能、复合技能、实现、调用、端口、参数绑定和作用域变量；描述零件、工位、载具、放置位与感知、放置配置的关系。保留原始参数和来源，列出当前提取规则无法实例化的类别，不推测单位、实际设备状态或现场执行结果。

这段说明有助于 TBox 设计，但不能扩大 ABox 提取器已经实现的规则范围。
随意输入非空文本仍可能让模型根据 XML 和词表设计出骨架；当前没有“业务要求足够明确”这一强制语义门禁。
模型回复中的“确认”不替代页面上的结构化确认按钮。

## 保存、恢复和导出

刷新 `#build?recipe=robotics&session=<session_id>` 只读恢复会话；选择历史修订可以查看差异和同修订导出。
等待输入或确认时不占模型执行槽；排队和运行状态继续显示事件。
失败保留上一有效修订，通过显式重试创建可追溯运行；服务重启不会自动重放失联模型请求。
最终版本地址为 `#library?asset=<ontology_id>&version=<version_id>`，来源和文件摘要绑定固定版本。

模型路径最终提供两个主要文件：

- `candidate.owl`：已确认类别、关系、属性及规则抽取的实例。
- `design.json`：一个总文件，包含设计、ABox、来源证据、词表、消息、确认、模型身份、覆盖和校验结果。

最终 JSON 直接下载已经保存的字节；不是下载时重新请求模型或拼接，也不拆成多份业务 JSON。
历史修订 JSON 表达该阶段的设计，不应与最终总 JSON 混淆。
manifest 用于内部运行完整性和追溯，不替代总 JSON。
旧离线路径保留原有 OWL、报告和 manifest 工件。

## 如何理解图谱和检查结果

关系图按实例展示，类别和属性定义在详情和导出文件中查看。
业务对象、技能调用、参数与其他对象可以分组查看；统计区分当前显示数与总实例数。
没有业务实例时查看技能或全部实例，不应把业务组为空理解为整个本体为空。

“设计有效”表示符合设计工件契约；“覆盖完整”取决于来源、TBox 和提取规则；“可生成行为树”另由 UR 消费契约判定。
当前 ABox 重点覆盖技能、接口、调用、参数、绑定和流程变量，另有条件式的感知配置／零件类型提取。
TBox 声明了工位、槽位、位姿等类别，也不意味着当前规则能自动创建这些实例。
原始值可能已经保存到参数绑定，而尚未形成业务配置对象；遗漏及未映射术语应在报告中核对。

当前新候选若不符合 `ur-pick-place-owl-v2`，会显示不支持行为树应用，并从任务选择列表过滤；后端也独立检查。
这符合本轮准入设计，不能通过更改标记或放宽验证来开放。
新候选到抓移放应用的适配、业务提取扩展及整体流程重设计留待后续新 DR。
构建成功、生成候选和真实机器人执行成功是不同结果；本轮未验证现场执行。

## API、部署和复核

部署和功能开关沿用 [构建指南](robotics-build-ui.md)；存储 schema 逐步升级到 6，既有版本不被改写。
设计执行器复用平台单 worker/gthread 部署，以独立文件锁取得执行权，与旧构建执行器按 operation 分工。
升级前按现有部署流程备份存储；不要把存储根切换为未知 schema 或多机器共享调度目录。
关闭机器人功能后拒绝新的设计写操作，已有当前 schema 会话、运行和工件仍可只读访问。

公开 HTTP 的字段和错误见 [设计 HTTP 契约](../specs/contracts/robotics-design-http-ui-v1.md) 和 [设计服务契约](../specs/contracts/robotics-design-service-v1.md)。
核心迁入来源见 [上游摘要清单](../specs/sources/IR-024-yang-sources.json) 和 [包内迁入清单](../specs/sources/IR-024-t05-migration.json)。
运行时不依赖 Yang 工程目录，不加载其 `.env`、Web 服务或聊天模型客户端；ABox 不使用模型自由生成实例。

全量复核：`.venv/bin/python scripts/check.py --suite all`，Node 必须在 PATH 中。
检查使用隔离的临时工作区及本地合成模型端点，不使用业务模型密钥或修改用户资产。
真实模型的质量观察单独记录，不等同于确定性回归，也不证明所有业务知识完整。
