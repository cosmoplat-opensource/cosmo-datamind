## 目标 Goal

在 DataMind 仓库中形成可独立导入的机器人领域包，贯通“新来源 XML → RDF 候选 → 发布 OWL → 消费侧加载 → 严格候选生成”的离线链路。
第一阶段先验证业务内核与协议兼容，暂不接入平台 UI、HTTP API 或持久化运行平台。
演示成功必须来自本轮构建及显式演示补充资料，真实缺证据时仍应拒绝生成正式候选。
保留已有固定 UR 模板、技能调用身份、绑定与数据流语义，并区分作者草稿策略与严格生成策略。

用户先授权编写 IR，后要求按 SDD 继续，并明确确认 T02 测试覆盖；当前已执行 T01～T03。
下列标准是从现有讨论与 DR 整理出的验收草案，未声明已经人审通过，也不自动将关联 DR 改为 accepted。
实现阶段依次进行验收要求确认、失败测试及 review、实现、回归和人审交付。

### 最小业务内核约定

以下描述行为边界，具体 Python 函数名由实现阶段确定。

| 入口 | 输入 | 输出或行为 |
|---|---|---|
| 构建 | 两种来源 XML、受支持的 UR profile | RDF 候选、来源引用和结构问题；不自动确认业务映射 |
| 发布 | 候选图、受信发布协议与规则版本 | 自包含 OWL 及发布验证记录；不覆盖输入文件 |
| 加载 | 发布 OWL、real/demo 模式 | 消费上下文或明确的契约错误；不依赖源 XML/sidecar |
| 严格生成 | 固定消费上下文、结构化任务 | 候选和验证报告，或澄清/缺知识/不支持/错误结果 |
| 作者草稿 | 明确的草稿策略及不完整配置 | 保留未解决值与标记；禁止作为严格候选结果返回 |

当前阶段通过结构化任务或确定性模型替身驱动，六字段任务协议和六个公开技能输入分别验证。
演示补充资料只补业务实例、映射、参数依据与模拟证据，并记录变更；不得以替换整图的方式把旧演示 OWL 冒充新构建产物。
如果新构建模板与演示资料不兼容，应定位并修复适配或如实报告，不自动改变模板顺序。

## 验收 Acceptance

- [ ] **ROB-01 基线可复核**：夹具带来源、SHA-256 和用途；兼容矩阵区分已有成功、协议失败和策略差异；通过项与已知失败不混记。
- [ ] **ROB-02 包导入独立**：在不同工作目录及导入顺序下均可使用构建与消费模块，无 sys.path 注入和顶层 skill_runtime 名称碰撞；无需访问原归档路径。
- [ ] **ROB-03 语义不丢失**：构建保留技能、实现、调用、步骤顺序、端口类型、参数绑定和黑板作用域；重复 MoveL 调用保持独立，未知模板或冲突模型明确失败。
- [ ] **ROB-04 新产物可发布消费**：对本轮 XML 新构建的图发布后，实际消费加载器通过协议、受信 SHACL、模板/条件/绑定验证；不能只验证预置 agent OWL。
- [ ] **ROB-05 失败契约不放行**：未知协议、篡改规则、外部 imports、DTD/实体及不兼容语义均明确拒绝，不产生成功发布或严格候选结果。
- [ ] **ROB-06 真实缺知识仍阻断**：缺少业务映射、参数、确认或有效适配证据时返回具体问题且不写严格候选；对话选择或名称相似不自动升级为知识确认。
- [ ] **ROB-07 草稿与严格结果区分**：不完整配置可进入明确标记的作者草稿；同等缺口不能在严格入口返回 generated，未解决占位值不能混入正式候选。
- [ ] **ROB-08 固定模板保真**：完整受支持任务仅改变允许公开配置，原有四棵树及调用顺序、固定绑定保持一致；重排或任意技能组合请求不能被静默接受。
- [ ] **ROB-09 生成不回读来源**：发布后把源 XML 移走或设置读取拦截，生成结果仍可由 OWL 恢复；直接编译和任务生成两条入口均验证，输入摘要不变。
- [ ] **ROB-10 模式及状态准确**：demo 资料在 real 模式被拒绝，演示候选有明确标记；歧义/缺选择请求应澄清，未知任务不回退为 pick_place；所有成功候选仍为 execution_readiness=not_verified。
- [ ] **ROB-11 新链路可重放**：临时来源构建加显式演示补充，完成发布和编译；XML 按结构/调用/端口/数据流比较，报告追溯来源和补充资料，输入及原归档文件不被覆盖。
- [ ] **ROB-12 统一环境与回归**：在选定的 DataMind 虚拟环境执行全部本轮测试和现有全量检查；依赖、退出码、跳过原因与报告位置完整，已有数据应用及对话存储无新增回归。
- [ ] **ROB-13 用户可直接运行离线演示**：按下述命令在已安装工程依赖的环境运行，无需 UI、服务、线上模型或机器人；三类场景均检查实际结果，生成可读汇总及可追溯产物，异常放行或基础设施错误返回非零退出码，重复运行不覆盖旧结果。

### 离线演示命令与预期结果（待实现）

以下是本轮必须交付的命令契约，当前脚本尚未实现，不代表现在已经可执行。
依赖安装完成后，在工程根目录执行：

```bash
.venv/bin/python scripts/demo_robotics.py --case all --output-dir .check-results/robotics-demo
```

脚本使用仓库内随交付提供的 XML、节点模型、结构化任务与显式演示补充资料，不依赖原归档目录的绝对路径。
每次执行在 output-dir 下创建唯一运行子目录，并在终端打印绝对输出路径及逐场景的预期/实际状态、PASS/FAIL 和问题摘要。
演示必须调用实际构建、发布、加载和编译模块，禁止返回预先写好的成功报告或直接复制预置候选。

| 场景参数 | 演示路径 | 通过条件与主要产物 |
|---|---|---|
| `demo-success` | 新 XML 构建 → 显式演示知识补充 → 发布 → 加载 → 结构化任务 → 编译 | 生成本轮 published.owl、demo_candidate.xml、validation_report.json 和来源摘要，标记 demo 与执行未验证 |
| `real-missing-evidence` | 新构建真实知识 → 发布加载 → 缺证据任务 | 明确返回 needs_information 及缺口报告，不生成候选 XML |
| `invalid-contract` | 对本轮发布物的独立副本篡改契约或规则 → 消费加载 | 加载明确拒绝并记录原因，不进入编译或生成候选 |

`--case` 可分别指定上表任一场景，`all` 执行三类场景并汇总。
输出根目录中的本次子目录包含 summary.json 和 summary.md，每个场景使用独立子目录，记录实际存在的工件路径和摘要。
负向场景按预期拒绝算作场景 PASS，但仍保留业务拒绝状态，不伪装为生成成功。
只有所有所选场景达到预期且产物检查通过才退出 0，意外生成、预期成功却失败、输入缺失或运行异常均返回非零；不得把所有异常都视为负向场景成功。
输出不得覆盖来源夹具、已发布输入、用户 workdir 或已有演示结果，输入摘要在运行前后保持一致。
演示说明同时给出“不存在候选文件”的核对方式，避免旧文件被误认为本轮成功结果。
