- **状态 / Status**：in-progress。
- **日期 / Date**：2026-11-05。

- **当前环节**：T05 GREEN：轻量任务服务、补齐保存、HTTP、页面及离线演示已实现，最终全量 12 段通过；下一步 T06 人工验收与整轮交付确认。

## 目标 Goal

让用户在 DataMind 中完成 Yang 的核心流程：获得本体、描述任务、回答必要澄清、查看和下载行为树。
任务所需参数、业务映射或适配信息不足时，在当前任务页完成轻量补齐，无需外部本体编辑器。
默认界面只显示当前版本，不要求用户理解固定版本/编辑底本/工作头，不把治理表单放在生成前面。
沿用现有构建、RDF/OWL、编译验证和持久化能力，补齐自然语言任务入口与 UI 联动。

### 实际使用路径

| 步骤 | 用户看到什么 | 用户主要操作 |
|---|---|---|
| 1. 准备本体 | 现有成对 XML 构建入口，构建模板沿用；也可选择已有本体或导入符合契约的 OWL | 构建；完成后点击“生成行为树” |
| 2. 描述任务 | 当前本体名称、一个当前版本号、任务输入框、模型可用状态 | 输入自然语言任务，点击“生成行为树” |
| 3. 补充选择 | 本次需要明确的零件或目标，候选使用易读名称 | 回答或点击候选；不填写通用知识表单 |
| 4. 补齐生成信息（按需） | 仅当前任务缺少或失效的映射、参数、适配项；已有有效项不出现输入框 | 选择/新建关联对象、补参数、提供依据并明确确认当前适配范围；保存并继续 |
| 5. 查看结果 | 简单的行为树层级预览、结论、XML 下载；参数来源/验证报告折叠 | 查看、下载，或开始新任务 |

缺口为空直接生成；尚缺内容时保留已填内容并提示下一项，不强制先补完整个本体库。
OWL 下载/导入为可选入口，不作为补齐知识的必经路径，不要求使用 Protégé。
本轮仅提供只读行为树预览，不新增三个图画布、通用知识编辑器或 XML 在线编辑器。
基础页只保留一个简短的离线用途说明，不重复展示三组技术状态。

## 轻量“补齐生成信息”契约

### 展示与依赖顺序

先澄清任务选择，再按该任务涉及的零件、零件类型、工位、载具、槽位及其参数配置计算缺口。
“缺少”包括不存在、值无效、尚未明确确认、适配依据已到期/被撤销/不匹配当前配置；不只检查空字符串。
输入框只针对当前缺口生成，已有效的字段和其他任务的对象不进入待办表单。
必要的对象名称/当前值可作为只读上下文；不能因此把所有参数再次展开成必填项。
依赖尚未确定时逐步展开：先选择映射，再检查其参数，最后核对当前配置的适配依据，不为未知对象编造下游缺口。
已有 grounding 的提前返回和通用 invalid_profile 不足以直接驱动逐字段表单；新增 task_completion 投影读取真实 RDF 并复用字段规则，不另建配置真相源。

| 类别 | 何时出现 | 最小交互 |
|---|---|---|
| 业务映射 | 当前任务缺少或存在冲突的零件→类型、工位→载具、载具→槽位、类型→感知配置、槽位→放置配置关联 | 使用名称选择已有对象；没有合适对象时在原位新建，系统生成 IRI；只修改当前关联，不删除兄弟载具/槽位 |
| 参数设置 | 选定配置的公开字段缺失、占位或不合法 | 只补对应的物体名、模型名、阈值、曝光时间、拍照关节位或放置位姿；已有值复用，格式检查复用 IR-019 |
| 参数关联 | 当前配置没有拍照关节配置或目标位姿节点 | 选择已有配置或在当前步骤创建；需要单位/坐标系说明时只呈现缺失的必要项，不猜测物理值 |
| 业务/配置确认 | 当前任务依赖仍为来源提取/待确认状态 | 展示当前范围和已有值供用户核对，一次明确确认该范围，不要求重填有效参数 |
| 任务适配 | 当前零件类型与抓取实现、目标槽位与放置实现缺少有效适配依据 | 显示实际范围，提供依据说明/引用及有效期，按需上传资料；用户明确确认，后台绑定实际来源与配置摘要 |

适配不是自动标定，参数语法正确也不能自动成为适配通过。
有效期不使用无限远默认值，依据不自动填写“已验证”；缺依据允许保存已填信息但仍阻止严格候选生成。
不要求用户输入 actor/reason、IRI、版本摘要或工作头；后端记录“本地会话提交”等真实来源，说明不是已认证个人签名。
用于适配的依据和明确确认来自用户实际提交；审计字段可记录动作名称，但不得伪造物理事实。
IR-019 公开治理接口的署名/理由要求维持；轻量服务复用底层编辑/证据校验并增加自身操作来源记录，不冒充通过旧人工审核。

### 保存、接续与重新校验

“保存并继续”仅提交本次展示的缺口答案；后端根据当前任务、固定版本及最新缺口重新校验允许修改的对象和字段。
值或映射保存不自动确认知识；有明确确认的项才记录确认行为。
一批补齐原子保存为新候选版本，原版本不覆盖；当前任务的会话引用显式推进，用户仍只看到一个当前版本。
手动切换本体/模式仍建立新会话；本任务补齐导致版本更新不清空用户刚明确的任务，但必须重新解析对象关联。
改变任务目标后重新计算缺口；旧表单不能写入新任务，迟到响应不能覆盖新表单，旧候选下载失效。
映射/参数变化后，已有适配依据重新按当前范围与配置摘要判断；不允许继承已失效确认。
补齐后从保存的 OWL 重新读取并执行严格生成，不把表单 JSON 直接当作编译配置。
失败可继续修改，未填完不生成候选；模型或保存错误不显示上一次成功产物。
不增加多用户协作管理界面，但保留已有版本校验和事务，不牺牲基础数据正确性。

## T02 固定的 Python 契约

`domains.robotics.task_model.ModelClient(base_url, model, api_key, timeout=30, transport=None)` 提供 `parse(messages, catalog)` 和 `status()`。
`ModelClient.from_datamind(config=..., environ=..., transport=...)` 接收 DataMind 配置快照与环境快照，不另造 BT_AGENT_* 配置入口。
有效环境值优先于 llm 配置，task_models.bt_extract 优先于默认模型；没有覆盖则沿用默认模型。
`transport(url=..., payload=..., headers=..., timeout=...)` 返回 Chat Completions envelope，仅为替换外部网络提供测试边界。
生产默认 transport 必须真的发 HTTP，连接异常、响应限制和不转发凭据的跳转规则在 T04 验证。
`ModelError` 有稳定 `code` 和可向用户展示的信息；`status()` 不泄露密钥。
`validate_task(task)` 校验六字段及长度，支持 pick_place、unsupported 或未明确的 null 操作。
`domains.robotics.task_dialogue.catalog_from_graph(graph)` 只提供业务名称目录，不传位姿、阈值等机器人配置。
目录项为 `kind, id, label, aliases`，id 使用完整 IRI，保留同名对象区别。
`grounded_mentions(task, messages, catalog)` 返回四字段请求与澄清问题，只重放用户明确选择；已解析对象用完整 IRI，未知名称保留供原 grounding 报错。
唯一上级推导仍由已有 grounding 根据实际 RDF 关系完成，不由模型猜测。

## T02 追加：当前任务缺口投影

新增 `domains.robotics.task_completion.inspect_gaps(graph, task, *, mode, now=None, revocations=())` 的只读行为契约。
输入为固定本体的 RDF 图与六字段任务，输出 `status, items, execution_readiness`。
status 为 ready / needs_clarification / needs_information / unsupported / error；ready 仅表示补齐项为空，不代替最终编译验证。
每个缺口项至少含 `id, kind, entity_iri, field, label, reason`；kind 为 mapping / parameter / confirmation / applicability。
field 为实际属性名或 grasp_compatibility / placement_compatibility，完整身份只用于后台绑定，界面显示 label。
缺口 id 对同一图/任务/缺口稳定，不能跨图版本作为修改授权；写入服务仍需重新检查。
业务对象尚未选定时返回 needs_clarification 且 items 为空；未登记对象的就地创建操作由 T04 以用户明确的创建意图验证。
部分映射缺失时可以返回已明确范围的映射缺口，但不可对未知下游对象生成参数/适配表单。
未填写的参数仅生成输入项；source_extracted 等待确认状态生成确认项，已有值不重复成为参数输入项。
该 API 不修改 RDF、不生成 XML、不创建运行或版本；现有 grounding、authoring 和 evidence 是规则依据。

### T04 固定的应用边界与轻量交互

本节把已确定的产品范围转为可测试接口，不表示 T05 已实现。
详细覆盖、旧入口处理和实际运行结果见 [T04 测试覆盖说明](../../docs/audits/IR-020-t04-coverage.md)。

`domain_runs.robotics_task_service.TaskService(root, model_client=None)` 复用现有资产和运行存储，默认模型来自 DataMind 配置。
提供 start / get / message / choose / complete / read_candidate；用户输入不直接变成编译配置。
start 固定 ontology_id、version_id、mode 和 request_id；message 接收 text、expected_revision、request_id。
complete 接收 answers、expected_revision、request_id；revision 和请求标识由页面自动处理，不让用户填写。
会话至少返回 session_id、ontology_id、version_id、mode、revision、messages、task、status、gaps、run_id、tree、candidate。
开始为空闲 idle；调用模型期间允许 running；完成后为 generated / needs_clarification / needs_information / unsupported / error。
补齐提交只携带 gap_id 与对应 value / target / create / confirmed / reference / valid_until / source_asset_ids，不接受任意 RDF 编辑或客户自报的证据范围和摘要。
新建对象仅提交 kind 和 label，后台分配身份；不自动合并同名对象，不接受客户端强行指定 IRI 或 confirmed。
已有任务目标缺少实体时，由 choose 接收明确的 field 与 target 或 create 意图；模型提及陌生名字不能自动创建对象。
重复请求返回原结果；同一 request_id 改内容报 request_conflict，旧 revision 的新提交报 session_conflict。
数据落盘失败保持旧会话和旧版本，输入由前端保留，同请求可重试。
新版本 metadata.task_completion 记录 session_id、origin=local_session、authenticated_actor=false；不冒充已认证人工审核。

`AssetStore.load_robotics_application` 保持与严格消费者相同的结构复验，但允许未发布候选试用；不修改旧 load_robotics 的发布要求。
任务补齐读取与严格生成是不同门槛：已保存但缺参数/关系的候选可以读取并投影缺口，不能先要求它通过完整 SHACL 才允许打开补齐页。
补齐读取必须核对固定字节与契约，不允许把损坏的技能执行结构当成可填写参数。
此区分沿用 IR-019 候选可保存尚不完整 RDF 的能力，不修改原 SHACL、发布器或严格生成器以放行半成品。
补齐完成后重新读取实际 OWL，通过严格消费者、编译与符号验证才产生候选 XML。

HTTP 使用 `/api/robotics/tasks` 建立会话，`/{session_id}` 回看，`/messages` 提交自然语言，`/completion` 提交补齐，`/choices` 提交明确选择/创建，`/candidate?revision=...` 下载本任务当前结果。
`/api/robotics/imports` 接收可选 OWL 导入；完整校验后存为候选，不自动发布。
适配附件复用已有 `/api/ontology-assets/{ontology_id}/evidence-sources`；上传本身不改变任务确认状态。
错误保留稳定 code/message，应用级保护及现有文件大小限制继续生效。
任务的旧下载链接在任务变化后失效；历史 RunStore 产物保持不可变，历史下载能力不被删除。
只读预览 tree 使用 tag / attributes / children 层级，由同次运行的实际 XML 生成。

基础路由为 `#robotics-task`，从构建结果或本体入口进入；刷新恢复 URL 中对应的会话，不自动重新提交任务。
只显示一个“当前版本”；模型未配置时展示设置提示，配置复用引擎设置中的 bt_extract 可选覆盖。
已有有效参数不重复输入，真正缺值时留空，仅给格式提示；未确认来源值以只读上下文呈现。
当前任务的知识确认合并为一个明确勾选“我已核对当前任务知识”，后台仍记录具体对象范围，不出现逐对象重复署名表单。
适配项展示各自实际范围，填写依据和有效期，可选上传附件；明确勾选“我确认以上依据适用于当前范围”后才计为确认。
高级治理不在默认生成路径中；兼容旧显式知识/评审路由，不删除已有后端和冻结测试。
