# IR-028 · 本体删除恢复与历史保留

- **状态 / Status**：proposed（规约草案，未进入实现）。
- **日期 / Date**：2026-11-12。
- **关联 / Refs**：[DR-074](../decisions/DR-074-ontology-asset-lifecycle.md)。

## 目标 Goal

旧数据构建有 /api/build/delete，直接删除 built_*.json；机器人注册资产无对应统一删除入口。现有删除对象／关系与整份资产删除不同。
可与 IR-026 并行；IR-025 提供执行前生命周期检查接点，IR-027 配合旧 graph key。

## 交付 Deliverables

- [ ] 冻结接口、状态语义和兼容规则。
- [ ] 对应服务、存储／适配实现及前端接点。
- [ ] 失败诊断、来源与版本追溯。
- [ ] 红绿测试、迁移验证、全量回归和使用文档。

## 任务 Tasks

- [ ] T01：冻结 active／deleted 状态、引用预览、冲突和恢复规则、旧 key 映射及迁移顺序；确认 OAL-01～04。

- [ ] T02：RED：覆盖删除／恢复、共享来源、历史保留、内置资产保护、revision 与幂等；提交人审。

- [ ] T03：GREEN：实现生命周期存储、影响预览、审计和旧 built key 快照／tombstone 适配。

- [ ] T04：RED：覆盖排队竞态、等待输入冻结、旧删除接口、文件扫描、缓存和重启；提交人审。

- [ ] T05：GREEN：统一所有入口的生命周期守卫，接删除确认与恢复操作，保留历史查看和下载。

- [ ] T06：在工作数据副本上演练迁移、删除、恢复和失败回退；全量回归并人审交付。

## 验收 Acceptance

- [ ] OAL-01：数据与机器人资产均可逻辑删除和恢复，默认目录不显示已删除资产。
- [ ] OAL-02：历史运行／下载仍可核对，来源未误删；恢复保留原版本和摘要。
- [ ] OAL-03：并发受理、重复删除、旧 key、缓存和直接 API 不能绕过删除状态。
- [ ] OAL-04：内置 demo 不可删除；用户确认前只预览影响，不执行删除。
- [ ] 现有全量检查通过；没有修改已审测试来放宽要求。

## 回退与交付

新增能力使用服务端开关和版本化配置；回退不改写既有资产。
检查与运行记录保持可追溯，删除保护和执行守卫不可因关闭展示功能而绕过。
测试路径在 T02/T04 创建后进入正式 requirements；当前只登记 planned_requirements，不宣称通过。
