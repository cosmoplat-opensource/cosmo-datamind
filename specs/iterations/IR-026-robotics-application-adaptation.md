依赖 IR-025；执行事实适配、业务补全和工件升级分别形成可评审任务。
按 2026-11-13 用户确认的补充范围，执行结构适配在 TBox＋ABox 构建完成后自动匹配消费者角色。
规范对应通过后直接生成应用版本，只有无法确定的对应才由用户补选并一次确认生成；构建直接入库及应用检查只读的边界不变。

## T05 补充：自动角色匹配与应用生成（2026-11-13）

用户明确要求增加自动匹配：通过时无需手动点击“确认并生成应用版本”，无法确定的对应才交由用户填写。
本次将原默认人工确认／提交流程调整为自动路径和人工例外路径，未把应用类别提前注入通用本体构建。

### 实现与交互

用户在应用检查中显式点击“补齐执行结构”，或提交公开应用准备请求时，后端尝试自动匹配。
自动规则为已知受控词表快照、规范角色 ID 和实体种类一致，并通过现有覆盖、层次、关系方向、范围和类型校验。
不调用 LLM 或按名称相似度猜测异名对应；未知词表及无法确定的角色进入人工核对。
自动通过后，在同一事务中保存可信映射和匹配依据并登记持久运行；UI 只显示生成进度及结果。
人工分支保留已知对应，显示待核对角色及实际本体术语选项；一次“确认并生成应用版本”完成整份映射校验及入队。
客户端不能提供 confirmed、automatic 等授权字段，错误映射不留下部分确认或运行。
原分步确认接口继续兼容；GET、刷新、宿主重启及历史待确认记录的读取都不触发新生成，失败后仍需显式重试。
来源完整性、固定版本、工作头 CAS、幂等和原任务切换守卫保留；总 JSON 记录自动／人工方式及规则版本，旧本体版本保持不变。
应用版本生成后仍需复检和任务业务补全，不自动制造零件、工位、载具或槽位，也不代表现场执行已验证。
