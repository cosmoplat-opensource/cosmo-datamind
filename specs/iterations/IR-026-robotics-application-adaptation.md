# IR-026 · 机器人应用检查与可追溯补全

- **状态 / Status**：proposed（规约草案，未进入实现）。
- **日期 / Date**：2026-11-12。
- **关联 / Refs**：[DR-072](../decisions/DR-072-robotics-application-adaptation.md)。

## 目标 Goal

新本体可以保存 360 个实例，但缺少当前 UR 消费者需要的执行字段与业务配置。类别齐全也不能替代提取和消费者适配。
依赖 IR-025；执行事实适配、业务补全和工件升级分别形成可评审任务。

## 交付 Deliverables

- [ ] 冻结接口、状态语义和兼容规则。
- [ ] 对应服务、存储／适配实现及前端接点。
- [ ] 失败诊断、来源与版本追溯。
- [ ] 红绿测试、迁移验证、全量回归和使用文档。

## 任务 Tasks

- [ ] T01：冻结 UR 抓移放角色清单、执行字段、提取来源、工件新版本及新旧语义对照；确认 RAC-01～05。

- [ ] T02：RED：覆盖 TBox 缺项、调用顺序、scope、端口绑定、静态／动态值歧义与来源损坏；提交人审。

- [ ] T03：GREEN：扩展确定性提取和角色适配，保存原实例映射、派生版本及自包含执行结构。

- [ ] T04：RED：覆盖构建直接入库、行为树按钮触发诊断、TBox 修订返回、任务业务补全、重复确认、新旧行为树对照及 JSON／OWL 一致性；提交人审。

- [ ] T05：GREEN：接通修订／适配／补全流程，复用消费者、编译器和校验器；验证移走源 XML 后仍可生成。

- [ ] T06：以真实新本体副本和旧 UR 样例完成端到端验证；回归 offline／strict 差异，完成工件升级说明及人审交付。

## 验收 Acceptance

- [ ] RAC-01：现有 llm自动构建版本可直接浏览；点击行为树入口后只读诊断 TBox、执行元数据和业务关联缺项，原字节不变。
- [ ] RAC-02：完善后同一 XML 和业务配置下新旧生成的执行结构、参数语义一致。
- [ ] RAC-03：只修改公开配置；变量歧义、类型冲突和缺技能顺序阻止生成。
- [ ] RAC-04：业务缺项可进入补全，未补齐不能生成；完整 JSON 与 OWL 同版本一致。
- [ ] RAC-05：生成不需要访问原 XML；旧 UR 路径和离线／严格模式语义不退化。
- [ ] 现有全量检查通过；没有修改已审测试来放宽要求。

## 回退与交付

新增能力使用服务端开关和版本化配置；回退不改写既有资产。
检查与运行记录保持可追溯，删除保护和执行守卫不可因关闭展示功能而绕过。
测试路径在 T02/T04 创建后进入正式 requirements；当前只登记 planned_requirements，不宣称通过。
