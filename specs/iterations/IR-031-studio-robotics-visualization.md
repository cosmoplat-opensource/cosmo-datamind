# IR-031 · Studio 共享图谱与机器人连续可视化

- **状态 / Status**：in-progress（T01 契约冻结，准备 T02 RED）。
- **日期 / Date**：2026-11-17。
- **关联 / Refs**：[DR-159](../decisions/DR-159-studio-ontology-visualization.md)、[IR-024](IR-024-robotics-dual-build.md)、[IR-027](IR-027-ontology-detail-experience.md)、[IR-032](IR-032-studio-data-visualization.md)。
- **工作分支 / Branch**：`feat/studio-ui-integration`。

## 目标 Goal

落实用户选定的第一步：提取共享 Studio 组件，完成机器人“类别 → 关系／属性 → 实例”的连续可视化，并统一已保存本体的浏览体验。
保留 Studio 的类别圆圈、动态布局、拖拽联动、双击展开实例和详情交互。
现有建模输入、阶段确认、历史修订和固定版本成为可视化的数据来源与操作边界。
用户需求及两步范围来自本次对话；下列验收是对这些要求的可检查表述，待随规约评审确认，不表示用户已经验收通过。

本轮包括 LLM 设计会话、对应完成候选及旧离线机器人本体的只读浏览。
不包括新模型协议、逐 token 图更新、OWL 推理、数据本体实例化、Studio 任意编辑器或任务行为树渲染替换。

## 任务 Tasks（每项一次提交）

1. **T01：冻结组件和机器人视图契约。**
   创建 `specs/contracts/studio-graph-view-v1.md`，规定组件输入／回调／销毁、来源身份、节点边标识、原始记录映射、属性呈现和 unionOf 语义。
   固定设计 revision、确认快照与产物版本的衔接，历史查看与当前编辑状态分离。
   盘点现有 `ontology_assets/detail_view.py`、`robotics_design.py` 及领域视图，确定可复用投影与必须补充的语义字段。
   登记附件核心文件摘要与迁移范围，选取可脱敏的代表性本体和小型手算期望图。
   冻结常规／大类别的数量、分批策略及 1440px／390px 布局验收场景。
   在明确的浏览器和设备环境下记录首次可交互、拖拽响应及反复进出资源释放的具体判据；不得等实现后按结果降低标准。

2. **T02：投影与共享组件 RED。**
   编写类别／属性／实例、继承／并集、多类型去重、空集、损坏固定版本、稳定标识与不同来源隔离的失败用例。
   编写增量更新、暂停／固定、多个 SVG 实例、销毁及迟到响应的组件行为测试。
   将本轮已落地测试从 `planned_requirements` 移入正式 `requirements`，保留 criterion 与 ID。
   测试文件和函数路径以真实落地为准；需要 Node 的行为通过 pytest 包装入口纳入追溯。
   记录针对缺失行为的失败断言，环境或依赖错误不能充当 RED，提交测试人审。

3. **T03：投影与共享组件 GREEN。**
   迁入所需渲染、布局、标签和图状态代码，建立受控适配器，修复 SVG 标识冲突与资源释放。
   补充只读投影所需字段，保留完整 IRI、表达式与原始语义数据。
   以最小实现满足 T02，不修改已审测试断言来迁就实现。
   新文件头及关键兼容点关联 DR-159，运行相关单元、组件和 HTTP 回归。

4. **T04：构建与浏览集成 RED。**
   使用真实页面和隔离服务，覆盖类别生成、确认后补关系属性、修改删除、失败重试、返回类别修改和构建实例。
   覆盖历史修订、刷新恢复、候选打开、旧离线本体、同类实例展开收起、超量继续查看和快速切换资产。
   用鼠标动作验证拖拽时邻居移动，验证位置保留而不是每轮重置，并检查固定／释放与双击。
   新增对状态、请求次数和持久化数据的断言，证明只读浏览不触发模型或写入。
   完成余下验收映射并提交 RED 人审。

5. **T05：机器人页面集成 GREEN。**
   在设计工作区挂载长期存在的共享画布，依真实来源和 revision 更新，不随输入框通知销毁重建。
   接入确认、历史、错误及结果版本衔接，将固定版本关系页升级为类别与实例统一浏览。
   实现大类别分批及完整数量、无实例说明、局部范围与继续查看入口。
   保留原有应用检查、详情修复、任务生成入口和来源流程隐藏规则。
   运行组件、设计、固定版本、生命周期及应用入口相关回归并完成性能验证。

6. **T06：完整回归与人审交付。**
   在隔离数据与用户样例副本上完成视觉和交互验证，保存截图、操作结果、规模与浏览器配置。
   运行 `python scripts/check.py --suite all`，新增测试及浏览器入口须纳入标准检查链或明确记录同轮执行证据。
   记录当前提交／工作树摘要、RED／GREEN、失败修复、跳过原因和性能实测，不沿用其它 IR 的通过数字。
   更新使用说明和实际验收映射，按 Deliverables／Acceptance 提交人审。
   用户确认后勾选交付项并标记 delivered，再进入 IR-032 的实现。

## 验收 Acceptance

- [ ] **STV-R01**：机器人设计按已保存修订依次显示类别、关系与属性、实例，等待和失败不虚构结果，返回修改阶段清除失效内容。
- [ ] **STV-R02**：同一来源的增量更新保留有效布局、缩放、选择与展开状态，新增修改删除可辨识，历史与迟到响应不能覆盖当前设计。
- [ ] **STV-R03**：Studio 风格类别圆圈和关系标签可读，拖拽产生力导向联动，固定释放、搜索、缩放及键盘详情入口可用。
- [ ] **STV-R04**：双击类别可展开收起全部可访问的显式归属实例，多类型去重，无实例明确说明，大类别分批显示准确数量且可继续访问。
- [ ] **STV-R05**：固定版本新旧机器人本体使用同一浏览体验，保留类别关系、实例事实、属性及并集含义，并按版本摘要验证来源。
- [ ] **STV-R06**：画布只读操作不触发模型或本体写入，多画布并存与销毁不串状态，错误不会显示另一资产作为成功结果。
- [ ] STV-R01～06 均有实际存在的行为测试，计划项没有被误记为已覆盖。
- [ ] T01 冻结的浏览器交互、规模和性能判据通过，实际截图保留 Studio 主要风格且详情文字可读。
- [ ] `python scripts/check.py --suite all` 对当前代码通过，既有 lint、类型、覆盖率及相关浏览器门禁不降低。
- [ ] 用户确认交付后才将本 IR 标记 delivered。
