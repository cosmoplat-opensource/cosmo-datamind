# IR-032 · 数据本体接入 Studio 画布与业务交互

- **状态 / Status**：in-progress（规约编写阶段；实现依赖 IR-031 交付）。
- **日期 / Date**：2026-11-17。
- **关联 / Refs**：[DR-159](../decisions/DR-159-studio-ontology-visualization.md)、[IR-031](IR-031-studio-robotics-visualization.md)、[DR-114](../decisions/DR-114-relation-identity-includes-role.md)、[DR-158](../decisions/DR-158-master-development-integration.md)。
- **工作分支 / Branch**：`feat/studio-ui-integration`。

## 目标 Goal

落实用户选定的第二步：数据本体主图和构建完成结果预览使用共享 Studio 组件，保留问数锚定、证据状态、详情与评审功能。
共享交互风格，同时完整保留业务概念、事件、动作、绑定表和不同角色关系的含义。
用户选定的范围不包含数据本体构建中的逐步图谱增量，也不包含双击加载数据库全部业务记录。
本轮不改 SQL 生成、关系裁决或发布规则；仅为接回身份、详情和评审补充必要投影及寻址接口。
验收条目来自用户选择的保留要求及现有主线兼容约束，待随规约评审确认。

## 交付 Deliverables

- [ ] T01 数据本体视图适配契约及共享协议兼容规则。
- [ ] 数据 IR 至共享视图的适配器，包含范围身份、证据状态、关系角色与原始业务记录引用。
- [ ] 主图与构建完成预览的统一组件接入及作业恢复、取消、错误和导航适配。
- [ ] 问数高亮、节点与关系详情、准确关系评审及撤销后的画布同步。
- [ ] STV-D01～06 行为测试、RED／GREEN、跨领域浏览器与性能验证证据。
- [ ] 当前代码全量回归、使用说明和人审交付记录。

## 任务 Tasks（每项一次提交）

1. **T01：冻结数据适配契约与兼容边界。**
   基于 IR-031 交付的 `studio-graph-view-v1.md` 增加数据领域约束，必要时拆分 `studio-data-view-v1.md`。
   盘点 `server.py::ir_to_graph`、对象／关系详情、`ir_shape` 的 role/ref、问数锚定、评审和构建作业实际数据流。
   明确当前数据库、graph key、内容修订和构建结果身份，禁止隐式切回其它数据库或第一张图。
   固定高亮、证据、选中和本轮变化的视觉组合规则及图例，避免一种颜色承载互相冲突的含义。
   固定无角色旧关系与同端点多角色关系的寻址，以及候选、发布、删除和历史阅读边界。
   冻结真实样例规模、多预览场景及性能指标；共享协议变更须同步验证机器人适配。

2. **T02：数据投影与详情寻址 RED。**
   覆盖对象／事件／动作、孤立节点、自环、多角色平行边、证据状态和数据源身份不丢失。
   覆盖无角色歧义拒绝、role/ref 查询详情及评审准确定位，同名不同库不混用。
   覆盖固定快照与仅 legacy key 的结果预览语义、删除和发布检查，以及旧详情响应串入新选择。
   将已实现测试移入正式 acceptance 映射并提交 RED 人审。

3. **T03：数据适配与读取接点 GREEN。**
   完成数据图适配器，按需补充当前投影和详情接口的 role/ref 传递。
   复用现有业务服务与守卫，组件内不重新判定证据或赋予发布资格。
   使 T02 转绿，并运行关系角色、数据源隔离、评审、发布与生命周期回归。

4. **T04：数据主图及业务交互集成 RED。**
   浏览器覆盖“问数结果 → 图谱定位 → 区分召回／实际使用 → 清除高亮”的完整路径。
   覆盖点击节点查字段／指标／来源、点击平行关系查证据、确认／否决／改动词、评审队列和撤销。
   评审失败保留原状态，成功后读取后端有效结果；只更新目标角色，不能误改平行关系。
   覆盖构建完成预览、作业恢复／取消／失败、多预览并存、数据源切换、删除当前本体和快速往返机器人页面。
   将余下测试映射落地并提交 RED 人审。

5. **T05：页面回接 GREEN。**
   接入数据主图及完成结果画布，将节点／边选择连接到 Datamind 的详情和业务入口。
   接回问数上下文及准确角色评审，成功后更新图状态并保持有效阅读位置，处理错误和迟到响应。
   保留构建作业的服务端持有、恢复、取消与终态判定，不能把日志或断流当成生成成功。
   数据实例能力未提供时用详情交互，不伪造实例数量或全表实例图。
   完成多预览销毁、空图、孤岛、长标签和不同尺寸验证，运行两领域相关回归与性能检查。

6. **T06：两领域完整验收与人审交付。**
   用同一代码版本验证机器人阶段图、固定版本图、数据主图和构建完成预览。
   核对原证据、字段、指标、数据入口及评审操作仍可达，且没有扩大数据或执行权限。
   运行 `python scripts/check.py --suite all`，记录实际测试结果、工作树摘要与全部必要浏览器证据。
   更新使用说明、已覆盖映射和交付记录，用户确认后勾选并标记 delivered。

## 验收 Acceptance

- [ ] **STV-D01**：数据本体主图和构建完成预览使用共享画布，按当前数据源和正确结果身份读取，作业恢复取消与失败语义不变。
- [ ] **STV-D02**：问数召回对象与 SQL 实际使用表分别高亮，清除高亮恢复当前图，切换数据源或图谱不残留旧上下文。
- [ ] **STV-D03**：关系证据状态和语义检查结果有文字与视觉区分，选择高亮不改证据含义，详情保留证据来源与字段关联。
- [ ] **STV-D04**：同一对对象的不同关系角色可分别查看和评审，确认否决改动词及撤销准确作用于目标关系，失败不伪装成功。
- [ ] **STV-D05**：节点详情及既有数据指标来源和评审入口可用，迟到详情不覆盖当前选择，候选与发布资格以及生命周期约束不被展示绕过。
- [ ] **STV-D06**：数据本体接入后机器人阶段可视化及固定版本浏览仍可用，多预览隔离、缩放可读性和资源释放满足共享组件契约。
- [ ] STV-D01～06 有实际存在的行为测试，IR-031 验收回归通过。
- [ ] T01 约定的规模、可读性与交互响应指标通过，多角色关系无重叠到无法选择的情况。
- [ ] `python scripts/check.py --suite all` 对当前代码通过，未降低既有回归、类型、lint 或覆盖率门槛。
- [ ] 用户确认交付后才将本 IR 标记 delivered。

## 验收映射与执行说明

计划测试位于 `specs/acceptance.json` 的 `planned_requirements`，尚不代表覆盖完成。
T02／T04 按实际落地测试迁入正式 requirements，保留验收语义，不通过放宽断言适配错误实现。
现有问数、发布、数据源隔离、关系角色、作业恢复和机器人应用测试均保留为回归基线。
问数回放须明确区分确定性夹具和真实模型结果，视觉高亮测试不能代替 SQL 或本体语义正确性验证。
本次仅编写规约，未实现数据本体可视化或执行全量回归。
