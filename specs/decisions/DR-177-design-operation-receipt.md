# DR-177 · 设计操作回执与图谱显示

状态：accepted。日期：2026-11-24。
实现交付状态：delivered。

## 背景

设计操作接口先保存业务回执，再根据该回执生成交互式图谱。修复前，若生成图谱时抛出异常，接口会把这次展示故障报告为 HTTP 409（`artifact_integrity`），提示“设计文件缺失或损坏”。此时写入事务已经提交。

例如，确认类别后，设计已从修订 1 的类别阶段进入修订 2 的关系与属性阶段；提交建模消息后，对应运行也可能已经入队。这两种情况下，调用方都只收到错误，无法从响应中取得已保存的修订或已受理的运行编号，因而可能提示用户重新提交已经生效的操作。

## 决定

设计操作的回执以服务端事务保存的会话状态为准。本地确认或编辑成功返回 HTTP 200，消息、骨架确认和重试成功受理返回 HTTP 202。真实写入失败沿用原错误和状态码。

图谱是回执附带的只读展示。写入成功后，如果图谱生成失败，保留会话、阶段、修订和运行编号，返回 `interactive_graph_view: null`，在 `interactive_graph_warning` 中提供固定错误码 `graph_view_unavailable` 和用户提示。图谱正常时沿用原响应。展示故障按次数计入服务指标。

同号同内容的请求重放原业务回执，附带图谱按该回执的快照重新生成。同号不同内容仍返回冲突。展示字段仅用于响应，不写入修订、请求记录或导出工件。

界面按已保存状态更新，图谱暂不可用时单独提示并隐藏旧画布。刷新页面使用只读请求。会话、历史修订和导出沿用原有读取及完整性检查。
