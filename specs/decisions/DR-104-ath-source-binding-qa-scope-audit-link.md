# DR-104 · ATH：令牌限定数据来源、深度问数范围、请求号贯通

状态：已实现。日期：2026-11-13。
关联：ATH-02、ATH-03、ATH-04、DR-095、DR-098、DR-102、DR-103。

## 问题

- 适配层转发请求时不带数据来源，智能体永远只能访问默认库；多数据库功能（DR-095）经 ATH 用不上，
  也没有办法把智能体限制在用户同意的那一个库上。
- 深度问数是产品的主要能力，没有对应的授权范围，智能体经 ATH 问不了数。
- 适配层的审计日志记了「谁在什么授权下调用了什么」，DataMind 的构建记录记了「建了什么」，两边对不上。

## 决定

- 授权页增加数据来源选择，选项取自 DataMind 已就绪的 SQLite 来源。所选来源写入授权码和令牌。
  提交未列出的来源返回 400。
- 适配层转发每个请求时带 `X-DataMind-Source`（取自令牌）。调用方自带的来源头和 `src` 参数被丢弃。
  经 MCP 发起构建时，`source` 参数缺省补为令牌的来源，指定其他来源返回 403。
- 新增范围 `datamind:qa.ask`，对应 `POST /api/chat`，单次等待上限 240 秒。
  响应原样返回，其中 `degraded` 标明是否为内置模板结果（DR-098）。
- 每个放行的请求生成请求号，连同调用方 `ath:<客户端>:<用户>` 写入适配层审计日志，
  并以 `X-Request-Id`、`X-DataMind-Actor` 带给 DataMind；MCP 服务器经环境变量接收并转发。
  DataMind 把它们记入构建作业和图谱构建记录（DR-103）。适配层在审计日志里记下 `start_build` 返回的作业号。

## 边界

- 一个令牌一个来源。跨来源需要重新授权。
- 问数的问题文本会进入问数引擎的提示词。经 ATH 进来的问题与界面上输入的问题走同一条链路，
  受同样的范围校验、只读检查和本体约束校验约束，没有额外的内容过滤。
- 调用方与请求号在 DataMind 一侧是声明值，不是经过验证的身份。
- A2A 没有增加问数技能。
