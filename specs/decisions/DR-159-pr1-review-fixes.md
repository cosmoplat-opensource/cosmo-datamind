# DR-159 · PR #1 合入后的审查与修复

状态：已实现。日期：2026-11-18。
关联：PR1-PUBLIC-01、PR1-LIFECYCLE-01、PR1-ROBOTICS-DOMAIN-01、PR1-ROBOTICS-HTTP-01、PR1-UI-01；DR-141 至 DR-158。

## 背景

GitHub PR #1(机器人本体半自动构建与行为树生成)于 2026-11-17 合入 master。它有 72 个提交、509 个文件，约 11.7 万行，合入前没有人工代码审查。
合入后按领域逻辑、持久化与契约、HTTP 安全面、界面与文档四块分别审查，并在本机跑了完整检查。发现三类问题：

- **已公开的内容**：
  - 52 个文件里有开发者本机路径(含用户名)，共 132 处；一个代码数据文件里有另一位开发者的本机路径；
  - 4 个文件出现外部合作方名称，源项目以个人姓氏命名；
  - 提交了 AI 编程工具的工作区目录和一份标注由工具整理的 docx；
  - 76 处文档链接指向没有提交的本地检查结果。
- **代码缺陷**：
  - 工作目录经过符号链接时(macOS 的临时目录、`current → release` 式部署)，人工编辑不生效，本机集成测试有 15 项失败；
  - 问数与应用检查以相反顺序获取写锁和 RDF 锁，可能死锁；
  - 一条超时的 SPARQL 查询会卡住全部图谱读取；
  - 问数 SQL 在全局写锁里执行；
  - 机器人与删除操作经内网 IP 用 HTTP 访问时报错；
  - 控制字符可以写进读不回来的 OWL 版本；
  - 每次编辑都另存完整本体。
  - 另有一批中低风险问题，见下文。
- **测试与流程**：
  - 新的浏览器测试只认 Linux 上的浏览器路径；
  - 有一项测试在整套运行时偶发失败；
  - 文档写着「不推送」但已合入；
  - 一条已交付需求挂着不存在的计划测试。

## 决定

每个问题先写会失败的测试，再修改代码；复现不了的不改代码，只留回归测试。

**公开内容**(PR1-PUBLIC-01)
- 本机路径换成占位符(`<仓库根目录>`、`<源项目目录>` 等)。
- 外部合作方名称改为「外部机器人平台」。
- 源项目改称「源项目 / the robotics source project」，代码里的来源说明保留，只换名称，并改了三个以它命名的文件。
- 删除 AI 编程工具的工作区目录和重复的 docx；原来指向工作区技能的链接改指 `AGENTS.md`。
- 指向未提交检查结果的链接改为文字说明。
- 新增 `tests/meta/test_public_content.py`，检查本机路径、外部名称(只存长度与摘要，不写明文)、工具工作区和失效的证据链接。
- 词表文件只改了 source 字段，字节摘要随之变化；按首版冻结的设计仍按同一词表处理(`vocabulary.same_vocabulary`)。
- **已经公开的历史提交没有改写**：改写 master 的历史会影响已拉取的人，需要另行决定。

**生命周期与问数闸门**(PR1-LIFECYCLE-01)
- 路径比较改用解析后的真实路径。
- 生命周期的 sqlite 事务不再拿 RDF 锁；应用检查先在锁外取得当前本体，再进事务。
- 问数 SQL 在锁内准入、锁外执行，执行后复核本体状态，期间被删除或修改则结果作废。
- 本体依据改用表结构摘要，业务数据写入不再让进行中的问答失效；共享缓存只在结构变化时清空。
- 迁移遇到坏图谱时跳过并记录，然后完成迁移；启动时对齐在生命周期之外被改写的图谱。
- 编辑版本只引用按内容寻址存一份的基线本体，旧格式仍能读取。
- 已删除本体的构建历史和数据只在 `?state=deleted` 的历史视图里返回。
- 生命周期开关与机器人功能读取同一配置来源。
- 执行器在判定子进程崩溃前再收一次结果；设计运行有 900 秒总时限。
- 被拦下的后续 SQL 不再覆盖答案的检查报告；空白的图谱项被忽略。
- 偶发失败的原因是测试对整个存储类打补丁，服务导入时启动的执行器也被影响；补丁现在只作用于测试自己的存储目录。

**机器人领域**(PR1-ROBOTICS-DOMAIN-01)
- 统一的 XML 文本校验(`domains/robotics/xml_text.py`)用于所有用户输入入口；任务本体保存前把序列化结果再解析一次。
- 旧路径上撤销的证据不再放行严格生成；两份分叉的证据规则合为一份。
- 来源校验要求输出端口绑定 `{变量}`，节点 ID、端口名、`output_key` 只能是标识符，错误带位置；节点 ID 与端口名拼接后重复时也拒绝。
- 追问没有解析出对象时保留之前的选择。
- 抽取时不同的原始输入拼出同一标识会报错，不再静默合并。
- 语义拒绝统一为 `ModelingError`；`owl:Thing` 作为数据属性定义域时，提示词约束与校验一致。
- 节点模型里自行声明的 SetBlackboard 与内置契约不一致时报冲突。

**机器人接口**(PR1-ROBOTICS-HTTP-01)
- 演示先查重放，复用已打包的演示，构建不并发。
- 证据上传按摘要去重，每个本体有总量上限(默认 100 MiB)；导入同样内容时复用已有结果。
- 导入与评审先数三元组(默认上限 20 万)，再做推理和形状校验。
- 评审人不能为空，不能是系统或模型身份，不能评审自己保存的版本；记录里标明评审人由客户端自报、未经认证。
- 已删除本体的版本详情只在历史视图里返回(修订了 DR-157「历史始终可读」的一部分)，回收站的「查看固定版本」按历史视图打开。
- 引擎设置里的行为树任务抽取有中文名。

**界面与测试**(PR1-UI-01)
- 请求编号在没有 `crypto.randomUUID` 时用 `getRandomValues` 生成。
- 本体库读取失败时给出提示；删除只经生命周期对话框确认一次。
- 生命周期对话框支持 Esc 关闭和焦点循环，切换页面时关闭。
- 问数页签与菜单同名为「深度问数」。
- 关系图的三类节点用外形区分(方框、圆角长条、虚线框)，边标签字号 12。
- 浏览器测试统一经 `tests/browser_runtime.browser_executable()` 查找本机浏览器(含 macOS 的 Chrome)。
- 已交付需求不再挂着不存在的计划测试。
- IR-030、DR-158 补注「已经 PR #1 合入」。

## 没有做的

- **没有改写已公开的历史提交**，上述内容在 GitHub 的历史里仍可见。
- **仓库没有用户认证**：评审人仍可由调用方填写两个不同的名字完成发布；证据评审和知识评审没有自评审检查。
- **单元测试仍然很慢**：主要是机器人测试里真实的 RDF 与编译工作，约 1100 个测试 20 分钟。没有压缩测试夹具。
- **设计运行中**已发出的模型调用不能中止，只在阶段之间检查时限。
- **演示并发保护**只在单个进程内有效；本次修复前构建的演示没有摘要，不会被复用。
- **导入时会把文件解析两次**；构建流水线和 `consumer.py` 没有三元组上限。
- 精确作答在全部查询被拦下时不返回结果，这是 DR-158 记录的有意改动，没有恢复。
- DR-141 至 DR-147、IR-019 至 IR-023 的状态保持作者的记录，没有替作者改成已交付。
