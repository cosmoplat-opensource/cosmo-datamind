# DR-137 · 反馈的回放验证

状态：已实现。日期：2026-11-16。
关联：FEEDBACK-REPLAY-01；DR-122。

## 背景

「待改进」的反馈进入评审页的待处理列表后，只能由人点「标记已处理」，看不出本体改过之后这个问题是否真的答对了。
「有用」的反馈只计数。对比实验后提出的「证据约束的本体自演化」选题里，使用中的反馈经回放核验后才算数；
这里先做其中最基础的一步：回放与比对。

## 决定

- 反馈时，界面一并提交当时所用的本体和答案的结果；服务端只保存每个结果的数据摘要
  (行集合的摘要、行数、最多 50 行样例)，最多 8 个结果。
- **回放**(`POST /api/chat/feedback/replay`)：按当前本体重新提问(不读缓存)，比对新旧答案的数据。
  旧答案的每个结果，在新答案里能找到行集合相同、或在样例上按列容忍口径一致且行数相同的结果，算一致。
  比的是数据，不是 SQL 文本。结果记入该反馈(保留最近 5 次)。
- 结论的含义取决于反馈类型：「待改进」的答案变了，说明修改起了作用，是否改对仍需人确认；没变，问题可能仍在。
  「有用」的答案变了，提示可能退化。
- **回归回放**(`POST/GET /api/chat/feedback/regression`)：后台逐条回放当前数据库下保存了答案的「有用」反馈，
  汇总一致、已变化、没有答案和跳过的条数，列出已变化的问题。
- 标记已处理时记下依据：最近一次回放的结论，或没有回放、由人直接标记。

## 没有做的

- 模型每次写的 SQL 不同，同一个问题在本体不变时也可能得到不同的数据；回放的「已变化」不能区分是本体修改所致还是模型的随机性。
  没有做多次回放，也没有在本体修改前后做配对检验。
- 回放不会自动修改本体，也不会自动标记已处理。
- 旧的反馈没有保存答案，无法比对。
