# DR-134 · 对外的 SQL 本体检查接口；问数评测的统一比对规则、配对区间与候选上限

> 2026-11-17：[DR-139](DR-139-review-of-dr133-138.md) 修订了检查接口在不带图谱参数时的默认本体，以及多条关系共用一对键时状态的取法。

状态：已实现。日期：2026-11-16。
关联：ONT-CHECK-01、QA-EVAL-02；DR-055、DR-129、DR-133。

## 背景

与 EvoOntology 的对比实验(在单独的实验仓库中进行)得出两点与产品直接相关的结论。

1. 实验分支上做过「SQL 本体检查」接口，让外部智能体在提交前检查一次。产品里没有这个接口，
   外部智能体只能经问数接口间接用上本体约束校验。
2. 对比结果起初显示 DataMind 领先 5–8 个百分点。重新评分后发现，两边用了不同的结果比对规则(集合与多重集)，
   多带一列也判错；统一规则、补齐两边提供给模型的信息后，大部分差距消失。产品的问数评测同样只给单次运行的正确数，
   没有区间，也看不出失分是因为上下文里缺了所需的表和列，还是模型选错了。

## 决定

- **`POST /api/ont/check`**。输入 `sql`、可选的 `graphs` 和 `tables`；做与问数执行前相同的校验
  (只读、所选范围、表白名单、连接键、重复计数、表与列存在)，只检查不执行。
  返回结论、原因、语句读到的表，以及每个连接条件对应的关系状态(`verified`、`asserted`、`candidate` 或空)。
- **MCP 只读工具 `check_sql`**，转发上述接口，把结论和连接条件的状态写成文字。
- **评测的比对规则**。各组用同一套规则。`correct` 沿用题集声明的判定(数值按容差，字符串按等值或包含)；
  另按题集里的参考 SQL 的结果集给出两种口径：严格一致(行作为集合相等，列序有意义)与列容忍(可多带列、列序可不同)。
- **重复与区间**。评测可重复 1–5 次。先在每道题内对重复取平均，再按题配对计算组间差，
  用按题有放回重抽样(2000 次，固定种子)给出 95% 区间。
- **候选上限**。参考 SQL 用到的表和列都出现在给模型的上下文里(列与表名出现在同一行)，记为在上限内。
  同时给出上限内的正确率，用来区分「上下文里缺了」和「上下文里有但选错了」。
- 旧的计数字段保留，按每题平均正确率取整，已有结果和界面照旧可读。

## 没有做的

- 题集只有 8 道题，区间很宽；界面上已注明不宜据此下结论。没有扩充题集。
- 候选上限按文字是否出现判断，没有区分「出现在关系提示里」和「出现在表结构里」。
- 检查接口不执行 SQL，结果是否正确仍要看执行。
