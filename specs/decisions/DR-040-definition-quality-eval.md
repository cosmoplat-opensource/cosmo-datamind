# DR-040 · 定义质量评分(把定义好不好变成数字)

- **状态 / Status**: accepted
- **日期 / Date**: 2026-07-31
- **决策者 / Deciders**: Boss(用户) + Writer(Claude)
- **关联 / Refs**: [[DR-010-iof-bfo-alignment]]、[[DR-039-hallucination-eval-harness]]、[[IR-009-eval-and-definition-quality]];实证=`definition_eval.py`、`tests/unit/test_definition_eval.py`、demo 本体逐条评分 + 金标术语表

## 上下文 / Context

DR-010 的完备度记分卡测**形式覆盖率**(有没有定义/反例/接地),回答「填没填」;
但填了的定义**好不好**——是否属加种差、是否循环、有无反例、与领域金标是否契合——从未被量化。
论文 RQ3 亦把「参考式定义评测」列为 future work。评测台(DR-039)测「关系真伪」,
定义质量是与之**正交**的另一维:测「概念定义得对不对」。

## 决定 / Decision

建**确定性、离线**的定义质量评分 `definition_eval`,与完备度记分卡正交并用:

1. **结构维度**(各 0/1,规则判定):
   - `present` 定义非空且≥8字;
   - `non_circular` 非循环(去术语与系词后仍有实义种差);
   - `genus_differentia` 属加种差形式——兼容中文名词短语式「[种差]的[属]」、系词式「X 是…」、英文「a X that…」;
   - `counter_example` 反例存在且≥4字。
2. **参考式维度**(可选):有金标术语表时,定义与金标 desc 的**字符二元组 Jaccard 重叠**(确定性,无模型);
   按 0.7 结构 + 0.3 参考 融合。
3. **批量 `score_ontology`**:全对象打分 + 平均分 + 待改进计数(<阈值),按分升序列出便于定位最弱定义。
4. **可选增强留接口**:嵌入相似度 / LLM-judge 在模型/引擎可用时叠加,不作离线必需
   (与评测台「提议端幻觉率」同一模式)。

## 后果 / Consequences

- (+) 定义质量成为可回归数字。demo 实测:**LLM(IOF对齐)路径平均 1.0,数据驱动 quick_build 平均 0.0**——
  把「两条构建路径的定义质量差距」量化为 **1.00 分差**(quick_build 定义留空,108 对象全待改进)。
- (+) 判别真缺陷:空定义/循环/缺反例/非属加种差被逐条标出并给 issues;与记分卡正交(填没填 × 填得对不对)。
- (−) **只测形式,不测语义深浅**:结构成立但空洞的定义(如「一个重要的东西」够长时)仍过属加种差——
  语义充分性需 LLM-judge/嵌入,属可选增强层,如实标注为局限。
- (−) 参考式仅覆盖金标术语表命中的少数术语(示例库 6 条指标);多为结构维度主导。
- 后续可接 `GET /api/ont/defquality/<key>` 路由(与 cq/health/drift 等同构),UI 出定义质量看板。
