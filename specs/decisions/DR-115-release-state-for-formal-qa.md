# DR-115 · 正式问数只取用有资格的图谱

状态：已实现。日期：2026-11-15。
关联：RELEASE-01、DR-101、DR-098。

## 背景

构建作业结束、验收检查的结论、图谱能否用于正式问数，此前是一回事：作业一完成，图谱就能被问数选中。
问数资格只检查绑定的表在当前数据源里是否可查，构建时落在图谱上的质量结论没有参与判断。
实测：验收检查判为不通过的草案，同步问数接口仍返回业务结果。

## 决定

三件事分开记录：

- **作业状态**：构建作业是否跑完（DR-101）。
- **质量结论**：验收检查的结果（通过、待评审、不通过），记在图谱的 `build_quality` 里。
- **发布状态**：人的决定，记在工作区的 `releases.json` 里，带发布人、时间和发布时的构建轮次。

图谱的发布状态有三种：

| 状态 | 条件 | 正式问数 |
|---|---|---|
| 已发布 | 有人发布过，且之后没有新的构建轮次 | 可用 |
| 草案 | 待评审、通过但未发布、没有质量记录的内置与早期产物 | 默认可用，响应标明是草案；严格模式下不可用 |
| 不可用 | 验收检查不通过 | 拒绝，返回 409 `graph_not_released` 和原因 |

- 规则在请求进入时判定，早于缓存和执行；同步问数、流式问数、根因诊断同一条规则。
- 响应头 `X-DataMind-Graph-Release` 标明本次取用的是已发布版本、草案还是预览。
- 人可以带 `preview` 预览不可用的草案；带调用方声明（经上游适配层进来）的请求不能预览。
- 发布（`POST /api/ont/release`）要署名，验收不通过不能发布；发布后再构建一轮，状态回到草案，需要重新发布。
- 严格模式（`DATAMIND_QA_REQUIRE_PUBLISHED=1`）面向多人共用的部署：只有已发布的版本能用于正式问数。

判定规则在 `ontology_release.py`，不依赖 Web 层。构建产物列表带上每张图的发布状态。

## 没有做的

- 发布记录按图谱键和构建轮次识别，还不是不可变的修订。同一底本的两次并行继续构建仍会互相覆盖，
  需要先有「每次构建落成独立草案」才能解决，单独处理。
- 图谱、指标、看板等其他读取入口不受这条规则限制，它们展示的是草案本身。
- 界面上还没有发布按钮，发布走接口。
