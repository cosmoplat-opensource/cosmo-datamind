# DR-133 · 校验改用语法解析，没有本体时如实提示，教程重跑

> 2026-11-17：[DR-139](DR-139-review-of-dr133-138.md) 修订了解析器对 left( / right( 的处理与重复计数原因里的子表名。

状态：已实现。日期：2026-11-16。
关联：QA-GATE-PARSE-01、DATA-CONTEXT-02、UI-A11Y-02；DR-098、DR-131、DR-132。

## 背景

DR-132 留下四项没有做。

1. **校验是基于正则的近似分析。** 本体约束校验用正则在整条语句上找表名、别名和连接条件，分不清作用域。
   DR-131、DR-132 两次修补的都是这一类问题：子查询别名与真实表同名、同一个别名在不同查询块里指向不同的表、
   `FROM` 后直接跟括号、UNION 各支混在一起。`JOIN … USING`、`NATURAL JOIN` 没有「别名.列 = 别名.列」的等式，看不出是关联。
2. **主库上没有适用的本体时仍回退到内置示例本体。** 问数生成的 SQL 引用不存在的表，
   指标、评审等接口返回的是「非法图谱键」。
3. **界面。** 附件上传控件不能用键盘打开；一批输入框没有可读名称；图谱里关系状态只靠线的颜色和线型区分，没有图例。
4. **教程里的运行记录是 8 月的。** 模型、步骤数和界面都已不同。

## 决定

- **语法解析**。新增 `sql_structure.py`：把语句切成词元，按括号和子句关键字还原结构。
  每个 SELECT 是一个查询块（UNION 各支、子查询、CTE 各是一块）；名字按作用域解析，先本块、再外层块；
  FROM 里的名字先看可见的 CTE，再看真实的表。输出真实表的清单、每块的别名、两侧都解析到真实表的等值条件、
  USING / NATURAL JOIN、聚合调用。校验的表白名单、连接键校验和重复计数检查改从这份结构取输入。
  USING 和 NATURAL JOIN 按本体里登记的同名键还原成连接条件，所以关联后对父表列求和也能拦下。
- **不新增依赖**。解析器只覆盖 SELECT，写在仓库里，只用标准库。本机没有现成的 SQL 解析库，
  引入第三方库需要下载并增加一项运行时依赖，这次没有做。
- **解析不了时退回**。遇到不认识的写法抛 `ParseError`，校验退回原来基于正则的做法并计数（`qa.sql_parse_fallback`）。
  原有的正则路径和 DR-132 的修补保留，作为退路。
- **没有本体时如实提示**。主库上没有适用的本体时，默认本体为空，不再回退到内置示例本体。
  问数返回「当前数据库尚无可查询的本体，请先基于当前数据源构建本体」；
  指标、评审、编辑、SPARQL 等不带图谱参数的请求统一返回 422 和「当前数据库尚未构建本体，请先构建」。
  没有配置数据库（文件不存在）的部署不变，仍可浏览内置示例本体。
- **界面**。附件上传的 input 改为视觉隐藏、可获得焦点；没有 label 的输入框取占位文字或同一行前面的文字作为可读名称；
  图谱图例加上图中出现的关系状态，线型和颜色旁边带文字；连接状态的色点标为装饰，状态由旁边的文字表达。
- **教程**。在示例库上按教程重走一遍，构建过程、产出、问数记录和对话修改的记录都换成 2026-11-16 的实际输出，
  写明所用模型；删去无法复核的延迟区间。3.3 节换成本次运行里真实出现的两次拦截。

## 没有做的

- 解析器不是完整的 SQL 方言解析器。窗口定义、表值函数等只做到能跳过；非 SELECT 语句、多条语句一律不解析。
- 退回正则路径时，DR-132 记录的近似分析的局限仍然存在。退回的次数有计数，没有告警。
- 聚合内容同时用到两张表的值（数量 × 单价）仍不拦；刻意构造的 `SUM(父表列 + 0 * 子表列)` 仍可通过。
  对逐行相减这类写法（订单金额减客户折扣）无法区分意图，没有加规则。
- 不带表名又有两张表都有的列仍不判断。
- 教程 1.1 节没有逐个模型实测；OpenAI 官方端点没有验证。
