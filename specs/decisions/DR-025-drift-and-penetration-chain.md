# DR-025 · 概念漂移检测与穿透链路核验

- **状态 / Status**: accepted
- **日期 / Date**: 2026-08-02
- **关联 / Refs**: [[DR-024-competency-questions-driven-build]](CQ 核验)、[[DR-011-generalized-adjudication]](裁决)、[[DR-013-human-review-relations]](证据分层)

## 背景 / Context

《本体智能研究报告(1.0)》(AIIA × CCSA TC601)第二遍精读补上了两处此前遗漏的要点。

**其一,四个行业案例的建模方法是同构的**——报告没有明说,但四例并列时模式很清楚:

| 领域 | 核心实体 | 穿透链路 |
|---|---|---|
| 电力配电网 | 停电事件/设备/线路/用户/组织机构 | 停电事件—设备—线路—用户 |
| 通信宽带 | 订单/网络资源/工单/用户/设备 | 接单—开通全交付链路 |
| 航空供应链 | 飞机/子系统/零部件/供应商/订单/库存/产线 | 飞机—最末级零部件多层 BOM |
| 银行反洗钱 | 客户/账户/交易/关联方/合规规则 | 客户—账户—交易—关联方 |

即:**定义 5–6 类核心实体 → 建立一条纵向穿透链路 → 在链路节点上嵌规则与动作**。
本体的价值不在对象多,而在**能否从链路一端穿到另一端**——电力案例要的是
"任意停电都能完整追溯原因、影响范围与责任主体",断在中间就等于追不到责任主体。

**其二,阶段六点名的两项维护能力我们完全没有**:

> 技术上,引入自动化检测工具监控本体与数据源的一致性,及时发现**概念漂移与关系断裂**。

代码扫描确认:漂移、断裂、调用频次三个关键词在本仓 0 命中。

## 决定 / Decision

新增两项确定性核验能力,均不调 LLM:

1. **概念漂移检测** `drift_check.py` + `GET /api/ont/drift/<key>`
   比对 IR 声明与数据源 schema,检出四类:
   `table_missing`(对象绑的表没了)、`column_missing`(属性绑的列没了)、
   `pk_missing`(主键列没了,裁决锚点断裂)、`relation_broken`(关系证据引用的父/子键没了)。
   输出一致率与逐条修复建议,漂移项回流 gaps。

2. **穿透链路核验** `cq_check.check_chain` + `POST /api/ont/chain`
   把"主链路"提升为可声明、可核验的一等公民,**逐段判定**并给出断点位置。
   三态:`intact`(各段仅经 verified/asserted)、`weak`(某段须借道候选边)、
   `broken`(某段完全不连通)。

## 为什么这样做 / Rationale

- **漂移是静默故障,不检测就只能靠事故发现**。本体说 `dim_customer.cust_id` 存在、
  库里已经没有,系统不会报错——SQL 照样生成、照样执行失败,失败原因被埋在
  一句"查询出错"里。这类问题必须主动扫,不能等用户投诉。
- **链路必须逐段判,不能只看首尾**。首尾连通但中段是候选边的链路,在业务上是断的:
  追溯会在断点处失去责任主体,而首尾判定会给出"通"的假象。逐段判定还有个实际好处——
  **断点位置直接告诉你该补哪一段**,而不是丢一句"链路不通"让人自己找。
- **只报事实,不自动修复**。漂移的正解可能是改本体、也可能是数据源回滚,这是人的判断;
  自动删对象会悄悄抹掉建模成果,违反本系统的可撤销原则。

## 影响 / Consequences

- 新增两个只读端点,不改任何既有写路径;未调用时系统行为完全不变。
- 漂移与链路的缺口条目与 CQ 缺口同格式(`{type, desc, fix}`),统一回流人审队列。
- 与 [[DR-024]] 形成互补的三问:
  CQ 答「本体**够不够用**」,链路答「追溯路径**通不通**」,漂移答「本体**还对不对得上数据**」。

## 代价与边界 / Trade-offs

- 漂移检测**大小写不敏感**:SQLite 标识符本就不区分大小写,IR 里的 `DWS_X` 与库里
  `dws_x` 是同一张表。若按字面比对会产出整片假阳性(实测 1044 个检查点会全红)。
- **未绑表的纯概念对象跳过检测**而非报错——语义层本就允许存在不落库的抽象概念。
- 链路节点解析要求**名称完整匹配**,与 CQ 锚定同一从严策略:宁可漏匹配报出缺口,
  不可错匹配掩盖缺口。
- 漂移检测只覆盖**本地 SQLite 数据源**(`DATAMIND_DB`)。外部库(MySQL/Doris)的
  schema 比对需要各自的方言实现,本轮不做——如实标注边界,不假装已覆盖。
