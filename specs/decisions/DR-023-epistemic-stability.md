# DR-023 · 语义增强三件套:对标 Trane 认知稳定性方法(M5/M4/M1)

> 状态:delivered(2026-07-30)。来源:Trane Technologies《Toward Epistemic Stability:
> Engineering Consistent Procedures for Industrial LLM Hallucination Reduction》
> (Freeman, Kicklighter, Erdman, Gordon · arXiv:2603.10047,亦见 Computer and Information Science)。
> 该文将认知稳定性定义为「一项工程流程在多次运行中给出一致、可复现、可辩护结果的程度」,
> 并从一致性与可复现性、上下文接地、可追溯性、专家可验证性四个面向加以刻画;另给出五种
> 推理侧消幻觉方法 M1–M5(成功率 M1 75%、M2 34%→80%、M3 80%、M4 100%、M5 77%)。
> 注:中文二手综述将其概括为「三维」,本文按原文四面向表述,避免转述失真。

## 与本系统的关系(先说清哪些无需照搬)

本系统在**外部可验证性**上已强于该文任一方法:M1–M5 全为提示侧技巧,而数据裁决
(取值重叠 ≥ θ ∧ 父键唯一)是确定性、不依赖模型自证的验证。可追溯性亦已具备
(每关系带 evidence/provenance)。故只补该文中本系统确实缺失的三项。

## M5 领域词汇表注入(该文 77%)

**缺口**:655 条术语表此前只用于 `expand_terms()` 扩展检索关键词(提召回),未注入 prompt
做消歧(防误解)。且 `build_context` 的表行是裸表名(`表 DWS_ORG_PERFORMANCE_DAILY:`),
108/108 对象明明都有人工校订的中文名却没进上下文;分层前缀约定与短缩写也未锚定。

**实现**:①表行改为 `表 X(中文名):`;②新增 `_glossary_block()` 注入分层约定
(dws_*=汇总层 等,仅本次上下文出现的前缀)与缩写锚定(仅出现在本次列名中、长度 ≤4 的
易歧义词元,上限 20)。实测锚定出 `ar=应收账款`——通用 LLM 极可能读成"增强现实",
正是该文 OA/DX 歧义案例的同类。

## M4 增强数据注册表(该文唯一 100/100)

**缺口**:喂给 LLM 的只有表名+列名+JOIN 提示。口径卡虽有 unit/desc,但它是**给人看的**
(随答案展示),不进模型上下文;取值量级与数据边界一概缺失。

该文 M4 为每条传感器记录注入六个字段:`component_type`、`normal_range`、`fault_threshold`、
`depends_on`、`fault_implication`、`units`。本系统按可确定性推导的部分对应实现:
`units` 直接取指标口径;`normal_range` 只给**观测区间**(实测 min/max)并明确标注——
工艺规范意义上的正常范围需要工艺标准输入,系统无从推导,不可用观测极值冒充
(极值本身可能就是异常样本);`depends_on` 由既有的本体关系与 JOIN 提示承担;
`fault_threshold` 与 `fault_implication` 缺输入源,不实现,亦不臆造。

**实现**(全部确定性 SQL,与数据裁决同源,零幻觉;算不出即省略,不臆造):
- `_data_window()`:显式告知业务数据时间窗。**这是一个真实缺陷**——实测本库数据止于
  2026-05-26,LLM 若按 `date('now','-3 month')` 写相对区间只命中 214/4190 行,且随时间
  流逝必然归零,而它无从得知。提示语直接给出倒推基准。
- `_metric_baselines()`:命中指标附 `范围[min,max] 均值 非空行数`,含负值时额外标注
  "业务异常,勿假设恒为正"(负毛利订单真实存在)。上限 6 个指标,10 分钟缓存(实测
  首次 11ms、缓存后 5ms)。

## M1 迭代相似度收敛(该文 75%)

**缺口**:0 处一致性检查。而论文 §8 明确写着"未做跨模型对比,引擎方差未量化"——M1 正是
量化并降低该方差的工程手段。

**实现**:`_relset()` 取 (source,target,verb) 三元组指纹(大小写/空白归一);
`_stability_annotate()` 用两次独立生成的 Jaccard 量化一致性,并逐条标 `stable`。
经 `/api/build/inquire` 的 `stability:true` **opt-in**(二次生成使构建耗时翻倍)。

**关键设计判断:一致性不作否决权。** 数据裁决是确定性硬证据;若数据见证了某关系,
不应因 LLM 这次提议不稳就降级——那等于用软信号推翻硬证据。故 `stable` 只做两件事:
①给人审提示"该关系仅在 1/2 次生成中出现";②聚合成 `ir["stability"]` 留档,
为论文补上认知稳定性的一致性维度。

## 回归

新增 AA 节 10 条断言(M5 三项注入、M4 时间窗与基线、M1 的 Jaccard/归一/标注/空输入,
以及"不作否决权"的设计留痕)。总数 271 → **281**。

## 第二批(2026-07-30):M3 流水线 + 反馈闭环 + 历史准确率

### ④ M3 单任务 Agent 流水线(该文 80%)· opt-in `pipeline:true`

**缺口**:`diagnose_stream` 单次 LLM 调用同时完成 识别根因 + 排序 + 出检查清单。该文把这种
形态的失效称为**级联不一致(cascading inconsistency)**,并指出「当单个 agent 同时承担根因
分析、严重度排序、修复方案与复盘四件事时,根因步骤的错误会传播到其后所有输出」。

**有依据的偏离**:该文的四节点(诊断/评估/方案/审核)全用 LLM。本系统只用 **2 个 LLM
节点 + 2 项确定性检查**,理由是:
- **评估(排序)不用 LLM**:排序依据是可枚举的客观特征(路径是否在本体边界内、置信度、
  证据是否点到具体表/字段)。规则打分可复现、可解释、零延迟;让模型自评"严重程度"
  恰是该文自己警告的循环论证。
- **审核不用 LLM**:合规性检查本质是集合匹配(清单是否只引用白名单对象/真实表)。
  让模型自审等于把裁判权交还被审对象——与本系统"数据裁决 > 模型自证"的设计原则冲突。

**实现**:`_dg_bounds()`(G1 边界校验,从原 ④ 抽出复用)→ `_dg_rank()`(确定性打分,
输出 rank/rank_score/rank_basis)→ 方案节点(LLM,只据已排序根因出清单,明令"不要重新
诊断")→ `_dg_checklist_gate()`(G2:越界引用**标记而非静默丢弃**,可审计)。

同时遵守该文关于 M2 v1 仅 34% 的教训——分解不等于简化,故每个节点后都有明确检查,且
节点失败单独上报(`assess`/`plan_gate` 步骤),失败可定位。

**实测**(引擎在线):#1/#2 得 10 分(界内+已验证+具体字段)、#3 得 7 分(依据待验证关系),
排序理由完整输出;清单 5 条全部通过 G2(引用的 4 张表均真实存在)。

### ⑤ 反馈闭环:人审否决模式回流

**缺口**:动作/人审记录此前只作审计,0 处回流。该文六步数据流的第六步"执行结果→回写
本体→更新故障模式库"缺失,"越用越聪明"的飞轮没有接口。

**实现**:`_rejected_patterns()` 把人审否决过的 (源表→动词→目标表) 连同否决理由回流,
注入抽取 prompt 的 `[已知误判模式]` 段——对应该文增强注册表里的"已知故障模式"。
只回流**否决**(负样本):它稀缺且信息量高;通过的关系本就在图谱里充当正样本。

**实现中的一处返工**:人审结论写在**编辑栈**(edits_*.json)而非基线 IR,首版用 `load_ir()` 聚合
得到 0 条。改用 `load_ir_edited()` 后正常(实测基线 0 条 / 应用编辑后 7 条)。

### ⑥ 可解释性第三问:历史准确率

**缺口**:该文要求每条输出能答三问,本系统答了前两问(provenance / 关系接地),
第三问"历史上类似情况准确率"为 0 处追踪。

**实现**:`GET /api/ont/accuracy` 按**系统原判**分组算人审同意率——回答工程师真正关心的
"系统说 verified 时,人有多少次认同";另按动词分组,暴露哪类语义关系机器最易判错。
`GET /api/ont/rejected-patterns` 暴露回流用的误判模式,供页面展示与审计。

**两条规范**:
1. **原判在评审当刻定格**:`confirm_relation` 会把 status 改写为 asserted,原判事后无法
   反推,故在改写前 `setdefault("review_prior_status", ...)`。事件发生时抓数据,不事后重建。
2. **小样本不给百分比**:`_ACC_MIN_N = 5`,低于此返回 insufficient。两三条记录算出的
   百分比是噪声而非证据,展示出来只会让工程师建立错误的信任——这与该文"认知稳定性"
   的初衷相悖。实测 n=2 的动词分组正确返回"样本 2 条(< 5),不给准确率"。

### 顺带清理

诊断 prompt 里原有一处西里尔占位符(`路径только用这些`)+ 下一行字符串替换的写法(既有
代码,非本轮引入)。能工作但脆弱:若只改一行,LLM 就会收到中文 prompt 里混着俄语。
已直写中文并删掉替换行,全仓西里尔字符归零。

### 回归

新增 AB 节 10 条(闭环:**测试内自造人审数据 → 验聚合 → 撤销复原**,否则无数据时断言无意义)
+ AC 节 9 条(流水线三个确定性组件 + 两处设计留痕 + opt-in 不改默认)。281 → **300**。

### 已知边界(使用者须知)
