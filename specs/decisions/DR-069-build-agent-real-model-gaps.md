## 上下文 / Context

场景回归基准(DR-067)录制了一份理想的模型提议,衡量不了模型提议本身的质量。用真实模型(DeepSeek)按界面流程
在能碳实库抽样上构建三轮(第 1、2、12 轮,共 122 张表)、在电子制造业务采样上构建一轮,并用直接查库的结果核对问数,
发现以下问题(两次运行结果一致,属于结构性缺陷):

- 14 条核心关系(实例 → 类型目录、指标/量测 → 设备、关联表 → 企业等)中只有 2 条已验证,8 条完全没有提出。
  原因:继续构建时模型只拿到前几轮对象的名称与表名,看不到列,实例表连不到前几轮建的类型目录;
- 指标、量测、事件、属性按 `obj_type` 指向设备或用能单元(多态引用),重叠 93~100% 却因键名不同停在候选;
- 键名缩写(`dev_group_id` ↔ `meta_device_group`)与驼峰(`ownerEntNo` 一类)被判为键名无据;
- 同名对象两轮绑定不同的表(第 1 轮把「企业」绑到企业调研表),合并时保留旧绑定,本轮按新表取的证据与绑定不一致;
- 第 1 轮混入 10 张积木报表(第三方报表工具)的表;第二轮起本体名被模型改掉;
- 问数:最基础的「按设备类型、按系统类型计数」因缺关系被拦下;按能源类型统计只给编码;
  制造问「各线别过站数」时模型把轨道列当成线别,答案错误且没有任何提示。

## 决定 / Decision

1. **按键名补提关系候选**(`key_links.py`):在模型提议之后、数据裁决之前,按「列属于哪张表」补提候选——
   列的词根(去后缀、展开缩写)与表的核心名一致即为该表的标识键;子键 = 修饰词 + 父表标识键,或子键词根指向父表名。
   至少一端在本轮,因此前几轮的对象也能被连上。租户键只在关联表上提;审计列与泛词不提;多张表都能对上时取与子表名
   共有前缀最长的一张,并列则不提;模型已提过的表对只作为备选键交给裁决。补提只产生候选,是否成立仍由数据裁决决定;
   有键名依据、重叠不低于 20% 的候选保留送人工复核,其余不进图。
2. **多态引用按判别值裁决**:子键是 `obj_no` 一类多态键且子表有 `obj_type` 一类判别列时,按判别值分条件比对,
   某个取值下重叠达标且父键唯一即判为已验证,证据记录 `condition`。验收认可该证据;问数的关联提示带上判别条件,
   口径校验要求 SQL 写出该条件。
3. **键名规则**:`dao_core` 按词元展开常用缩写(dev、sys、ent 等),驼峰先拆成下划线;`name_score` 保持与上游引擎同口径不变。
4. **合并时处理绑定冲突**:同名对象两轮绑定不同的表时,保留与对象名吻合的那张;按另一张表取的已验证关系降为候选并注明原因。
   继续构建沿用底本名称。
5. **构建体检**:第三方工具自带的表(积木报表、Quartz、工作流引擎等)默认不进计划。
6. **问数**:
   - 口径校验给出明确原因时,让引擎按原因修正一次,修正后的 SQL 照样过校验;
   - 码表说明要求按名称输出;
   - 新增维度词核对:问句里的维度词在 SQL 中取自哪一列,该列在本体中没有这层含义时,在执行记录与报告末尾提示核对(只提示不阻断)。

## 后果 / Consequences

同一数据、同一流程、真实模型复测(两次):

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 14 条核心关系:已验证 / 候选 / 未提出 | 2 / 4 / 8 | 9 / 4 / 1(两次相同) |
| 三轮共计关系 / 已验证 | 84 / 49 | 155 / 85、148 / 83 |
| 两次运行已验证关系的重合度 | 0.81 | 0.81 |
| 能碳问数 6 题答对 | 3(2 题被拦、1 题只给编码) | 6 |
| 制造「各线别过站数」 | 答错且无提示 | 仍取错列,但执行记录与报告给出明确提示 |

- 余下 4 条候选受数据所限:指标编码只在类别内唯一;抽样库里企业-设备、企业-用能单元关联表与计量关系有大量孤儿记录,重叠未达阈值。
  计量关系 → 能源类型字典仍需码表契约。
- 新增 key_links 步骤约增加 10~30 秒(第 12 轮)。
- 场景基准增加「被拦下的 SQL 按原因修正一次后答案正确」,共 27 项。
- 未解决:对象类型(对象 / 事件 / 信息记录)仍有误分;电子制造无代码包时过站 → 线别的键名不相容,仍停在候选。

## 备选与不做 / Alternatives

- **把前几轮表的完整结构塞进提示词**:不做。几百张表会挤掉本轮证据;确定性键匹配更便宜、可回放。
- **多态引用放宽一般命名规则**:不做。只在存在判别列时按判别值裁决,没有判别列的键名不同仍停在候选。
- **维度词对不上时直接拒答**:不做。确定性核对会有漏判,提示比阻断代价小(与 DR-026 一致)。
