# DR-066 · 先交付简洁的本体构建到行为树生成流程

> 2026-11-06 后续变更：基础任务的适配必填条件和版本展示由 DR-067 / IR-021 替代。离线候选不要求适配证据；以下保留原迭代设计和审计历史。


- **状态**：accepted（产品方向由用户确认；各批测试仍按 SDD 人审）。
- **日期**：2026-11-05。
- **关联**：DR-060、DR-061、DR-062、DR-063、DR-064、IR-019、IR-020。

## 上下文

用户实际使用 IR-019 界面后指出：输入项过多、信息过密，不知道下一步应该做什么。
固定版本、编辑底本、工作头同时展示，以及署名、理由、依据、证据审核和合并流程，不适合作为基础版的默认操作。
用户明确要求只显示当前版本，将多用户协作和高级治理的优先级后移。
用户随后选择：“先打通构建到行为树生成，暂缓高级维护功能”。
用户进一步明确：参数设置、业务映射和必要的任务适配必须在 DataMind 内完成，不依赖 Protégé，界面只展示当前任务缺少的内容。

复核 Yang 源码后确认：ontology 通过 CLI 从成对 XML 构建 OWL，人工知识修改使用 Protégé。
agent 网页的主要操作是选择真实/演示模式、输入任务、回答澄清、查看和下载生成结果。
它没有知识维护、证据管理、版本比较和冲突合并这些网页分区。
它仍检查实际 OWL 中的映射、参数与适配依据，页面简洁不意味着这些数据可以凭空补齐。

## 决定

1. 基础版优先交付“构建或导入本体 → 输入任务并澄清 → 按需补齐生成信息 → 查看/下载行为树”。
   每一步只突出一个主要动作，当前本体只显示一个当前版本号。
   新建对话、当前缺口、生成结果逐步呈现，技术详情默认折叠。
2. 知识维护、证据管理、版本比较、重建合并和人工审核不作为默认主流程的必经页面。
   已有后端和历史入口保留为兼容能力，不继续扩展高级治理 UI。
   不要求用户填写通用署名、操作理由、工作头或修订号才能发起任务。
   当前任务缺少适配依据时，依据本身仍需用户提供，不能因精简界面而省略。
3. 沿用 Yang 的受约束任务解析方式，复用 DataMind 模型配置。
   模型只提取六字段任务，确定性内核读取当前 OWL、解析业务对象、实例化固定技能流程并验证 XML。
   缺少模型配置明确提示，不用规则伪装成 LLM，不允许模型直接生成可下载 XML。
4. 基础应用消费固定版本的经过结构复验的 OWL，不要求先完成人工审核发布。
   为此提供单独的应用快照加载入口，不放宽旧的“已发布版本加载”接口，不自动伪造审核记录或把候选改为已发布。
   已有校验、不可变载荷、运行与下载摘要检查复用；新增多人协作和治理流程暂缓。
5. 信息不足时区分两种下一步：任务选择不明确则对话澄清，本体知识不足则在 DataMind 当前任务页按需补齐。
   只呈现当前任务依赖中缺失、无效或尚待明确确认的业务映射、公开参数和适配依据；有效内容直接复用，不要求重复输入。
   缺少所需对象或配置时允许就地新建并关联，不要求先在外部编辑器创建。
   复用 IR-019 的受控编辑与适配校验，通用编辑器、证据管理页和发布审核不是前置步骤。
   用户显式确认当前范围，后台记录实际操作来源并绑定当前配置；不能通过保存表单、聊天“确认”或后台默认值伪造适配依据。
   保存产生新版本，当前任务接续到该版本后重检缺口，旧运行与旧本体保持可追溯。
   OWL 下载/导入作为可选能力保留，完成基础流程不依赖 Protégé 或任意外部编辑器。
6. 演示作为明确选择的独立入口，使用登记的示例 XML 和演示补充材料构建独立本体。
   不修改用户真实本体，也不将演示补充材料自动应用到任意上传文件。
   离线验收可注入标明为测试替身的模型响应；正常页面仍调用真实配置模型。
7. 沿用现有持久化原语及 RunStore，补会话与版本/运行的关联，不另建通用聊天平台。
   每次解析、补齐和生成固定当前版本和模式；本任务保存补齐后显式推进会话的版本引用并记录新旧关联，不改写既有运行快照。
   用户主动换本体或换模式开始新会话，结果不能沿用上一次任务。
   首版不做 XML 在线编辑、任意流程规划或机器人实机执行。

### 当前任务配置的查看与更换（2026-11-06 用户补充）

默认复用已有配置时，任务页展示“本次使用的配置”、关联对象和关键参数。
用户可主动更换当前零件类型的感知配置或当前放置位的放置配置，选择已有配置或仅填写名称新建，再明确保存。
更换仅作用于当前任务解析出的关联对象，不能提交任意主体或关系；生成本体新版本，保留旧版本及其任务结果。
更换后重新检查参数、知识确认和适配依据，旧配置的依据不能作为新配置的适配结论。
入口说明新版本供后续任务复用；取消不写入，更换失败保留选择，成功后丢弃旧范围下尚未保存的补齐答案。
不扩展为全图配置编辑器，不在此轮提供已完整参数的任意在线编辑。

## 后果

本决定覆盖 DR-063、原集成 Proposal 和 IR-019 中“先完成高级维护再进入行为树应用”的交付顺序与默认交互要求。
IR-019 T07 的历史实现及回归证据保留，T08 整轮验收暂缓，不把用户提出简化解释为原复杂界面已经验收。
旧 UI 中与新入口冲突的测试要求在新一批 RED 阶段逐条标明替代关系，再审覆盖；不在 GREEN 阶段偷偷删除断言。
基础版必须具备任务范围内的知识补齐能力；复杂协作、全图维护和版本合并仍后置。
单用户操作来源可以由服务端生成会话标识，不冒称已认证个人，也不自动填写“已测量”或虚构依据。
构建成功只代表得到了本体；只有任务与本体知识均满足条件，才提供离线候选 XML。
生成成功仍不代表实机可执行。
