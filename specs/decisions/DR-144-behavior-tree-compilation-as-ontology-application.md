# DR-144 · 受约束任务解析与版本化行为树应用

- **状态 / Status**: proposed
- **日期 / Date**: 2026-11-02
- **关联 / Refs**: [[DR-029-openai-compat-runtime-and-test-isolation]]、[[DR-141-unified-domain-semantic-graph]]、[[DR-143-parameter-contracts-calibration-and-readiness]]、[[DR-146-persistent-build-runs-and-artifact-manifests]]

## 上下文 / Context

源项目已实现模型提取任务、实体锚定、多轮澄清、证据检查和确定性编译，但由独立服务及环境变量管理。
其模型客户端校验完整消息协议、JSON 字段、拒答和截断，DataMind 普通 run_turn 的单消息接口不是等价替代。
agent 的生成依赖受支持的固定模板与六个公开输入，并没有任意规划或任意资源调度能力。
行为树生成属于消费本体的应用，既不是 OWL 导出格式，也不是现有动作中心的业务执行记录。

## 决定 / Decision

1. **迁入业务内核**：把任务服务和编译器作为 DataMind 本地领域模块调用，不依赖独立 Web 服务或 iframe。
2. **模型只理解任务**：保留 operation、part、station、carrier、slot、unsupported_requests 六字段和明确选择/撤销规则，禁止模型直接生成 XML 或填物理参数。
3. **配置集中、协议保留**：使用平台 bt_extract 模型用途配置，保留 system 与历史消息、JSON 模式、字段校验、响应限制、拒答及截断检查。
4. **失败如实返回**：模型失败和未知任务不得回退为默认抓移放，也不沿用数据问数的演示兜底。
5. **版本固定**：会话固定本体版本、模式和 profile，每次运行固定编译器、提示词与证据快照；新版本发布不改写在途输入。
6. **确定性生成**：只使用被支持的模板、实体、绑定、参数与条件，保持原模板结构，任何新增控制流都需要独立规约和测试。
7. **策略显式分离**：正式应用保留 needs_clarification、needs_information、unsupported、generated、error 状态，不完整作者草稿由单独策略管理。
8. **校验能力如实声明**：首版执行已有 SHACL、模板、端口、参数、绑定和符号数据流检查，不宣称已具备通用资源冲突分析或失败收尾保证。
9. **产物边界明确**：输出离线候选 XML、manifest 和验证报告，生成阶段只依赖发布本体，不回读原行为树 XML，不新增现场执行 API。
10. **用途配置不等于独立模型**：bt_extract 是内部用途标识，UI 显示“行为树任务解析模型”，可以复用现有模型与凭据配置，不要求新增模型部署。
11. **专用适配复用已有协议**：迁入源项目的严格任务解析协议并接入平台配置，不重新实现普通聊天；六字段任务结构与六个公开技能输入是不同契约。
12. **固定模板边界显式化**：首版保留原子技能、复合技能、实现与每次调用，按现有模板固定步骤顺序，仅从本体选择允许的配置；保存步骤知识不代表支持自由技能组合。
13. **编排扩展另行立项**：多模板选择、模板编辑发布及自动规划需补充契约与验证，不作为本次迁移已经具备的能力。

## 后果 / Consequences

- 正面影响：平台统一模型配置和交互体验，同时保留已验证的澄清与拒绝语义。
- 正面影响：每份候选可固定到可审计本体版本，避免处理中被其他编辑影响。
- 代价：需要适配模型配置与会话存储，不能直接调用普通文本问答包装器。
- 代价：支持范围首先限定于现有 UR 抓移放，更多任务必须注册模板、契约和验证用例。
- 影响的文件/路由：机器人 task_service、llm_adapter、compiler、会话 API、生成应用与平台引擎设置。
