# DR-099 · 证据强度补漏：单值子键、指标的独立参照、指标 id、否决模式回流

状态：已实现。日期：2026-11-13。
关联：EVID-STR-01、MET-REF-01、REVIEW-FB-01、DR-035、DR-054；来源为 2026-11-12 代码审查。

## 问题

- 两条构建路径都以 `min_distinct=1` 调用统一裁决。子键只有一个取值时，重叠率只能是 0% 或 100%，
  只要这个值在父表里出现、键名有据，关系就被判为 verified。
- 指标核验逐个比对参照，一致即停。从参考基准反解出的指标带两个参照：它自己的来源 SQL，以及人工校准的参照值。
  来源 SQL 排在前面，而它与契约出自同一条语句，比对必然一致，所以参照值永远比不到：参照值写 99999、实际为 100 也是 verified。
- 指标 id 只含表、列、聚合方式。同一列上过滤条件不同的两个指标共用一个 id，写入指标层时后一个覆盖前一个。
- 人审否决的关系模式回流到提议提示词时，只认示例本体的字段名（`source`/`target`、对象 `id`）。
  构建产物用 `source_concept`/`target_concept` 和对象 `name`，否决一条也读不到。

## 决定

- 统一裁决里，子键只有一个取值且其余条件满足时，判为 candidate 并写明原因，交人工判断。两个及以上取值的行为不变。
- 指标核验先比独立给出的参照值。参照值不一致时即判不一致，不再用来源 SQL 的自比结果改判；参照值一致时，证据记录的是参照值。
- 指标 id 在有过滤条件时追加过滤条件的摘要（`.f` 加 8 位十六进制）；无过滤条件的 id 不变。
  已入库的旧 id 在下次并入时按名称匹配。
- 否决模式按 IR 形状取端点键名，对象同时按 `id` 和 `name` 索引。

## 没有改的

- 只有来源 SQL 一个参照的指标，核验的仍是「契约能复现来源语句」，不是指标本身正确。
- 孤儿记录容忍（重叠率不低于 20% 即可 verified，DR-070）和抽样库上的证据完整性标记未改。
- 多态键规则、码表关系、声明外键对已有关系的改写规则未改；继续构建时人工决定过的关系由 DR-097 保护。
