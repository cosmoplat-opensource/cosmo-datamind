# DR-130 · 两张子表互相放大、指标的汇总方式、查数结果三态、实际取数日期

状态：已实现。日期：2026-11-15。
关联：QA-FANOUT-02、METRIC-ALGEBRA-01、QA-STATUS-01；DR-054、DR-055、DR-122、DR-129。

## 背景

研读 QCon 上海 2026 的几份本体与语义层材料后，对照现有实现找出四处缺口。材料只提供思路，下面的做法是按本项目的现状定的。

1. DR-055 的扇出关卡只拦「对一对多父侧表的列求和」，且只认 `SUM(别名.列)` 这一种写法。
   一张工单有三条工序、两条设备占用，把工单、工序、占用三张表一起关联后对工序工时求和，每条工序会被算两遍；
   这种情况聚合的是子表的列，原关卡不拦。聚合里写表达式、列不带表名时也不拦。
2. 指标契约声明了聚合方式，但没有说明换粒度时能不能相加。平均值再求平均、去重计数相加，结果能算出来，但是错的。
3. 一条查询执行出错或被校验拦下后，这条分析直接从答案里消失；返回 0 行与「业务上没有」不作区分。
4. 依据卡只有全库的数据日期，看不出一条查询实际读到的数据新到哪一天。

## 决定

- **子表互相放大**。校验时按别名记下语句里出现的「子表 → 父表」关联。同一个父表别名下关联了两张不同的子表，
  或两张子表按指向同一张父表的键直接关联（多对多），对其中任一子表的列做 SUM / AVG / COUNT(列) 即拦下，
  说明是哪两张表、共同的父表是什么，并给出改法（分别按父表的键聚合后再关联）。这种情况下 COUNT(*) 也拦下。
  COUNT(DISTINCT)、MIN、MAX 不受影响；先在 CTE 里各自聚合再关联的写法不拦。
- **表达式与不带表名的列**。聚合函数的参数按括号配对取出，里面出现的列都检查。
  不带表名的列，语句用到的表里只有一张有这一列时归到那张表；两张表都有的不猜；数据库打不开时不猜。
- **汇总方式**。由聚合方式推出：求和、计数可以相加；最大、最小可以上卷但不能相加；平均值要用合计除以计数重算；
  去重计数只能回到明细重算。写进指标的计算规则文本，随计算规则卡和问数上下文一起给出。不需要另填字段。
- **三态**。每个结果标 `status`：`data` 或 `empty`。空结果核对所读的表各有多少行，
  区分「表里没有数据」和「筛选条件没有命中」，两种都注明不能据此认为业务上不存在。
  执行出错和被本体约束拦下的查询计为失败，在依据卡上列出标题和原因，注明这部分结论缺少依据。
  三种状态的条数和失败清单记入答案记录。
- **实际取数日期**。每个有数据的结果给出 `data_as_of`：所读的表、时间列、该列的最大值。
  时间列取查询里用到的那一列；查询没用到时间列时取对象上声明的时间列；都没有就不给。依据卡上显示「实际取数截至」。

## 没有做的

- 判断在整条语句上做，不分子查询的作用域。按父表别名区分已经避开了大部分误判；
  子查询与外层恰好用同一个别名指同一张父表、各自关联不同子表时，仍会被拦下。
- 一张父表、一张子表时的 COUNT(*) 不拦：它数的是子表的行，问句要的是哪张表的行数，校验阶段判断不了。
- 汇总方式目前只是告知，没有据此拦截「对平均值再求平均」的语句。
- 没有做指标与明细共用口径的下钻、参数化指标、归因工具。
- 空结果的核对只看表的总行数，不分析是哪个条件没命中。
- 取数日期按时间列的最大值，不区分事件时间与入库时间，也不判断数据是否过期。
