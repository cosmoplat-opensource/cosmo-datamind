# DR-067 · 离线候选生成与可读版本

## 上下文

用户明确批准：适配依据和有效期不再是基础生成前置条件，缺少适配记录也能生成离线候选 XML。
用户同时要求替换难以辨认的长版本号。
本决定覆盖 DR-066 在基础任务页面沿用严格适配准入的要求；既有严格领域接口和正式治理能力保留。

## 决定

1. 基础 HTTP 任务使用离线候选策略；对象选择、映射、参数、知识核对、模板、结构及符号验证继续执行。
2. 适配依据缺失、过期、被撤销或不匹配时，离线生成不受阻，但任务状态和验证报告必须说明适配未验证，执行始终未验证。
3. 原严格生成接口默认保持证据准入；离线策略必须显式传入，不能伪造证据或修改 OWL 来绕过检查。
4. 任务页用折叠的“适配记录（可选）”记录抓取/放置备注，不再要求日期、资料或确认勾选；备注按任务和版本保存，不算适配验证。
5. 已有正式证据继续按真实范围和有效性评估；提交中的撤销也更新最终报告，离线产物不能声称已通过设备验证。
6. 同一本体按版本登记顺序显示“版本 1、版本 2…”；编号与不可变内部 ID 一一对应，不截取 ID，不根据时间或当前列表排序猜测。
7. 现有版本表仅追加、不提供删除；使用其持久登记顺序计算编号，无需改写 OWL 或迁移资产表。
8. 新增版本不改变旧编号，分支版本也获得不同编号；不同本体的编号分别计算。
9. 任务页、本体目录与版本详情使用一致编号；内部 ID 保留在链接、请求和 DOM 身份属性中，不在详情正文或折叠区显示，保存后显示版本变化提示。

## 后果

生成成功仅说明离线候选通过软件校验，不说明现场适配或执行验证完成。
可选备注没有有效期，也不会替代正式证据；更换版本后不将旧版本备注当作新版本的适配记录。
旧任务可只读显示新版页面，并通过明确的“继续生成”操作使用当前选定任务，不要求重新调用模型。
原测试中“页面必须填写适配证据才生成”和“显示完整内部版本 ID”的预期由本次用户需求替代，其他保护断言保留。
