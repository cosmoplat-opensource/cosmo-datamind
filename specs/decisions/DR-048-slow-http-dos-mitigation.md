# DR-048 · HTTP 慢速攻击缓解(Slowloris)

- **状态 / Status**: accepted
- **日期 / Date**: 2026-08-14
- **决策者 / Deciders**: Boss(用户,漏洞扫描报告)+ Writer(Claude)
- **关联 / Refs**: [[DR-006-security-model]];实证=`srv_hardening.py`、`server.py`、`tests/unit/test_srv_hardening.py`、实连复现记录

## 上下文 / Context

漏洞扫描系统 2026-08-14 对 `http://192.0.2.32:8092/` 的扫描,
在 0 紧急 / 0 高危 / **1 中危** / 10 低危 / 7 信息中,唯一中危为:

| 项 | 值 |
|---|---|
| 漏洞 | http 慢速攻击(Slow HTTP DoS) |
| CVE / CVSS | CVE-2007-6750 · **5.3** |
| POC | HTTP 连接持续时间 **186s** |
| 修复建议 | ①设置适当的超时时间,规定请求头和请求体发送的**时间以及频率**;②增加最大连接数 |

该端口正是本系统。成因:`app.run()` 用 Werkzeug 内置服务器,
**请求处理器不设任何 socket 超时**、线程数无上限——只发半截请求头即可长期占用连接与线程。
本地复现:连接存活 **75s+** 未被切断。

## 决定 / Decision

新增 `srv_hardening.py`,在 `app.run(request_handler=...)` 处装上三道约束:

1. **请求头总时限**(默认 10s,`DATAMIND_HDR_BUDGET`)——**本修复的关键**。
2. **请求正文总时限**(默认 300s,`DATAMIND_BODY_BUDGET`)——远宽于头预算,不误杀慢速大文件上传。
3. **socket 超时**(默认 30s,`DATAMIND_REQ_TIMEOUT`)+ **并发上限**(默认 256,`DATAMIND_MAX_CONN`,
   超出即刻关闭、不排队不占线程)——对应建议②「并发要有明确边界」。

环境变量缺失/非法/越界一律回落默认值,**不允许退化成「无限制」**。

## 为什么单靠 socket 超时不行(实测)

首次实现只设了 `WSGIRequestHandler.timeout=30`,**实测无效**:连接每 3s 滴入一个请求头即存活 75s+。
原因是 `settimeout` 约束的是**单次**读的等待,慢速客户端持续滴入数据就能无限续命——
这正是 Slowloris 的原理,也解释了扫描器为何能撑到 186s。

真正管用的是**跨多次读的总时限**(等价于 Apache `mod_reqtimeout` 的 header 预算,
亦即报告里「时间**以及频率**」的后半句)。实现为 `_DeadlineReader`:
在 `parse_request()` 期间对读流施加绝对截止时间,头读完即换用更宽的正文预算。

**修复前后实测**:

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 每 5s 滴一个头 | 存活 75s+ 未断 | — |
| 每 3s 滴一个头 | — | **12.1s 被切断** |
| 每 1s 滴一个头 | — | **10.1s 被切断** |
| 扫描器 POC | 186s | 预期 ≈ 头预算 |

## 与 SSE 长流的关系(已验证)

系统有 4 个 SSE 端点,深度问数可跑数分钟。超时是**单次 socket 读写**与**请求接收阶段**的上限,
不是响应流的寿命上限;流期间服务端只在有事件时写,客户端正常读取时写不阻塞。

实测:一条深度问数 SSE 流持续 **85.4s**、**最大事件间隔 40.3s(> 30s socket 超时)仍未被切断**,
34 个事件完整送达。

## 影响 / Consequences

- (+) 中危漏洞闭环:慢速连接由「无限占用」变为 ~10s 内被切断,且并发有硬上限。
- (+) 参数全部可经环境变量按部署环境调整,启动横幅如实打印生效值供运维核对。
- (−) 头预算 10s 对**极端劣化网络**下的正常客户端偏紧;可用 `DATAMIND_HDR_BUDGET` 放宽(上限 30s)。
- **边界**:本修复加固的是内置服务器。对外提供服务时仍建议按 README 走 WSGI + 反向代理,
  由反代承担 TLS、限速与更强的连接治理——本修复保证的是**即便直接暴露内置服务器也不再被慢速攻击拖垮**。
