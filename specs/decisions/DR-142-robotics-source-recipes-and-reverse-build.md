# DR-142 · 机器人本体自动构建、增量编辑与发布契约

> 引用的开发中间材料仅保留本地副本；历史记录不代表当前版本已验证。

- **状态 / Status**: proposed
- **日期 / Date**: 2026-11-02
- **关联 / Refs**: [[DR-050-executable-ontology-build-gate]]、[[DR-056-evidence-integrity-and-isolated-validation]]、[[DR-141-unified-domain-semantic-graph]]、集成技术方案（本地材料）

## 上下文 / Context

upstream 的 ontology_pipeline 能确定性抽取行为树及节点模型，但混合了 UR 模板、角色和示例业务知识。
其固定模板和步骤定位不能代表对任意 BehaviorTree.CPP v4 XML 的支持。
本次复测中新构建图通过构建侧 SHACL，却因缺少 artifactContract 被 agent 拒绝，构建器也未输出 agent 要求的 validationShapes。
agent/input/ur_skill.owl 可以被当前 agent 加载，而 ontology 的存量及新构建 OWL 未通过同一加载契约。
ontology 自带生成入口与 agent 消费入口存在差异，不能将局部生成成功视为两个入口已经兼容。
平台必须提供从来源、候选、领域编辑到可消费发布物的完整流程。
重建若只覆盖文件，会丢失人工补齐的实体映射与参数依据。

## 决定 / Decision

1. **独立构建配方**：增加机器人行为树逆向构建配方，与现有数据构建并列，输入明确区分主行为树和节点模型两种来源角色。
2. **支持范围显式化**：首版只支持当前 UR 抓移放 profile 及其 BTCPP v4 结构子集，未知节点、模板差异和模型冲突返回定位信息。
3. **抽取与策略分离**：抽取负责技能实现、调用、端口、绑定、顺序和数据引用，profile 负责已支持的技能组合、角色、公开配置及任务模板。
4. **来源不可变**：上传资产保存字节摘要及逻辑标识，语义事实记录来源文件角色和节点位置，不暴露部署绝对路径。
5. **草稿可补齐**：实体映射、参数 Profile 和适配证据通过领域编辑形成可审计候选，来源字面量不自动升级为标定或适配证据。
6. **重建保留人工工作**：新来源与既有已审核修改通过带前置条件的差异合并关联，身份不明或步骤变化产生冲突，不按旧序号静默套用。
7. **发布封装成为正式步骤**：发布产物包含受支持的 artifactContract、内嵌 SHACL、来源与版本信息，并由消费侧验证器复验。
8. **规则受版本约束**：SHACL 摘要和编译器支持关系由本地受信代码登记，不以接受任意上传规则的方式解决兼容问题。
9. **领域验证独立**：机器人结构与绑定校验不使用数据库关系裁决，构建成功和发布成功均不替代具体任务的证据准入。
10. **发布验证覆盖语义**：补齐协议标识和内嵌规则后，还须验证模板、条件与绑定兼容性，不能仅以两个字段存在作为成功条件。

## 后果 / Consequences

- 正面影响：本体自动生成真正成为平台前段能力，新构建产物能够进入同平台的后段生成。
- 正面影响：已有人工知识可随来源变化复核，失败原因可回到文件和节点定位。
- 代价：必须补发布器、领域编辑和差异合并，直接搬运 CLI 无法完成目标。
- 代价：首版支持范围受现有模板限制，扩展控制流与机器人类型需要新增 profile 和测试。
- 影响的文件/路由：机器人 importer、profile、publisher、领域编辑器、构建 API、来源上传与构建 UI。
