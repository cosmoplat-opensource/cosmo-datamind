# DR-143 · 参数依据、适配证据与分层准入

- **状态 / Status**: proposed
- **日期 / Date**: 2026-11-02
- **关联 / Refs**: [[DR-054-metric-contract-and-lifecycle]]、[[DR-056-evidence-integrity-and-isolated-validation]]、[[DR-141-unified-domain-semantic-graph]]、[[DR-142-robotics-source-recipes-and-reverse-build]]

## 上下文 / Context

历史 XML 的数值可证明来源配置，不能证明其适用于当前对象、机器人、坐标系或槽位。
yang 构建侧允许不完整草稿，agent 则在缺少业务映射或适配证据时拒绝生成候选。
直接复用指标的 candidate/verified/certified 状态机并统一阻断所有输出，会丢失作者草稿能力且混淆不同证据含义。
本体协议合法、参数有来源、适配已确认与机器人可执行是不同结论。

## 决定 / Decision

1. **参数与证据分开建模**：参数记录值或引用、端口类型、单位及坐标系等已知信息，适配证据记录对象范围、技能实现、有效期和依据来源。
2. **未知保持未知**：没有来源的单位、坐标系、物理量或标定结论不由模型推断为事实，源字面量保留其原有证据等级。
3. **状态维度独立**：分别记录草稿/发布状态、结构验证、业务映射完整性、参数依据、适配有效性和执行准备状态。
4. **作者草稿允许不完整**：缺少值或证据的本体可保存、比较和评审，若生成调试草稿则显著标记未解决项，不能作为正式候选成功返回。
5. **严格生成保持准入**：应用按所选任务检查实体确认、参数完整性和必要适配证据，缺失时返回 needs_information，不用默认值、用户口头确认或演示证据补齐。
6. **发布不等于全任务就绪**：结构及协议完整的版本可以发布，具体任务仍根据其引用的实体和证据独立检查。
7. **确认可审计**：人工审核记录操作者、依据、时间和适用范围，不能用一次普通点击伪造测量结果或自动获得技术验证。
8. **失效保持可追溯**：证据到期、撤销或被替代时，相关候选增加复核提示，原证据和原始报告保持可审计。
9. **执行状态保守准确**：首版生成产物保持 execution_readiness=not_verified，静态和符号检查不报告实际机器人运动成功。
10. **业务映射在知识完善阶段维护**：本体构建后、评审发布前，登记零件到零件类型及感知 Profile、工位到载具和槽位、槽位到放置 Profile 的关系。
11. **任务选择与知识确认分开**：生成时将用户名称定位到已登记实体并检查映射，歧义通过对话澄清；本轮选择不自动成为永久知识或适配证据。
12. **跨领域关联可渐进接入**：数据库记录与机器人实体的对应关系可辅助建立业务映射，但连接业务数据库不是首版机器人知识维护的前置条件。

## 后果 / Consequences

- 正面影响：既支持工程师逐步完善知识，又保留 yang 严格生成入口的证据边界。
- 正面影响：UI 能解释到底缺少哪一类知识，避免单个“通过”状态误导用户。
- 代价：领域报告和评审 UI 需要展示多个独立维度，不能机械复用指标认证页面。
- 代价：真实样例缺证据时仍不能产出严格候选，演示成功不能代替真实适配验收。
- 影响的文件/路由：机器人参数与证据模型、领域评审、任务准入、版本差异与工件新鲜度查询。
