# DR-163 · 独立测试数据与有界并行验证

状态：accepted。
实现交付状态：delivered。

## 验证目的

完整测试集继续覆盖真实构建、语义校验、固定版本读取、持久化、回滚、幂等及错误路径。保留现有断言、可选组件跳过条件和整体 74%、核心 87%、路由 61% 的覆盖率门槛。生产代码与校验实现不变。

## 决策

任务测试的公共准备数据由本轮真实构建生成，每个测试通过原受理和保存服务创建独立数据库、资产身份、运行记录及字节文件；只复用真实构建产出的本体字节及其报告，保存时仍重新执行完整语义校验；不复制数据库中的资产和运行身份，仅复用构建完成的初始条件，不缓存测试操作中的校验结果。不改动直接验证构建与发布行为的原有测试入口。变体在独立图副本上构造，已有目录使用原构建路径，禁止覆盖现存数据。失败的种子生成不得留作成功缓存。

现有本地并行命令构造采用固定版本的 pytest-xdist，保留不超过 4 个工作进程及单进程对照的独立回归。每个进程保持独立临时环境，pytest-cov 汇总全部进程的覆盖率，失败仍使检查非零退出。新增依赖仅用于开发验证；pytest-xdist 3.8.0 使用 MIT 许可证并支持 Python 3.9 及以上，与当前 Python 3.10/3.11 环境兼容。现有 PyYAML 的 CI 配置检查配套固定 types-PyYAML 6.0.12.20261113（Apache-2.0，Python 3.10+），保留 YAML 结构解析和类型检查，不新增忽略规则。

保留全套用例，记录 JUnit 逐项耗时与最慢用例，以完整运行实际结果判断优化效果。原始日志和性能取样保留在本地检查目录或 CI 附件，不逐轮提交开发过程报告。当前 CI 以 master 的分组结构为准：`unit_tests` 使用 8 个矩阵分组，各自安装 Python 测试依赖、Node、Playwright 和 Chromium，执行分组并上传覆盖率数据；每组 CI 预算 70 分钟，脚本内分组进程预算 55 分钟。`unit` 依赖全部分组成功，失败时在下载和汇总前退出；按分组总数下载完整覆盖率输入，执行 lint、类型检查及三层覆盖率门槛，CI 预算 15 分钟。普通完整单元入口通过 pytest-cov 汇总分支覆盖率，按 `--workers` 使用 1～4 个进程，脚本内预算两小时；CI 分组入口仍用 coverage 执行对应分组，汇总入口只合并覆盖率，不重新运行全套测试。

## 任务浏览器的有界并行与诊断

任务浏览器复用设计浏览器的既有 pytest-xdist 调度方式，默认两个独立进程，`--workers 1` 保留完整串行对照，进程数仅允许 1 或 2。
每个进程拥有独立浏览器，每个用例拥有独立服务、模型端点及临时存储；完整执行原有构建、任务适配、语义校验、重试、历史与下载断言，不缓存测试操作结果。
默认入口不筛选用例，显式 `--case` 继续只用于定向检查，任一测试失败或收集失败均使入口非零退出。
日志实时记录用例名，并输出逐项 JUnit 与最慢 20 项耗时，阶段被终止时仍可定位已完成与进行中的用例。
任务入口先等待真实固定版本就绪，再保留原页面与版本断言；准备和导入响应使用产品既有的 30 秒请求期限，不误用普通控件的短等待时间。
慢网回归只延迟真实浏览器传输，覆盖任务准备与 OWL 导入，仍校验真实服务响应、固定版本、模式隔离和源资产字节，不替换成功响应。
保留 600 秒阶段上限及现有 CI 总预算，不以延长限制替代优化。
验证需同时覆盖入口契约、受限 CPU 下的串行对照和完整 `scripts/check.py --suite ui` 浏览器任务，不将本地结果解释为远端 CI 已通过。
