# DR-014 语义罗盘三补:关系进问数 · 反馈回流队列 · 最小根因诊断

日期:2026-07-25 · 状态:已实现 · 回归:test_all.py 119/119

## 背景

deck 差距审计发现三处"讲了但系统没有":①深度问数不用本体关系(JOIN 靠 LLM 猜);②反馈按钮纯前端装饰,无证据回流;③根因诊断四步(P21)整体缺失。

## 决定与实现

1. **沿本体关系召回进问数**:`_join_hints()` + build_context 一跳邻居召回——命中表沿 verified/asserted 关系把维表拉进上下文(≤4 个),并给出 `⋈ 子表.child_key = 父表.parent_key` JOIN 提示行(≤12,键取关系证据);SQL 规划 prompt 要求 JOIN 优先用这些键;chat_stream 新增 `ontology_relations` 步骤露出("沿本体关系召回 · N 条已验证关系作 JOIN 依据")。
2. **反馈落库 + 本体迭代候选队列**:`POST/GET /api/chat/feedback`、`POST /api/chat/feedback/resolve`(workdir/qa_feedback.json,原子写+锁)。问数/诊断结果卡「有用」直接上报;「待改进」展开内联意见框→提交进队列;评审页新增「本体迭代候选队列(证据回流)」区,待处理高亮、可标记已处理——P24 质量链第⑥环闭合。
3. **最小根因诊断(P21 前三步)**:问数新增「根因诊断」模式,`POST /api/diagnose/stream`:本体识别意图(cn 变体匹配,含去「表」后缀)→ 沿关系召回(2 跳 BFS,≤8 对象/14 关系)→ LLM 受白名单约束生成 ≤3 根因+检查清单 → **边界校验**(路径引用越界对象→降 candidate;依据关系非 verified→candidate)。引擎离线如实拒答("宁可不答,不编结论");实体未命中本体也拒答(不作无锚定生成)。结果卡:根因(状态签+路径+依据)+检查清单+边界声明+反馈按钮(接②,闭环)。

## 不变量

- 反幻觉规范延续:诊断只在本体边界内作答;verified 标签只来自关系的数据裁决状态。
- 全部无原生弹窗(DR-013 教训);反馈队列全局(不分图谱)。
