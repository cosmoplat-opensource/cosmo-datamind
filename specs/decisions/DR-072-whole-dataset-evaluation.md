# DR-072 · 全库评估与修正:注释接入、类型无关的取值比对、按取值补提与实例表识别

- **状态 / Status**: accepted
- **日期 / Date**: 2026-10-01
- **关联 / Refs**: [[DR-071-full-scale-holdout-evaluation]]、[[DR-060-build-preflight-sampling-and-rounds]];
  实证=`tests/unit/test_build_agent_gaps2.py`

## 上下文 / Context

此前各轮评估用的能碳抽样库没有库表注释(只读抽样的旧导出未写 `_dm_tables` / `_dm_columns`),而平台的只读抽样会保留注释
(实库表注释 75%、字段注释 82%),评估与实际使用条件不一致;评估也只覆盖部分表与少量参考关系。本次改为在整个数据集上评估:

- 评估库:同一份抽样数据 + 按平台抽样格式写入的库表/字段注释,594 张表,15 轮全部构建;
- 对象:全部对象的中文名与库表注释是否一致、覆盖、重名;
- 关系召回:不依赖智能体键名逻辑,按取值在全库穷举「子列 ⊂ 唯一父列」得到 3,364 个候选对,随机抽 140 个人工判定真伪,
  以判定为真的关系计召回;
- 关系精度:已验证关系按证据来源分层随机抽样,人工逐条判断;
- 问数:覆盖 15 轮各业务域的 19 道题,答案与直接查库比对,同一本体跑 3 次;
- 人工工作量:候选关系、复核弱冲突、待确认名称的条目数。

## 发现与决定 / Findings and Decision

1. **类型不同的同一取值算作不重叠**:子表把编号存成文本 '121'、父表存成整数 121 时,`INTERSECT` 按存储类型比较,
   重叠率记成 0%(价格标准 → 价格分组真实 98.6%)。取值先规范成文本再比较。
2. **字段注释没有进对象属性**:问数上下文与召回都看不到字段含义。构建时把 `_dm_columns` 的注释补到属性上;
   库表注释作对象别名,模型起的中文名与注释毫无共同字时标记待确认。
3. **模型漏建对象**:每轮有个别表没被模型建成对象,其上关系无从建立。本轮范围内未覆盖的表按注释补建基础对象。
4. **负责人、审批人等角色引用**列名与用户编号对不上:取值是 `USER_10411` 这类带字母的编码时,按取值补提候选,
   经取值形态证据成立(编码 100% 落在父列时去重值下限 5)。
5. **实例表被当成「版本重复」的父表**:量测实例表里同一量测编码按设备各存一行、名称一致,被认成版本重复。
   同键的重复行能被另一个标识列(设备编号等)区分时判为实例表,有效行规则与类别作用域都不再按版本重复处理。
6. **同一子键验证指向多张父表**(设备编码同时连到设备主表与网关下挂设备):保留父表核心名与键词根最吻合的一条,其余改为候选。
7. **复数表名**(price_groups)在键名比对时还原单数;问数召回中对象完整中文名或别名原样出现在问句里时计分最高,
   中心词去掉「信息」「数据」等后缀再取,同分时偏向已验证关系多的主数据表。
8. **码表 CASE**:提示按文本比较编码(库里可能存成文本也可能存成数字)。

## 后果 / Consequences

同一份全库评估数据、真实模型,本轮第一次构建(修正前)与最终构建(修正后)对比:

| 指标 | 修正前 | 修正后 |
|---|---|---|
| 15 轮构建耗时 | 556 秒 | 598 秒,无降级轮次 |
| 对象覆盖 | 526 / 550 张计划表 | 550 / 550 |
| 中文名与库表注释一致(有注释的表) | 92% | 92%;不一致 33 个,另有 15 个同名待确认 |
| 14 条核心关系 | — | 14 条已验证 |
| 已验证关系抽查(分层随机 50 条) | — | 49 条正确(1 条父表选了网关下挂设备而非设备主表) |
| 全库穷举候选中人工判定为真的 22 条 | 已验证 13、候选 2 | 已验证 14、候选 2;未提出的 5 条主要是逐表租户键与审计列(设计上不逐表建) |
| 19 道全库问数(同一本体跑 3 次) | 8 题答对,4 题答错且无提示 | 13~14 题答对,答错且无提示 0 题,其余给出提示或被拦下 |
| 需人工看的条目 | — | 367 / 1,323(候选关系 336、复核弱冲突 16、名称待确认 15) |

- 问数中仍答不对的题:多为在若干同类表(多套标签、多套账单、多套用能单元结构表)中选错表,或关系因孤儿记录过多停在候选被拦下;
  这些情况都会给出提示或拦下,不再静默答错。
- 人工工作量的大头是候选关系(336 条),其中多数是模型提出、重叠不足或键名无据的关系;是否自动驳回其中一部分是下一步要定的取舍。
- 评估脚本与参考答案保存在本地评估目录,不进仓库。

## 备选与不做 / Alternatives

- **用库表注释直接替换模型起的中文名**:不做。注释常带「元数据-」「xx表」等修饰,模型的措辞多数更规范;只作别名并标记冲突。
- **对未覆盖的表不补对象,等人工**:不做。补建的对象标记 `coverage_fill`,审阅时可一并确认。
