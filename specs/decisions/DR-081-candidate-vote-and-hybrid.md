# DR-081 · 精确作答的多路候选投票;本体约束校验作为智能体工具;跨方法投票

- **状态 / Status**: accepted
- **日期 / Date**: 2026-10-05
- **关联 / Refs**: [[DR-080-qa-probe-verify-and-role-keys]];实证=`tests/unit/test_qa_vote.py`;实验=`../08_对比实验/结果报告.md` 第 10 节

## 上下文 / Context

DR-080 之后,DataMind 问数在 BIRD Mini-Dev 测试集上与 ReAct 智能体持平(42.2% 对 42.6%),
但两者答对的题有相当一部分不重合。目标:在同一骨干模型(DeepSeek-V4-Flash)下超过 EvoOntology(44.6%)。
方法选择只用开发集(构建 174 + 验证 75 = 249 题;DataMind 不读题目,用这两部分开发不泄漏测试集),测试集每个最终方法只运行一次。

## 决定 / Decision

1. **精确作答的多路候选与执行结果投票**(`/api/chat` 的 `candidates: k`,k ≤ 3):
   - 按三种规划策略(默认、先探查、先写出所需表列与条件)各走一遍完整问数链路,并行执行;
   - 按结果行集合分组投票(只比取值,数值统一到 6 位小数,行序无关);
   - 票数相同时由模型在并列组中选择;响应中加 `candidate_vote` 步骤说明票数。
2. **本体约束校验作为智能体工具**(对比实验 `tool_server/datamind_gate_mcp.py`,不进产品):
   开发集上反而下降(见后果),不作为最终方法。
3. **跨方法投票**(对比实验 `hybrid_vote.py`):ReAct 智能体 + DataMind 本体(C3)与 DataMind 多路候选(D3)两路答案,
   结果一致直接采用,不一致时由模型按问题与执行结果选择。

## 后果 / Consequences

开发集(249 题):

| 方法 | 答对 |
|---|---|
| C3 ReAct + DataMind 本体 | 118 |
| E1 C3 + 本体约束校验工具 | 107 |
| D2 DataMind 问数(DR-080) | 104 |
| D3 D2 + 多路候选投票 | 108 |
| H1 C3 + D2 + D3 投票 | 114 |
| **H3 C3 + D3 投票** | **126** |

- E1 下降的原因:BIRD 的 SQLite 工具已给出声明外键,智能体的连接几乎都正确(216 题调用该工具,217 次通过、4 次拦截),
  校验带不来新信息;不能把这个结论推到外键缺失的工业库上。
- H1 低于 H3:D2 与 D3 出自同一系统,错误高度相关,两票压过 C3;投票源要来自不同方法。

测试集(251 题,一次运行):H3 117(46.6%),高于 B(EvoOntology)112(44.6%)、A 107、C3 106、D2 106、D3 105。
配对 McNemar:H3 对 B p = 0.44(不显著),对 C3 p = 0.02,对 D3 p = 0.06。
