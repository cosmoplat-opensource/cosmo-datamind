# DR-135 · 算术见证与多级表头

> 2026-11-17：[DR-139](DR-139-review-of-dr133-138.md) 修订了算术见证的误差下限、派生公式按表核验与多级表头的四处问题。

状态：已实现。日期：2026-11-16。
关联：ARITH-WITNESS-01、UPLOAD-HEADER-01；DR-093、DR-054。

## 背景

年报表格与 iXBRL 标注对齐的实验里，有两点可用于产品：

1. 「总计 = 分项之和」这类算术关系是可靠的证据。业务库里同样常见：毛利 = 金额 − 成本，金额 = 数量 × 单价。
   而构建时模型提出的派生公式一律标为「尚未执行核验」，问数时模型也不知道哪些列之间有确定的算术关系。
2. 那条线的主要瓶颈是列归属：一个数值属于哪一年、哪个项目，写在上层表头里。
   产品上传 CSV 时只认第一行表头；Excel 用合并单元格做的两三行表头导出后，列名重复，整份文件上传失败。

## 决定

- **算术见证**(`arithmetic_witness.py`)。对本体里每张表最多取 5000 行，检查「一列 = 两列的和、差、积、商」，
  至少 99.9% 的行成立、有效行不少于 20 才记录。两个输入都不为 0、彼此不相等，且结果的绝对值不小于 0.11(允许误差的十倍)的行，
  不少于有效行的 20%，否则不记(避免 0 = 0 × x 这类对什么关系都成立的行)。同一个等式只记一次，以表里排在最后的列为结果列。
  在示例库 108 张表上找到 12 条(金额 = 数量 × 单价、毛利 = 金额 − 成本、净值 = 原值 − 累计折旧等)，耗时约 1.2 秒。
- 构建时新增步骤 `arithmetic_witness`，结果写入 `ir["arithmetic"]`。派生公式里的算式恰好是「列 运算 列」
  且与某条见证一致(全部行成立)时，标为已核验并附上见证；算式里还有别的项的不算。
- 问数上下文里，列出所选表的算术关系及核验行数。
- **多级表头**(`header_parse.py`)。第一行有空格或重复值(合并单元格的痕迹)，其后连续几行没有数值(四位年份不算)、
  键列位置为空，这几行就是表头，最多 3 行。上层表头在本行内向右补齐，各层用「_」连成一个列名。
  上层是期间(年、季度、月等)时，另存一张 `<表名>_long` 长表：键列 + 期间 + 项目 + 值。删除上传资料时一并删除长表。

## 没有做的

- 算术见证只看两列之间的关系；三列以上的合计(总计 = A + B + C)、跨行的合计(合计行 = 各明细行之和)没有做。
- 见证没有用于指标核验的参照，只用于派生公式和问数提示。
- 多级表头只处理 CSV/TSV；Excel 文件仍只作为资料存档，不建表。
