# DR-056 · 完整取证、状态新鲜度与隔离验收

状态：已采纳
日期：2026-09-07
关联：DR-006 / DR-035 / DR-045 / DR-050 / DR-054，IR-014

## 上下文

已有回归通过不代表边界安全：取值前缀被当成完整证据、复合 FK 被拆边、旧 verified 状态覆盖新失败结果。
构建界面对不完整 SSE 的处理也可能使失败看起来像完成，并丢失输入。
开发者运行测试时默认读取日常 workdir 和可选模型配置，验收结果依赖本机状态。

## 决定

1. 关系取证由 `sqlite_evidence.relation_signals` 在 SQLite 内按完整单列/元组集合聚合。
   在同一只读快照中计数；不以 LIMIT 前缀支持 verified；记录 distinct/匹配数、完整性与方法。
   自动组合搜索仍为 2–4 列，显式键允许最多 32 列；复合 FK 依约束 id 与 seq 顺序作为一条关系。
   声明 FK 必须检查引用完整性；含孤儿记录或无法核验时保留 candidate。
   固定 60% 门槛不变；连接证据不能代替业务语义的人审。
2. 构建取证预算为 60 秒；资源失败必须留痕，不能被编码成验证成功。
   输出不能覆盖源 SQLite（含硬链接）；异常与超时均关闭连接。
3. 机器状态服从最新核验；人工 certified/deprecated 保留。
   不把另一口径的核验证据嫁接到人工确认的口径；参照 SQL/值、维度、粒度、容差与结果一起保存。
   比较拒绝截断、非有限值、非法容差与不规则结果；维度精确匹配，度量用十进制数比较。
   表结构、指标 SQL、参照 SQL 与重分组查询共享一次只读事务快照和查询预算，禁止跨时点伪一致。
   重新核验遇到并发指标变更返回 409，保留最新人工操作；长 SQL 不持有全局写锁。
4. 请求守卫验证完整源和显式 Host；TLS 反代源通过配置声明，不由任意 forwarded 头决定。
   API fetch 在每次重定向及实际连接处验证目标，固定已验证 IP，保留 TLS 校验，禁用环境代理。
   SQL 词法守卫同时处理引号、注释和语句边界，拒绝 SELECT INTO 等写入形式。
   问数使用 SQLite authorizer 检查真实读取表，严格图谱范围与显式选表取交集，含引号和 CTE 同样受限。
   API 物化采用原始列到合法列的稳定映射，表替换与数据插入同一事务。
5. 构建只在收到合法 done 事件时成功；错误、EOF、超时及超限都保留可重试输入。
   底本异步响应必须与最新选择一致；底本加载失败阻断提交；多轮结果容器 id 唯一。
   构建结果中的外部值必须转义，窄屏和键盘操作纳入实际浏览器验收。
6. `scripts/check.py` 为本地与 CI 的统一入口。
   仅从 Git 已提交内容复制测试种子到临时目录，禁用本机模型和引擎配置，独立启动并清理服务。
   单元、覆盖率、lint、类型、HTTP、十轮变序和 UI 分层运行，任何失败返回非零。
   `specs/acceptance.json` 把验收要求关联到可执行测试；元测试防止测试链接失效。

## 后果

- 部分历史 verified 会在重建后降级；这是暴露真实数据问题，旧产物不会自动批量改写。
- 完整取证的数据库扫描成本高于截断集合；大库可能触发预算，需要后续按规模评测和索引优化。
- 默认任意 Host 不再可用，反代部署需设置外部源或可信主机；方言歧义 SQL 会被保守拒绝。
- 当前仍是单用户工作台；不宣称多租户隔离、任意外部 SQL 函数无副作用或所有漏洞已穷尽。
- 需求与测试的链接只证明覆盖入口存在；正确性由测试实际执行、人工评审和独立基准共同支持。
