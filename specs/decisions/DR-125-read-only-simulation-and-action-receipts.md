# DR-125 · 问数推演只做只读试算；动作按回执确定结果

> 2026-11-15：没有结构化回执的服务端错误改记为结果未知，见 [DR-129](DR-129-recheck-on-publish-scope-receipts-columns.md)。

状态：已实现。日期：2026-11-15。
关联：ACTION-EXEC-02、QA-WHATIF-02、DR-120、DR-123。

## 背景

DR-120 让问数里的假设性问题调用低风险动作的执行器。评审指出的问题均已复现：

1. 「低风险」是动作类型上的一个标注，不等于执行器不写业务系统。一句问话就能触发真实的写操作。
2. DR-123 把试算列进了模型辅助分型的选项，模型可以把一个普通问题判成试算。
3. 只有问数权限、经适配层进来的智能体也能触发推演。
4. 执行器调用前没有落盘。进程在调用途中退出，记录里什么都没有，业务系统里却可能已经生效。
5. 执行器超时或返回不完整时记为失败。实际结果不明，记为失败会让人以为可以放心重发。

## 决定

**只读试算。**

- 执行器在部署配置里可以标为只做试算（`simulate_only`）。问数发起的推演只调用标了这个标记的执行器，
  请求里带 `mode=simulate`。没有标记、没有执行器、或动作是高风险的，在调用任何东西、写任何记录之前就拒绝，并告诉使用者到动作中心发起。
- 试算的回执如果声明写回了业务系统，这次试算记为失败并注明违规。
- 模型辅助分型的选项里不再有试算。推演只由明确的假设性问法触发。
- 带调用方声明的请求（经适配层进来）不能触发推演，回答里说明需要使用者在界面里发起。

**动作状态与回执。**

- 状态增加「执行中」和「结果未知」。调用执行器之前先把记录写成执行中；高风险动作批准后同样先写执行中再调用。
- 回执里明确成功才记已执行，明确失败记失败，其余（超时、连接中断、回执不完整）记结果未知。连接被拒绝说明请求没有送达，记失败。
- 执行中的记录超过最长等待时间仍没有回执，下次读取时转为结果未知。
- 每次调用带一个幂等键，执行器可以据此识别重复请求。
- 结果未知的记录由人到业务系统核对后处置：记为已执行或未执行，要署名并写明核对依据。系统不自动重发。动作中心的记录列表上有处置入口。
- 执行器调用不跟随跳转，不使用环境里配置的代理。

## 没有做的

- 是否真的只读取决于执行器自己。标记由部署方配置，平台只核对回执里的声明，无法验证执行器内部的行为。
- 幂等键是否生效取决于执行器的实现。
