# DR-140 · 构建放弃等待后停止模型调用；本体修改前后的配对回放；数据接地的移植偏差与对比基准重测

状态：已实现。日期：2026-11-17。
关联：DATA-GROUNDING-04、FEEDBACK-REPLAY-04；DR-136、DR-137、DR-138、DR-139。

## 背景

DR-139 留下两项。

1. **放弃等待后，后台线程仍在调用模型。** 数据接地(起候选名)和业务概念两步在有界线程里执行。
   构建超时放弃等待，或者客户端断开时，事件流不再等结果，但后台线程会继续发起后面几批模型调用，
   直到它自己的 240 秒预算用完。取值画像的查询也没有时限。
2. **回放分不清差别来自本体修改还是模型的随机性。** DR-138 的多次回放只能发现「几次结论不一致」，
   它比的是反馈时保存的答案和现在的答案。反馈时用的模型调用早已过去，现在问出不同的答案，
   既可能因为本体改了，也可能只是模型这次写法不同。

## 决定

**取消信号**
- 新增 `_cancellable_stream`：在 `_bounded_stream` 外加一个取消信号。事件流结束时都会置位，
  包括正常完成、超时放弃，以及客户端断开导致生成器被关闭。
- `_concept_ask` 每次调用前检查取消信号。已置位时不再发起调用。
- 起候选名按批进行，每批开始前检查取消信号和预算。
- 取值画像的查询挂上进度回调，取消或超时即中断。
- 数据接地和业务概念两步都改用 `_cancellable_stream`。
- 已经发出的那一次模型请求无法从另一个线程中止。它受单次超时约束(至多 45 秒，且不超过剩余预算)，结果不再被采用。

**版本记录**
- 反馈时记下所用每张本体的版本：构建产物的内容摘要、编辑条数、这些编辑的摘要。
- 只要构建产物没有重建、这些编辑在之后没有被撤销或改写(编辑记录只是在后面追加)，反馈时的版本就能精确复原：
  只回放前 n 条编辑。

**版本固定**
- 新增上下文变量 `_IR_PIN`(图谱键 → 编辑条数)。设置后，同一上下文里的问数读到的就是那个版本。
- `load_ir_edited` 按它截断编辑记录。
- 图谱行、修订号、库的适用本体、示例本体适配这几处缓存，遇到固定的图谱时不读也不写。
- 问数的工作线程复制调用方的上下文，固定的版本能传到线程里。

**单条配对回放**(`POST /api/chat/feedback/replay`，`paired: true`)
- 在反馈时的版本和当前版本上，用同一个模型交替提问，各问 1–3 次(界面默认 2 次)。先后次序逐轮交换，抵消时间上的漂移。
- 两边都是现在问的，模型的随机性对两边相同，比较的是「与反馈时的答案一致」的次数。
- 「待改进」的反馈：修改后复现原答案的次数减少，记为修改起了作用。
- 「有用」的反馈：修改后一致的次数减少，记为可能退化。
- 同一版本的几次回答彼此不一致时，在说明里提示。
- 版本无法复原(重建过、编辑被撤销)、反馈后本体没有修改、早期反馈没有版本记录时，给出原因，不做配对。

**批量配对回放**(`POST /api/chat/feedback/regression`，`paired: true`)
- 对「有用」的反馈逐题做配对回放，按题配对计算「修改后 − 修改前」的一致比例之差。
- 用 `qa_eval_stats.paired_ci` 给出 95% 区间(按题有放回重抽样，固定种子)。区间不含 0 时才认定修改改变了答案。
- 列出一致次数减少的题和未能配对的原因。

**界面**
- 评审页：记录了版本且保存了答案的反馈多一个「修改前后对比」按钮。
- 回放区多一个「修改前后配对回放」按钮，显示两边的一致比例、差值、区间和结论。

**数据接地的移植偏差(在对比基准上重测时发现)**
- 第一次重测的正向构建里，数据接地报告「候选名:表 0/0」。原因：抽取时模型已经给代码名的表起了中文名，
  移植版本按「有没有表需要起名」决定是否用取值画像、是否重提，结果在名称不透明的库上两样都没有用上。
- 对照冻结的实验代码(`08_对比实验/runs/v4/dr093_frozen_code`)，有三处与实验不同：
  - 实验只要有取值画像，就用画像摘要并重提；
  - 实验在画像摘要后附上已核验的「用语 → 列」(至多 300 条)；
  - 实验重提时，除了未通过的概念提议的表，还加上已核验用语与概念名有共同英文词的表。
- 三处都改为与实验一致(`_concept_inputs`、`workload_concepts._related_tables`)。这次重测停掉，按改正后的代码重新构建。
  修正 DR-136、DR-138 中「名称正常的库不重提」「有对象需要起名时才改用画像摘要」的说法。
- DR-139 把每轮重提的条数限制在未通过的条数以内，实验没有这个限制，模型可能把一个概念拆成几个重提。
  现改为不限条数(至多 40 条)，重提的条数计入「提议」，所以「未保留」仍不会是负数。

**对比基准重测结果**(2026-11-17)
- 设置与实验分支的 dm93 完全相同：不透明合并库(BIRD 11 个库合并、表名列名换成代码)、同一份构建用业务问题(139 条，只有问题和口径说明)、
  同样的 dm2evo 转换参数，由 EvoOntology 的智能体经共享工具使用本体，测试题两个方向各 200 道、各跑 3 次，模型 deepseek-flash。
  本轮构建包含画像、反查、核验与不限失败条数的重提策略。实验脚本和逐题统计仅在内部留存。
- 结果(列容忍口径，按题重抽样的 95% 区间)：

  | 条件 | 正确率 |
  |---|---|
  | 不用本体 | 28.8 [25.6, 32.1] |
  | 改动前的 DataMind 本体(dm) | 25.7 [22.2, 29.2] |
  | 实验分支冻结代码(dm93) | 36.5 [32.7, 40.3] |
  | **本仓库移植版(dmP)** | **37.2 [33.2, 41.2]** |
  | EvoOntology 本体 | 44.2 [40.1, 48.5] |

  - dmP − dm：+11.5 [+7.9, +15.0]；严格口径 +9.9 [+6.7, +13.2]。
  - dmP − dm93：+0.7 [−2.9, +4.2]，区间含 0，移植版与实验结果一致。
  - dmP − 不用本体：+8.3 [+4.7, +12.0]。
  - dmP − EvoOntology：−7.1 [−10.8, −3.5]。在名称不透明的库上，DataMind 本体仍不如 EvoOntology 本体。
- 第一次重测（按起名结果决定是否使用画像）只完成构建，效果未经测试题验证。

## 没有做的

- 已发出的模型请求不能中止，最多再等一次单次超时。
- 构建产物重建后，修改前的版本无法复原，只能做普通回放。
- 配对回放让模型调用翻倍；单题每边只问 1–3 次，单题结论只作参考，判断要看批量回放的区间。
- 对比基准只测了不透明合并库一种设置；可读名称的库、工业库上没有重测移植版。
- 「与反馈时的答案一致」是比对标准。「待改进」的答案不再复现，不等于现在的答案正确，仍需人确认。
