# DR-101 · 构建作业由服务端持有，连接只是订阅者

状态：已实现。日期：2026-11-13。
关联：BUILD-JOB-01、BUILD-JOB-02、DR-056、DR-058；来源为 2026-11-12 代码审查与 ATH 接入复查。

## 问题

构建在 `/api/build/inquire` 流式响应的生成器里执行，生成器由连接驱动：

- 浏览器关闭、代理超时或网络抖动，生成器被关闭，构建中断；临时文件和子进程可能留下。
- MCP 构建服务器把作业放在自己进程的后台线程里，靠消费这条流推进。宿主结束 MCP 进程
  （每个请求起一个进程的桥接层就是这样），构建随之中断，作业号在下一个进程里查不到。
  经 ATH 适配层发起的构建因此无法完成。
- 语义复核、交叉复核等步骤耗时几分钟且期间没有事件；前端 120 秒收不到事件就断开，断开又导致构建中断。

## 决定

- 构建在服务端后台线程里执行，过程事件追加到作业记录。线程带着请求的上下文变量运行（数据来源等）。
- `/api/build/inquire` 的行为对调用方不变，仍是事件流；它现在订阅作业，响应头 `X-Build-Job` 给出作业号。连接断开不影响构建。
- 新增 `POST /api/build/jobs`（请求体与 inquire 相同，立即返回 202 与作业号）
  和 `GET /api/build/jobs/<id>`（状态、第 `after` 条之后的事件、结束时的 done 事件；`wait` 为长轮询秒数，上限 25）。
- 订阅者在没有新事件时每 15 秒收到一条 `tick`。
- 流没有以 done 或 error 结束、或执行中抛异常时，作业以 error 结束并补一条 error 事件：半程不算完成（DR-056）。
- MCP 的 `start_build` 改为向服务端提交作业，`get_build`、`wait_build` 改为查询服务端；MCP 进程不再保存作业。

## 边界

- 作业记录在服务进程内存里，最多保留 40 个；服务重启或 worker 回收后作业不可查，正在执行的构建会中断。
  已经写入的图谱文件不受影响。持久化作业与重启后续跑没有做。
- 没有取消构建的接口。
- 前端仍只在页面打开期间显示进度；刷新页面后凭作业号续看还没有接到界面上。
- 作业接口与其他接口一样没有登录认证；经 ATH 访问时由适配层按授权范围放行。
