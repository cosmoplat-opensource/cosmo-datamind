# DR-102 · ATH 适配层进入产品仓库

状态：已实现。日期：2026-11-13。
关联：ATH-01、DR-058、DR-097、DR-101、DR-006。

## 背景

DataMind 没有登录认证，只监听本机（SECURITY.md）。让外部智能体访问它，需要一层认证和授权。
此前按 ATH（智能体可信握手协议）网关模式写了一个适配层：授权服务器加资源服务器，放在 DataMind 前面，
按范围放行目录、本体、SPARQL、构建工具（MCP）和 A2A 技能。它放在实验目录里，不随产品发布，也不在产品的测试里。

## 决定

- 适配层作为可选模块放在 `ath_adapter/`：`provider.py` 为服务，`e2e/` 为端到端脚本与客户端。
  包名不用 `ath`，避免与官方 SDK 的包名冲突。
- 状态目录缺省为 `workdir/ath_state`，已加入忽略规则；组织名、项目地址改为环境变量，代码里不写具体单位名称。
- MCP 服务器路径缺省取本仓库的 `mcp_build_server.py`。
- 适配层的 7 个单元测试并入 `tests/unit`，计入覆盖率；端到端脚本需要外部网关，不进常规检查。
- 开放范围不变。评审与编辑、删除、引擎与连接配置不开放。

## 没有做的

- 数据来源随令牌限定、深度问数的范围、适配层审计与编辑记录打通，留待后续。
- 没有改 DataMind 自身的认证方式；直接访问 8092 的调用方仍不经过授权。
- 端到端的 31 项检查没有在本次改动后重跑。
