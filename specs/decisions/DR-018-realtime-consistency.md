# DR-018 跨环节实时一致性:所有读方统一走「含编辑回放的 IR」

日期:2026-07-26 · 状态:已实现 · 回归:test_all.py 186/186(新增 U 分区 18 断言)

## 背景 / 问题

用户要求验证"一个环节的变动能否被其他环节实时看到"。代码审计发现读方分裂:图谱/评审/诊断/本体对话/SPARQL/完备度走 `load_ir_edited`(含编辑回放),但 **深度问数 build_context、总览 KPI、指标中心×3、表详情、/api/graphs 列表(3 处循环)走原始 IR/原始文件** —— 后果:人审否决一条关系后,图谱已剔除,**问数的 JOIN 提示仍在引用被否决的关系**;列表计数与图谱页不一致;编辑对指标/总览不可见。"共享语义中枢"名不副实。

## 决定

1. **单一读取路径**:全部读方(示例 7 处、app 2 处、graphs 列表 3 处)统一改为 `load_ir_edited` —— 草案层(基线 IR + 编辑日志回放)是唯一的当前真相;性能代价为每次调用深拷贝+回放(212KB 级,PoC 可接受,图谱端点本就如此)。
2. **口径对齐**:总览 KPI 的关系数排除 `rejected`,与图谱渲染同口径。
3. OWL/Turtle 无需另改:`_ir_to_turtle` 经 `ir_to_graph` 生成,已随 DR-013 的 rejected 过滤;SPARQL 每次现做现转,编辑即时可见。

## 回归锁定(U 分区,写→四方读→撤销→四方复原)

以「否决 fact_delivery→fact_sales_order」为探针:①图谱剔除 ②总览-1 ③**问数 JOIN 提示剔除** ④SPARQL 三元组消失(关系在 OWL 中具体化为 rel_* 资源,探针用 rdfs:domain/range)⑤评审页显示已否决 ⑥列表计数=图谱页;改动词→⑦图谱边 ⑧详情卡即时更新;撤销→全部复原;⑨构建产物删对象→列表计数即时变化并可复原。

## 增补(同日):人审 ↔ 本体图谱 页面级实时反映

- **发现 UI 层真 bug**:页面初始化被 `loaded[p]` 一次性守卫——评审页人审后**切回图谱页不重取数据**,看到旧图(API 层一致、页面层滞后)。修法:`goPage` 对易变页(graph/review/actioncenter/ontquality)**重访即重取**(revisit 时 drawGraph/rvLoad/acLogLoad/ontQualityRender;首访仍走 load 防双初始化)。
- 样式即语义:通过(candidate→asserted)= 橙长虚[4,3]→蓝短虚[2,2];否决=整条剔除;确认对象=候选标记消失——人审结果在图上**肉眼可辨**。
- 验证:Playwright 人工路径 7/7(采样 candidate 边→评审页精确通过/确认对象→**切回图谱不刷新即见** asserted/候选消失;否决→切回即消失;边卡直审→当场重绘;撤销×4→切回全复原);U 分区补 4 条 API 断言(⑩通过→边 status/human_review 即变、⑪确认→节点 candidate 即变、撤销复原)。套件 **190/190**。

## 教训

- "各自 load 一份"是一致性 bug 的温床:**读方必须只有一个入口**;新端点一律 `load_ir_edited`。
- 一致性测试的正确形状:一次写 → 断言**每个**读面 → 撤销 → 再断言每个读面复原;只测写方自身等于没测。
