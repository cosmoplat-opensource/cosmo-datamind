# DR-141 · 统一本体资产、版本与领域权威载荷

## 上下文 / Context

DataMind 当前主要通过 JSON IR 与编辑覆盖层管理数据本体，并没有现成的跨领域不可变发布体系。
upstream 使用 RDF/OWL 表达技能、实现、调用实例、端口契约、参数及黑板数据流。
DataMind 当前 OWL 出口把节点表达为类、边表达为属性定义，不能据此恢复机器人实例断言与完整 RDF 语义。
前版 Graph v2 唯一真相源提议缺少无损映射证明，直接落地会扩大迁移范围并丢失已有语义。
两个工程需要统一平台治理，同时避免同一版本存在两份可独立修改的权威数据。

## 决定 / Decision

1. **统一资产封套**：本体目录统一登记资产 ID、版本、领域、载荷类型、父版本、来源摘要、构建配方、profile、协议和校验报告。
2. **每版本单一权威载荷**：数据领域保留 JSON IR，机器人领域保留完整 RDF/OWL，二者通过类型化适配器参与平台治理。
3. **展示投影只读**：机器人 nodes/edges 仅用于显示，领域编辑操作作用于 RDF 草稿，再生成新版本与投影。
4. **发布版本不可变**：调用方固定版本和载荷摘要，编辑、重建及外部 OWL 导入产生新候选，不覆盖已有版本。
5. **保留语义身份**：实体由资产、版本及 IRI 共同限定，保留类/实例、数据类型、语言标签、空白节点、列表、调用次序和数据流作用域。
6. **显式跨域关联**：业务数据对象与机器人实体通过带证据和审核状态的关联连接，同名不自动产生等价关系或适配结论。
7. **渐进兼容**：现有 IR 读取、编辑及问数保持兼容，机器人资产只由声明支持相应契约的应用消费。
8. **延后通用表示替换**：只有通过 RDF 语义往返与领域行为对照后，才另行决定是否统一底层图表示。
9. **术语与表示分层**：IR 是现有中间表示结构，JSON 是其保存格式；RDF 是图数据模型，OWL 表达本体语义，机器人版本可序列化为 OWL 文件。
10. **领域扩展覆盖完整结构**：除工位、载具、槽位、零件与设备外，还需保留原子技能、复合技能、实现、调用实例、端口、绑定、条件和数据作用域，不能只扩充显示词表。

## 后果 / Consequences

- 正面影响：本体构建、评审、应用与产物可以共享一个平台生命周期，机器人语义无需在集成前重新发明。
- 正面影响：可避免把图谱显示 JSON、交换 OWL 和权威数据作为三个独立编辑源。
- 代价：平台需要维护载荷适配与领域专用校验，现有数据本体也需要逐步登记版本。
- 代价：跨领域查询和编辑必须明确能力边界，无法只靠一个通用 nodes/edges API 完成全部操作。
- 影响的文件/路由：新本体资产模块、领域适配器、版本存储、图谱目录与详情、现有 IR 兼容入口。
