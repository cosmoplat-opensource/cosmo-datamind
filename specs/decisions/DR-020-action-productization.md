# DR-020 动作层产品化(类型管理 CRUD + 行业动作种子 + 问数→动作闭环 + 审计筛选导出)

日期:2026-07-26 · 状态:已实现 · 回归:test_all.py 226/226(W 节 +14)+ 功能直测 15/15 + UI 冒烟 9/9

## 背景 / 问题

DR-015 的动作层是"只读注册表":4 个种子写死在 json,没有管理面 —— Palantir ActionType 的核心是**类型即治理对象**(谁定义、参数是什么、什么风险级、能否停用),缺管理面就只是演示道具。且动作与问数没有闭环:分析看完了,"下一步做什么"断在页面之外。

## 决定

1. **类型管理 CRUD**(`/api/action/type` · `/update` · `/delete`):
   - 自建类型:名称/绑定业务表(须在数据目录中)/风险级(**缺省 high,从严**)/参数 schema(≤12 个,name 强制 snake_case,select 须给 options,`_valid_at_params` 统一校验)/效果说明;创建人必填入登记(created_by/created_ts)。
   - **内置种子受保护**:仅允许 停用/启用 与改说明,改语义(风险级/参数/绑定表)与删除一律 400 —— 种子语义是演示与文档的锚,不可被误改。
   - 停用即刻生效:`invoke` 对 `enabled:false` 返回 400;历史审计永远保留(删类型不删日志,日志存 action_cn 快照)。
2. **3 个行业动作种子**(均绑定真实库表,高风险须审批):
   - `freeze_batch` 冻结生产批次(质量隔离)← fact_production_order(batch_no 真实存在)
   - `adjust_temp_zone` 产线温区参数调整 ← dim_production_line
   - `supplier_scar` 发起供应商纠正措施(SCAR,8D)← dim_supplier
   共 7 类:质量 2 / 生产工艺 1 / 交付 1 / 设备 1 / 供应链 1 / 财务 1。
3. **问数→动作闭环**:答案卡渲染后异步匹配「结果 SQL 命中的表 × 动作类型 object_table」,给出「相关动作」直达发起按钮(≤4 个,标注「须审批」)——分析到行动一步直达;动作弹窗全局可用,任意页面可发起。
4. **动作中心 UI 产品化**:KPI 四卡(启用类型/待审批/已执行/已驳回,`/api/actions` 增 denied 计数)、新建/编辑弹窗(参数行编辑器)、卡片 停用态/自建标记、审计日志 状态筛选+关键词搜索+**CSV 导出**(BOM 头,Excel 直开)。
5. **业务助手角色补挂**:生产主管 +温区调参、质量工程师 +冻结批次/SCAR。
6. **MCP 零改动继承**:list_actions 读同一注册表,新种子/自建类型自动对外(实测 MCP 输出含 freeze_batch/supplier_scar);invoke 的停用拦截在服务端单点生效,MCP 侧自动继承。

## 不变量

- 决策捕获纪律不变:动作只登记不写只读源库;审批语义只在服务端(MCP 不暴露 approve)。
- 审计不可失:删类型/停用不影响既有日志;日志含操作人/审批人/意见/时间/效果全要素,可导出。
- 风险缺省从严:未指定风险级按 high 处理。

## 验证(实测)

- 功能直测 15/15:7 类型;新种子缺参 400/全参 pending/驳回留痕;自建 创建→低风险直执行→停用→发起 400→删除;内置改语义/删除均 400;MCP list_actions 含新种子;清场后无 pending 残留。

## 教训

- 注册表要当"治理对象"而非配置文件:一旦有 UI 可写,校验(name 规范/表存在/select 选项)与保护(内置只读语义)必须同时落地,否则第一天就会被写脏。
- 测试脚本自身的清场也要断言(「无 pending 残留」「无自建残留」)——上一轮崩溃脚本留下的孤儿类型让回归误报,查了一轮才发现是测试残留不是产品缺陷。
- 原生 `confirm()` 又被写进了新代码(删除自建类型),复查才抓到 —— DR-013 的教训(原生对话框可被浏览器静默拦截)要靠检查清单落地,不能靠记忆;已改页面内两次点击确认。
