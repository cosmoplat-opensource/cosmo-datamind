# DR-022 技能生态五项(对比实验/注入痕迹/产物沉淀/败题修复/存而不用审计)

日期:2026-07-27 · 状态:已实现 · 回归:test_all.py 249/249(Y 节 +13,含增补的分层对账 2 条)

## 背景

DR-021 把技能从死代码变成真输入后,顺势补齐技能的"证据链":有没有用要能测出来(①)、用了要看得见(②)、
好的产物要能沉淀回技能(③);同时清偿两笔旧账:评测败题(④)与全站"存而不用"清查(⑤)。

## 决定

**① 技能对比实验**(`/api/build/skill_compare`·`/status`·`/results` + 构建页「技能对比实验」弹窗):
同一建模目标 × 两组技能,各跑一次**真实构建**(LLM 抽取+反幻觉裁决;抽取失败如实记失败,**不用兜底数据冒充**),
对比 对象数/关系数/verified/动词分布/类型分布/定义覆盖率;两组产物保留在「已构建本体」可进图谱细看,每组落盘。
后台单线程顺序跑(防 CLI 争抢),运行中再次发起返回 409。

**② 技能注入痕迹**:构建流水线新增 `skill_inject` 步——「技能注入 · N 段方法论并入抽取 prompt(共 X 字)」,
选中技能内容为空时如实标注。技能生效自此在执行记录里肉眼可见。

**③ 产物沉淀为技能**(`/api/build/skill/from_graph` + 已构建本体卡「沉淀为技能」):
从图谱**确定性提取**(不经 LLM)动词表(top8+频次)/类型分布/定义风格样例(属+种差)→ 生成自定义技能 md,
命名 `from-<key>`;沉淀物可编辑、可编排、正文注入下次构建——「构建→复盘→技能」闭环,与问数侧「沉淀为 Skill」对称。

**④ 评测败题修复**(通用改进,不对题开小灶):
- Q7 类(跨两跳聚合):`_join_hints` 增**两跳路径召回**——选中表间无直连但经一张中间表可达时,给出完整
  `⋈⋈ A.k1=M.k2 ∧ M.k3=B.k4(经中间表 M)` 链(≤3 条);口径校验天然放行(两跳各是真实关系键)。
- Q8 类(均值分母):两个出 SQL 的 prompt 增加口径要求——「月均/日均」分母用 `count(DISTINCT 期间)`
  不得除以固定常数;「最…的」单值问题 JOIN 后聚合再 `ORDER BY … LIMIT 1`;⋈⋈ 须完整沿链 JOIN 中间表。
- 三组同 prompt(只有上下文不同),实验对照公平性不受影响。

**⑤ 存而不用审计**(`specs/audit-input-consumers.md`):12 个输入面逐一登记消费方;
清查出的第 3 起真死代码——**问数沉淀技能(qa_skills)只展示不复用**——当场接上:
`_match_qa_skill`(归一化等值/互含匹配)命中即复用其已验证 SQL、跳过引擎规划(`skill_reuse` 步,秒级响应),
stream 与非 stream 两链同语义。历史 3 起死代码(术语词典/技能正文/沉淀技能)共性入档:先建输入面、后忘消费方。

## 不变量

- 对比实验不美化:组失败如实展示,不回退 quick_build 充数(对比的意义在于同条件真实差异)。
- 沉淀技能是确定性提取物,不经 LLM 生成(来源可审计:图谱统计+样例摘录)。
- 修复④是通用机制(路径召回/口径规范),不是给金标题定制答案。

## 验证(实测)

- 功能直测 6/6 + 快测 8/8(两跳链/复用命中与不误命中/沉淀三件套/注入含最新编辑/对比端点校验);
- test_all.py 249/249(Y 节 13 条:11 条主体 + 增补 Y12/Y13 分层对账;Y6 为真实问数走 skill_reuse 步);
- 对比实验与评测重跑实数见下方增补。

## 增补(同日):对比实验实数 与 评测揪出的数据质量缺陷

**① 对比实验首轮实跑**(同目标「构建可审计的制造企业本体」,A=ontology-agentic,B=A+verb-discipline 规范技能):

| 指标 | A 组 | B 组(+规范技能) |
|---|---|---|
| 对象 / 关系 | 85 / 98 | 19 / 24(规范「宁少勿滥」生效) |
| verified 率 | 72/98=73% | 21/24=**87.5%** |
| 动词 | 归属7、下达给2、发生于2、对应2、核销2、部署于1…(自由) | **全部落在白名单**:归属12、产生5、驱动3、监测1 |
| 事件占比 | 20/85=24% | 10/19=**53%**(规范「过程性判 event」生效) |
| 定义覆盖 | 100% | 100% |

技能有效性从宣称变实测:规范技能的 4 条要求在产物上全部可见。

**④ 评测复盘(诚实记录)**:prompt 口径规范已生效(Q8 复跑中模型分母确实用了 `count(DISTINCT month)`),
但 Q7/Q8 仍错——数值对账后确认根因是**合成数据分层不一致**:DWS_PRODUCTION_DAILY 与事实链产量合计差 17.4%
(TOP1 产线都不同),agg_metric_monthly 与 fact_sales_order 的 2025 销售额差 10.9%。模型选汇总层作答并无过错,
口径不明的问题在不一致数据上没有唯一正确答案。处置:
- 数据质量页新增**分层对账**检查(汇总层 vs 事实层合计,差异>5% 报警)——评测发现固化为产品能力;
- qa_set 升 **v2**:Q7/Q8 问题句明确口径(「按生产产出明细」「以销售订单明细为准」),变更理由入题集 note;
- 终跑结果见下方补记。**评测的价值在此显形:它揪出的是数据的病,不是模型的病。**

**终跑补记**(qa_set v2 + 路径召回 + 口径规范,同模型 claude-haiku):
**C 组 8/8 正确 · 8/8 出处引用**(A 3/8·1/8,B 2/8·1/8 不变)。Q7 的 SQL 完整沿两跳链
`fact_production_output ⋈ fact_production_order ⋈ dim_production_line`,Q8 分母为 `COUNT(DISTINCT 月)`——
两项通用修复在真实生成中生效。三轮走势:6/8(首跑)→ 6/8(修复后仍败,诊断出数据层病因)→ **8/8**(口径入题+对账入质检)。
