# DR-146 · 持久化运行、会话隔离与工件追溯

- **状态 / Status**: accepted（2026-11-18 由仓库维护者确认：代码已于 2026-11-17 经 PR #1 合入 master，合入后的审查与修复见 DR-159）
- **日期 / Date**: 2026-11-02
- **关联 / Refs**: [[DR-044-json-store-abstraction]]、[[DR-056-evidence-integrity-and-isolated-validation]]、[[DR-141-unified-domain-semantic-graph]]、[[DR-144-behavior-tree-compilation-as-ontology-application]]

## 上下文 / Context

DataMind 当前 JOBS 与源项目的会话都主要依赖进程内状态，无法作为完整的跨重启运行历史。
DataMind 已有对话持久化：本体对话保存在服务端 ont_chats.json，构建对话历史保存在浏览器 localStorage。
已有消息历史应复用，新增需求是将固定输入版本、任务状态、验证过程与产物可靠关联，而不是重建一套聊天系统。
AgentService 当前使用一个 RLock 包围整次任务处理，包括模型调用，会串行化不同用户会话。
本体版本、模型配置、证据、编译器与产物必须形成稳定关联，不能只用文件名或当前工作目录推断来源。
新版本发布与旧证据失效是不同事件，不应把所有历史产物一律标记失效。

## 决定 / Decision

1. **元数据事务化**：建议以工作目录内 SQLite 保存新增本体版本、资产索引、运行、事件及会话关联，复用平台路径限定和原子写入；现有聊天存储无需立即全量迁移，存储实现须满足可靠关联与恢复要求。
2. **工件发布有序**：先写工件并核验摘要，再事务提交可见索引和终态，避免出现成功记录却缺少工件。
3. **有界后台执行**：新构建和生成任务由有界队列承接，各阶段有超时，首版维持本地部署，不引入分布式队列。
4. **会话隔离**：采用每会话串行化或乐观版本检查，防止同会话交错写入，同时不把不同会话的模型调用锁在一起；RDF/SPARQL 校验保留专用共享锁或进程隔离。
5. **重启语义明确**：运行历史可恢复，遗留 running 标记 interrupted，重试创建关联原运行的新记录，不假定外部调用已恢复或未发生。
6. **事件可重放**：持久化事件携带递增序号，SSE 按游标续读，轮询读取同一状态源。
7. **manifest 完整**：每份候选记录本体版本与字节摘要、来源、profile、编译器、规则摘要、任务、参数/证据引用、非敏感模型配置和工件摘要。
8. **新鲜度单独表达**：新版本出现不改写旧报告，证据到期、撤销或快照损坏产生需复核状态，原始事实与历史产物仍保留。
9. **下载受目录登记约束**：客户端使用工件 ID，服务端从对应运行清单解析受控路径及媒体类型，不接受任意文件路径。
10. **旧接口渐进兼容**：现有 JOBS 和 /api/jobs 保持行为，新运行在作业 UI 中合并显示，后续统一另行评估。
11. **会话与运行一对多**：复用会话身份和消息历史，一段对话可关联多次解析、澄清或生成运行；单次运行固定任务输入、本体版本、状态、验证结果及产物引用。
12. **manifest 是产物来源清单**：以 JSON 保存并可随候选下载，连接生成依据与输出文件，不是对话文本、领域插件声明或校验报告本身。

## 后果 / Consequences

- 正面影响：刷新、重启和多轮澄清不会破坏版本追溯，不同会话可独立推进。
- 正面影响：运行状态、事件与工件来自同一持久化记录，便于重试和审计。
- 代价：需要处理数据库迁移、事务边界、孤立临时工件清理及存储保留策略。
- 代价：第一版不自动续跑中断任务，也不因新增持久化就直接切换多 worker 部署。
- 影响的文件/路由：ontology_assets、domain_runs、会话服务、SSE、工件下载、作业 UI 与启动恢复逻辑。
