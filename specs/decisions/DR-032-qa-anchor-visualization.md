# DR-032 · 深度问数的本体锚定可视化

- **状态 / Status**: accepted
- **日期 / Date**: 2026-08-02
- **关联 / Refs**: [[DR-026-double-blind-intent]](实际命中来源)、[[DR-027-business-aliases]](别名参与召回)、[[DR-022-two-hop-join-path]](两跳链)

## 背景 / Context

深度问数选了本体图谱之后,本体到底起了什么作用,对用户是**黑箱**。
执行记录里只有一行「匹配相关表/指标 · 命中 14 张表」——哪 14 张、凭什么选中、
JOIN 用的是本体的哪条关系,全都看不到。

这正好是本体最该被看见的地方:问数的可信度就建立在"表和 JOIN 键都来自本体"上,
而这个链条此前只有系统自己知道。人只能看到一个答案,无从判断它是不是锚对了地方。

## 决定 / Decision

在对话气泡内画出**这一次问数的锚定子图**,与执行记录并列:

- **方框 = 被锚定的本体对象**,填色区分入选理由:
  关键词命中 · 核心事实表 · 沿本体关系召回 · 数据源限定 · 无命中默认候选
- **连线 = 被写进上下文、作 JOIN 依据的本体关系**:
  绿实线 verified · 橙实线 asserted · 灰虚线 两跳可达
- **✓ 与实线加粗 = 最终 SQL 真正用到的对象**,其余淡出
- 下方:图例、JOIN 键清单(可折叠)、命中指标、以及"N 个召回对象未被 SQL 用到"

时序上分两次呈现:`build_context` 一完成就先推一版(引擎规划要几十秒,
这期间人已经能看锚定),SQL 执行后回填「实际命中」。

## 为什么这样做 / Rationale

- **与上下文同源,不另起一套推导**。结构化边由 `_join_hints(..., pairs=)` 在生成
  提示行的同一趟里收集;对象由 `build_context(..., trace=)` 在挑表的同一趟里记录。
  另写一段代码重新推导一遍"应该锚定什么",**可视化会与真正喂给引擎的内容悄悄漂移**,
  那时它就从证据变成了装饰。断言 AN4 直接锁死"结构化边数 == ⋈ 提示行数"。
- **"实际命中"复用双盲检测的通道 B**([[DR-026]]),不新埋点。
  它本就在解析 SQL 里的表,顺手回填即可。
- **召回与使用要能对照**。只画召回会让人以为这些表都被用了;
  标出 SQL 真正落到哪几张,才看得出**召回是宽是准**。
- **静态 SVG,不用 G6**。图谱页用 G6 是要交互;这里每轮对话一张图、会话可回放 30 轮,
  用图引擎意味着 30 个实例的生命周期管理。SVG 无实例、可随会话存进 localStorage、回放即得。
- **锚定随 `done` 落一份**,不只做实时事件——否则命中问数缓存或翻历史对话时图就没了。

## 影响 / Consequences

- 本体在问数里的作用第一次是**可见且可核对**的:选中的表、JOIN 的键、
  关系的状态,都能与本体页对上。
- 实测「最近一个月各产线产量趋势」:锚定 14 个对象、9 条关系(7 verified + 2 两跳),
  **SQL 最终只用了 1 个** —— 召回宽出一个数量级,这在此前的执行记录里完全看不出来。

## 代价与边界 / Trade-offs

- 图内**最多画 16 个对象**,超出时显式标注"图中只画了前 16 个(共 N 个)——
  其余对象同样在上下文里,未省略喂给引擎"。选中 `demo` 图谱作数据源时会锚定全部
  108 个对象,画全既不可读也无意义;但截断必须说出来,否则读图的人会以为召回就这么多。
- 两跳关系的**中间表不在图上**(它未必进上下文),只出现在连线悬停与 JOIN 清单里。
- 范围标签取「限定是否**真的生效**」而非「是否选了图谱」:选中图谱的绑定表若在本体里
  一张都没匹配上,召回其实回落成了全库,此时标成"数据源限定"是谎报范围已收窄。
  实测 `cq` 图谱正是这种情况(5 张表,0 匹配),UI 如实显示"已回退全库召回"。

## 一处测试自伤

加完后 UI 实操的「执行记录含双盲意图步骤」转红。原因不是功能坏了,是**测试的等待条件
被我的改动提前满足**:它以 `innerText.length>900` 兜底,而锚定区块一渲染就撑过了阈值,
页面在引擎真正执行前就被抓取。改为等确定性的终局信号(执行到 SQL / 明确失败)后恢复。

教训:**以文本长度作完成信号是脆的** —— 任何往页面里加内容的改动都会让它提前触发,
且失败现象会指向一个与真因无关的功能点。
