# DR-070 · 机器人本体统一入口与模型／离线双路径

- **状态 / Status**：accepted（2026-11-10 用户确认方案无问题并要求继续下一步）。
- **日期 / Date**：2026-11-09。
- **关联 / Refs**：[IR-024](../iterations/IR-024-robotics-dual-build.md)、[DR-060](DR-060-robotics-source-recipes-and-reverse-build.md)、[DR-064](DR-064-persistent-build-runs-and-artifact-manifests.md)、[DR-067](DR-067-offline-candidates-and-readable-versions.md)、[DR-069](DR-069-robotics-task-application.md)。

## 上下文 / Context

用户确定本轮必须上传 XML，有 LLM 时采用新 TBox/ABox 方案，无 LLM 时保留原离线构建方案。
2026-11-09 完成方案，2026-11-10 获用户确认后进入 IR-024 的契约冻结与 TDD。
范围不包含无 XML 建模或人工录入替代 XML。
数据本体已在同一构建入口优先调用模型、失败后回退 quick_build，但机器人新旧方案的建模语义不同，不能直接复制失败回退策略。
当前机器人构建接受行为树和节点模型两个来源角色，以固定 ur_pick_place 模板构建符合既有消费者契约的 RDF/OWL。
新 TBox 工程根据 XML、用户需求及受控词表设计类别、关系和属性，ABox 工程按 XML 规则提取实例，模型只参与后者的交互而不生成实例事实。
新方案导出的 RDF/XML 可以作为本体候选存储，却不自动满足现有 ur-pick-place-owl-v2 消费契约。
如果只拼接页面或替换构建函数，会出现版本不可恢复、模型错误被误判为离线成功、设计本体无法打开或被错误送入行为树应用等问题。

### 方案比较

| 方案 | 收益 | 代价与结论 |
|---|---|---|
| 统一入口，按模型状态选择新旧领域构建器 | 沿用用户习惯，保留离线能力，统一资产与版本 | 本轮采用方向；需增加设计会话及候选校验契约 |
| 嵌入两个独立智能体网页和服务 | 快速展示上游功能 | 双配置、双会话、版本割裂，不符合统一平台目标 |
| 完全替换旧构建器 | 单一构建链 | 无模型时能力丢失，违背已定范围 |
| 有模型失败后静默使用旧构建器 | 可能仍有输出 | 不能证明自然语言要求得到执行，不采用 |

## 决定 / Decision

### 用户已确定的范围

1. 机器人构建继续位于现有“本体构建”的机器人配方中，模型与离线方式共用入口。
2. 必须提供 XML，首版沿用行为树 XML 与节点模型 XML 两个来源角色。
3. 有可用 LLM 时使用新方案，无可用 LLM 时使用现有离线构建方案。
4. 本轮不包含纯自然语言、无 XML 的构建，也不增加替代 XML 的填写向导。

### 已确认的技术细则

以下细则随本方案于 2026-11-10 获用户确认。
具体接口和配置判定冻结于 [构建契约 v1](../contracts/robotics-dual-build-v1.md)，实现不得绕过下面的语义边界。

5. UI 不提供模型／离线模式选择器，由后端决定并显示实际构建方式。
自然语言建模要求在模型路径中作为输入，在离线路径中明确显示不参与语义建模，不宣称旧方案理解了文本要求。
旧请求不提供文本时，模型路径进入“补充建模要求”状态，不自行编造用途，也不切回旧方案。

6. “有模型”依据平台运行时注册、有效配置及本构建适配能力判定，不以一次网络探测成功为前提。
复用平台配置、环境变量优先级及运行时选择顺序，不引入 TBOX_LLM_*、ABOX_LLM_* 或第二套密钥设置。
存在多个可支持的运行时时，按平台当前优先顺序选定一个并固定到会话。
未配置且无可用运行时才选择离线；部分配置、显式配置错误、注册的运行时不受支持或残留失效注册应返回可解释的配置问题。
运行时注册表与实际配置需交叉检查，不能仅看 current_ready 标签或某个旧实例是否还在缓存中。

7. 会话固定构建方式、来源快照、词表及模型身份；每轮保存非敏感配置标识、提示词版本及输入摘要。
已有模型会话在模型断开、配置被移除或身份改变后不得转成离线会话或偷偷换模型。
恢复兼容配置后可显式重试；要采用新方式或新模型须重新发起构建，旧结果保留。
密钥不进入会话、版本、导出、模型提示词及调用日志。

8. 模型路径采用“类别设计 → 确认类别 → 关系与属性设计 → 确认骨架并构建实例”的阶段。
固定类别的确认由结构化操作表达，消息中出现“确认”不能越过阶段校验。
返回类别修改会撤销当前确认并使下游草稿过期，历史版本保持不变。
LLM 仅提出结构化 TBox 候选；术语、类别层次、引用、来源、域／值域和数据类型由本地程序验证。
不把属性关联建议误写为 OWL 定义域，不把并集误写为多个交集式定义域，不把属性声明当成实例属性值。
词表外概念进入待明确项，首版不增加在线词表编辑功能。

9. ABox 使用已确认 TBox 和原 XML 的确定性抽取，不让模型生成或修改实例事实。
抽取采用新工程已支持的 XML 子集，不能宣传支持任意控制结构。
抽取缺失术语、遗漏信息和未映射项须生成报告，部分覆盖不称为完整抽取。
资料中的指令只作为来源内容，不得改变服务端阶段、词表约束或执行权限。

10. 离线路径继续调用原 ur_pick_place 构建、发布封装与消费复验，不改用数据本体的 quick_build。
保持其输入限制、语义输出、失败报告及已有行为树应用能力。
没有模型时仍只支持旧模板范围，不因页面增加模型能力就放宽旧算法约束。

11. 复用现有资产目录、不可变版本、来源登记及 domain.sqlite3，按新契约增加设计会话和每轮运行记录。
阶段 JSON 是设计修订的权威快照，OWL 是该修订的确定性导出。
完成 ABox 后，资产版本的 RDF/OWL 是权威载荷，阶段 JSON 只作为不可变来源工件，不能双向独立编辑。
下一轮修改形成新修订和新资产版本，不能覆盖历史快照。
2026-11-10 用户补充明确：每个设计／构建结果必须有一份完整 JSON，不要求与来源工程逐字段同构，不将业务内容拆为多个 JSON 分开保存。
总 JSON 内嵌当前 TBox、已生成的 ABox、来源证据、词表、建模消息、确认记录、覆盖与校验报告，以及非敏感版本／模型追溯信息。
每个成功结果将这份完整 JSON 固定保存并支持直接下载，不仅在下载时临时拼接多个业务 JSON。
OWL 保留为同一结果的语义导出；底层运行 manifest 仍仅用于工件登记，不承载总 JSON 缺失的业务内容。


12. 新增“设计候选”契约，与现有“UR 应用候选”契约分开验证。
设计候选通过本地语义与来源校验后可登记、浏览和导出；TBox 设计修订在会话内可查看和导出。
保存、打开和导出设计候选不要求先通过 UR 发布器，也不伪造 artifactContract。
行为树入口及后端继续使用既有消费契约，新候选不兼容时展示原因并阻止进入生成。
不得通过自动重跑旧构建器、补固定标记或丢弃模型设计来声称新候选兼容。
首版不承诺把任意新设计的本体自动转换为可执行的 UR 本体。

13. 模型鉴权失败、超时、限流、格式或语义校验失败时保留上一有效修订，记录错误并允许重试，不静默回退离线。
每个用户操作最多允许一次 JSON 格式修正请求；语义错误不通过无限循环请求消除。
用户等待确认时不占后台执行槽位，模型网络等待不持有 SQLite 写事务或 RDF 全局锁。
请求幂等、修订号冲突、恢复中断和来源摘要检查与旧平台同等受控。

14. 数据本体构建的现有回退策略、机器人任务生成的离线候选策略、已有图谱和历史工件不在本轮修改范围。
“离线构建”与“不连接实机的离线候选生成”分别显示，避免把使用模型的任务解析称为无模型流程。

## 后果 / Consequences

用户只需选择机器人配方并上传 XML，不用理解两套服务或维护两套模型配置。
无模型环境保留现有确定性能力；有模型环境增加受词表约束的对话建模。
新增模型路径包含人工确认步骤，其交互时间不能套用旧的一次性构建超时。
资产存储可复用，但现有严格构建完成契约、实例编辑器和专用图谱视图不能直接承载通用设计草稿，需要显式扩展。
模型配置可用不代表服务一定成功，错误必须真实呈现。
合法设计候选可能暂不支持行为树生成，UI 和后端必须一致表达这项限制。
影响面包括机器人构建 UI/API、模型适配、设计状态机、TBox/ABox 核心、版本与运行契约、候选详情及应用准入。
实现和行为验收按 IR-024 分阶段执行，不把本记录当作功能已经完成的证明。
