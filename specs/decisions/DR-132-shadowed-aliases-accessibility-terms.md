# DR-132 · 同名别名不能绕过校验，界面可访问性，用语统一

状态：已实现。日期：2026-11-15。
关联：QA-GATE-ALIAS-01、QA-FANOUT-04、QA-STATUS-03、ANSWER-RECORD-05、UI-A11Y-01、UI-CHART-02；DR-098、DR-129、DR-130、DR-131。

## 背景

对 DR-131 的改动再做一轮独立复查，发现它引入或遗留了下面的问题。

1. **同名别名绕过校验（DR-131 引入）。** DR-131 把 `FROM (SELECT …) x` 的别名与 CTE 同等对待，不做连接键校验。
   别名取成一张真实的表名时（`… WHERE EXISTS (SELECT 1 FROM (SELECT 1) dim_customer)`），
   语句里对这张表的连接键校验和表白名单检查都被跳过。同类的旧问题还有三处：
   子查询里定义与真实表同名的 CTE；同一个别名在另一个查询块里指向 CTE，覆盖了它指向真实表的那次绑定；
   `FROM (a JOIN b …)` 里紧跟括号的表没有登记。
2. **重复计数检查放得过宽。** DR-131 规定聚合内容同时用到两张表的列时不拦。
   `SUM(CASE WHEN 子表.状态 = 'A' THEN 父表.额度 END)` 因此通过，而它的结果会按子表行数放大。
3. **UNION 各支、关联子查询仍被混在一起判断。** UNION 的两支共用一个查询块；
   关联子查询里引用外层别名的等式被当成关联。
4. **数值匹配的两条新规则过宽。** 列名出现在数字后面任何位置都算数；「从 800 到 1200」被当成区间。
5. **查询状态。** 明细查询命中的那一行某一列为空，被标成空结果；`createtime`、`updatedAt` 这类连写和驼峰写法的时间列认不出，
   `day_count`、`time_cost` 又被认成时间列；`2026.11.08`、`2026年11月`、14 位时间串不算日期。
6. **默认本体。** DR-131 只排除了内置示例本体。没有登记数据源的早期构建产物同样描述的是原来的库，
   换库后仍被当成当前库的本体。标准部署下，每个请求为了确定默认本体要读一遍全部图谱。
7. **界面。** 图谱列表请求失败一次后，缓存被空列表顶替，使用者选定的本体可能被清空；
   同一组、同一横轴取值有多行的明细在图表里只画出最后一行。
8. DR-131 记为未做的四项可访问性问题：弹窗没有对话框语义，部分可点击的元素不能用键盘操作，
   请求期间按钮不置灰，有一百多处小于 12 像素的字号。
9. 界面、服务端和测试里混用「底本」「构建体检」「沉淀为技能」「出厂正文」等内部说法；
   NOTICE 里的职务与对外材料不一致。

## 决定

- **同名的不豁免**。CTE 名和子查询别名与库里实际存在的表同名时，按真实的表处理，照常做白名单和连接键校验。
  别名已经指向真实表的，不被后面指向 CTE 的绑定覆盖。`FROM` 后紧跟括号的表也登记。
- **CASE 的条件不算被聚合的列**。判断聚合内容来自哪张表之前，先去掉 `WHEN … THEN` 之间的条件。
  `SUM(CASE WHEN 子表条件 THEN 父表列 END)` 拦下，`SUM(CASE WHEN 父表条件 THEN 子表列 END)` 放行。
- **查询块**。UNION / INTERSECT / EXCEPT 之后是另一个查询块。等式两边的别名都出现在本块的 FROM 里才算关联。
- **数值匹配**。列名要紧跟在数字后面，中间最多隔一个单位；句子里有「从 … 到 …」时不按区间处理。
- **查询状态**。只有汇总查询（有聚合函数且没有 GROUP BY）返回一行空值才算空结果。
  时间列按名字的最后一个词认，连写和驼峰写法以 date / time 结尾的也认，时长类（downtime、runtime 等）除外；
  日期取值的写法补上点分隔、年月汉字和 14 位时间串。每张表最多试两个候选列。
- **默认本体**。凡是没有登记数据源的本体，绑定的表一张都不在当前主库里时，都不算当前库的本体。
  内置示例本体是否适用的结论按文件指纹缓存，标准部署下不再逐个读图谱。
  主库没有任何适用的本体时，默认值仍是内置示例本体（保持原有行为，没有改成空）。
- **界面**。列表请求失败时保留原来的缓存。同一组、同一横轴取值有多行时不拆分序列。
  弹窗加上对话框语义：打开时焦点移入，Tab 在弹窗内循环，Esc 关闭，关闭后焦点回到原处。
  弹窗页签、关闭按钮、附件和看板的删除按钮、可点击的表格行、目录筛选标签可以用键盘操作；
  顶栏的状态徽标不再是按钮。写请求在途时，刚被点击的按钮置灰。最小字号统一为 12 像素。
- **用语**。「底本」改为「基础本体」，「构建体检」改为「构建前检查」，「沉淀为技能」改为「保存为技能」，
  「出厂正文」改为「默认内容」；界面上的「物化」改为「导入」。历史决策记录保持原文。
  NOTICE 中的职务改为「工业智能首席科学家」。

## 没有做的

- 校验仍是基于正则的近似分析，没有引入 SQL 解析器。`JOIN … USING`、`NATURAL JOIN` 之后对父表列求和不拦。
- 聚合内容同时用到两张表的值（数量 × 单价）不拦；`SUM(父表列 + 0 * 子表列)` 这类刻意构造的写法可以通过。
- 不带空格的 `1200-1500` 不识别为数字，两端都不核对。
- 文件上传控件仍是隐藏的 input，不能用键盘打开。输入框缺少关联的 label，状态只靠颜色区分的地方没有处理。
- 主库上没有适用的本体时，仍回退到内置示例本体，而不是提示「尚未构建本体」。
