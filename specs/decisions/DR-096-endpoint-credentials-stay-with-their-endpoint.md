# DR-096 · 已保存的端点凭据只发往已保存的端点

状态：已实现。日期：2026-11-13。
关联：ENG-CRED-01、DR-017、DR-006；来源为 2026-11-12 代码审查。

## 问题

引擎设置里的三处行为会把 API Key 交给不该拿到它的一方，或让配置与实际调用不一致：

1. 「测试连接」和「拉取模型列表」接受请求里给的端点地址，Key 留空时沿用已保存的 Key。
   请求方只要换一个地址，已保存的 Key 就会放在 `Authorization` 头里发往该地址。服务本身没有登录认证。
2. 应用配置时按「环境变量当前有值」判断是否由部署方注入。上一次应用配置写入的值也算有值，
   所以在界面上换服务商后，端点地址和模型名保持旧值，只有 Key 更新：新服务商的 Key 被发往旧服务商。
3. 端点或 Key 清空后，此前登记的 OpenAI 兼容驱动仍在运行时列表里，带着旧地址和旧 Key 继续被调用。

## 决定

- 请求未带 Key 时，只有端点为空或等于已保存端点（忽略末尾斜杠）才沿用已保存的 Key；
  其他端点必须同时给出它自己的 Key，否则返回 400，不发起任何出站请求。
- 「环境变量优先」只对进程启动时已存在的变量成立（`_ENV_LOCKED_AT_BOOT`）。
  界面保存的端点、模型、超时、回复上限随配置更新；Key 可由配置补位的原有行为不变。
- 驱动登记时若端点或 Key 不齐，撤掉已登记的 `openai` 驱动。
- 「测试连接」的超时限制在 1 到 300 秒，非数字按 60 秒处理（此前非数字返回 500，数值无上限）。

## 边界

- 没有对端点地址做内网或回环地址限制：本地自建模型服务（vLLM、Ollama）是受支持的用法。
- 服务仍无登录认证（见 SECURITY.md）；本决定只保证 Key 不随请求里的地址外发，不解决谁可以改配置的问题。
- 已有驱动实例在配置变更后由 `_apply_engine_cfg` 重新登记，本决定未改这一机制。
