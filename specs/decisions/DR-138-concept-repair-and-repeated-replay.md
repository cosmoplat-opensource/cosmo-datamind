# DR-138 · 概念重提与多次回放

> 2026-11-17：[DR-139](DR-139-review-of-dr133-138.md) 给每轮重提的条数加了上限。

状态：已实现。日期：2026-11-16。
关联：DATA-GROUNDING-02、FEEDBACK-REPLAY-02；DR-136、DR-137。

## 背景

- DR-136 移植数据接地时，实验分支上「未通过核验的概念带原因重提」没有移植。实验报告的 +10.8 个百分点是包括这一项在内的整体效果。
- DR-137 的回放只问一次。模型每次写的 SQL 不同，同一个问题在本体不变时也可能得到不同的数据，
  回放显示「已变化」时分不清是本体修改所致还是模型的随机性。

## 决定

- **概念重提**。名称不透明、业务概念步骤改用画像摘要时(DR-136)，一批提议里因表不存在、列不存在、
  筛选条件命中 0 行或无法执行而未通过核验的概念，连同原因、相关表的画像和已核验的「用语 → 列」交给模型重提，
  至多 2 轮。重提后通过核验的概念标 `repaired_round`，构建步骤的说明里给出重提后成立的条数。名称正常的库不重提。
- **多次回放**。单条回放可指定 1–3 次(界面默认 2 次)。各次结论一致时沿用；不一致时记为「结果不稳定」，
  说明答案受模型随机性影响，不能据此判断本体修改是否起了作用。
  批量回放时，结论为「已变化」的题再问一次，两次都变才列为可能退化，否则记为不稳定。

## 没有做的

- 重提只针对业务概念，不针对主题和使用提醒。
- 多次回放把模型调用次数翻倍；没有做本体修改前后的配对检验。
- 移植后的整体效果仍没有在对比基准上重测。
