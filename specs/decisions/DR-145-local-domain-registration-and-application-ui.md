## 上下文 / Context

用户需要在 DataMind 完成本体自动生成、知识完善和行为树生成，单独增加聊天页面无法覆盖此前流程。
现有前端采用 hash 路由、原生 JS、共享设计样式和逐步抽出的 ui/modules。
机器人图谱需要展示调用次序、参数绑定与数据流，现有数据关系图不足以解释这些信息。
领域接入需要可扩展边界，但本轮不需要先实现完整插件平台。

## 决定 / Decision

1. **小型静态注册**：启动时登记随仓库部署的领域配方、载荷适配、验证器和应用，不开发远程插件安装或任意前端脚本加载。
2. **沿用现有 UI 基座**：在 ui/modules 增加模块，复用 hash 路由、图谱选择、样式与作业展示，不整体更换前端框架。
3. **覆盖前段构建**：本体构建页增加机器人配方、两类文件角色、profile 选择、进度和问题定位。
4. **覆盖知识治理**：本体详情与评审提供实体映射、参数依据、适配证据、版本差异、重建冲突和发布入口。
5. **同一知识的三种展示**：本体关系视图回答对象如何关联，行为树视图回答调用结构与次序，数据流视图回答输入输出和黑板变量如何传递；三者来自同一权威版本，不维护三份本体。
6. **独立应用、共享平台**：新增行为树生成入口，组合任务澄清、树预览、参数溯源、验证问题和工件区，保留现有数据问数入口与深链。
7. **能力决定可用性**：根据发布契约和编译器支持报告启用应用，不只检查节点 kind；不满足条件时显示缺口和修复入口。
8. **术语与状态明确**：区分建模提示词技能和机器人动作技能，分开展示结构验证、适配证据、候选生成与执行未验证状态。
9. **演示资产隔离**：real/demo 分别标记并固定到会话，演示资料不能在真实模式作为有效证据。
10. **视图按迭代分步交付**：完整目标包含三种视图，首版可先提供关系图、行为树及节点侧栏中的参数来源和数据流明细，独立数据流画布的交付范围在 IR 中明确。
11. **复用对话入口**：保留已有会话历史体验，增加会话到运行及产物的跳转；业务映射维护放在本体详情和评审中，任务歧义在应用对话中处理。

## 后果 / Consequences

- 正面影响：用户可以在一条连续路径中完成从新来源到可追溯候选的全部工作。
- 正面影响：不必为 UI 整合重写全部数据问数模块，现有产品能力可渐进接入。
- 代价：图谱投影、领域编辑与版本跳转需要新增交互，不能仅复用现有聊天框。
- 代价：第一版是受控领域接入，接入新领域仍可能需要增加渲染器，不承诺内核零修改。
- 影响的文件/路由：领域注册表、ui/index.html、ui/modules、构建/目录/评审/应用/引擎设置/作业中心。
