# DR-159 · Studio 图谱组件与本体构建可视化

- **状态 / Status**：accepted（2026-11-17 用户要求按 SDD 启动 IR-031；T01 冻结技术契约作为 RED 依据）。
- **日期 / Date**：2026-11-17。
- **工作分支 / Branch**：`feat/studio-ui-integration`。
- **关联 / Refs**：[IR-031](../iterations/IR-031-studio-robotics-visualization.md)、[IR-032](../iterations/IR-032-studio-data-visualization.md)、[DR-150](DR-150-robotics-readonly-graph-views.md)、[DR-152](DR-152-robotics-dual-build.md)、[DR-155](DR-155-ontology-detail-experience.md)、[DR-158](DR-158-master-development-integration.md)。

## 上下文 / Context

用户希望在机器人本体构建过程中，通过类别圆圈、关系连线、属性展示和实例展开理解本体如何逐步完善。
当前机器人设计已经具有类别、关系与属性、实例构建阶段及持久化修订，但主要以文字和表格展示。
当前机器人关系画布以实例为主，无法完整表达类别设计阶段。
用户要求保留附件 Studio 的主要风格、拖拽时节点联动及双击类别展开实例的交互。
用户选择先提取共享组件并完成机器人构建与已保存本体浏览，再接入数据本体图谱和构建结果预览，保留问数锚定、证据状态、详情与评审。
只替换画布会丢失当前本体身份、业务状态和操作上下文，使用户无法判断所见内容来自哪个阶段、版本或数据源。

### 当前基线与来源

附件源码位于 `${ROBOTICS_SOURCE_ROOT}/Ontology Studio/Ontology Studio`。
可复用核心为 `static/graph.js`、`static/model.js`、`static/edgeRouting.js`、`static/labelLayout.js` 及相关视觉样式。
Studio 的 SVG 渲染、力导向布局与实例展开已有实现，但不理解 Datamind 的修订确认、资产状态或数据证据状态。
Datamind 接点包括 `ui/modules/robotics-design.js`、`robotics-views.js`、`graph-render.js`、`qa-anchor.js`、`build-stream.js` 和 `ui/index.html`。
本分支数据构建已有服务端作业、恢复与取消流程，不能照早期 SSE-only 评估覆盖其行为。
关系身份沿用 [DR-114](DR-114-relation-identity-includes-role.md) 的源对象、目标对象和角色，不能退回仅凭两端点识别。

### 方案取舍

| 方案 | 收益 | 代价与取舍 |
|---|---|---|
| 提取 Studio 共享组件，由 Datamind 适配数据与操作 | 保留主要交互，同时接回阶段、版本和业务功能 | 本文采用方向；需要统一视图协议与两类适配器 |
| 嵌入完整独立 Studio 页面和服务 | 初期能较快看到原页面 | 双状态与文件流程难以接入当前构建和评审，不采用 |
| 在 G6 上重新实现 Studio 的所有交互 | 延续现有图库 | 需重做已存在的交互和视觉，不作为本轮主方案 |

## 决定 / Decision

1. **分两轮交付，共用组件。**
IR-031 完成共享图谱组件、机器人设计阶段可视化与固定版本浏览。
IR-032 在该组件上完成数据本体图谱、构建完成结果预览及现有业务交互适配。
本轮范围不包含数据本体构建中的结构化增量输出、数据库业务记录实例化、OWL 推理或实机执行。
机器人逐 token 生成节点、Studio 全量编辑器和新导入格式也不在本轮范围内。

2. **画布共享，领域数据和操作由适配器提供。**
共享组件接收只读视图投影、显示状态和交互回调，负责节点、连线、布局、选择、搜索、缩放与展开呈现。
机器人设计、机器人固定版本、数据本体各自转换权威数据，并提供对应详情及允许的操作。
视图投影不是新的本体存储，也不替代 RDF、设计会话、数据 IR、评审日志和资产版本。
组件源码纳入仓库，运行不依赖附件绝对路径、独立 Studio 服务或外部 CDN。
复制范围及来源摘要在实施时登记，排除输出截图、备份、发布包和无关编辑器代码。

3. **以真实设计修订驱动连续展示。**
类别阶段显示类别圆圈及已存在的继承关系。
关系与属性阶段在已确认类别基础上显示对象关系，并通过属性标记、详情和按需展开显示数据属性及类型。
实例构建成功后，按对应产物显示类别实例数量、显式类型归属、实例关系和数据值。
每轮结构化结果通过现有校验并保存后更新画布；等待期间保留最近有效结果并显示真实运行状态。
不得根据日志、计时器或模型未完成文本伪造类别、关系或完成状态。
离线构建直接显示真实完成结果，不虚构 LLM 分阶段设计过程。

4. **保持身份、修订与阅读位置。**
投影携带来源身份：设计会话及 revision，或固定 ontology_id/version_id/payload 摘要，或数据源范围及 graph key 和有效内容修订。
机器人节点以完整 IRI 为身份，视图辅助节点和边使用可重复生成的稳定标识。
数据节点保留当前业务 ID；边保留 role/ref，显示名称不能充当跨本体唯一身份。
同一来源的有效更新保留仍存在节点的位置、固定状态、缩放、选择和展开状态，并区分新增、修改、删除。
物理布局允许自然移动；不得因轮询或输入框变化反复重新初始化全图。
历史修订明确标识且只读，不覆盖当前设计；切换来源不得带入另一版本的内容或迟到响应。
设计退回类别阶段后，失效的关系、属性和实例不得作为当前有效内容继续显示。

5. **保留 Studio 的主要视觉与交互。**
类别使用蓝色圆圈，实例使用可区分的形状，关系带名称，提供图例、详情侧栏、平移缩放、适应画布和搜索。
力导向模式下拖动未固定节点会带动相连的未固定节点，提供固定／释放和暂停布局操作。
双击类别展开或收起其显式归属实例，多类别实例去重但保留各自归属连线。
当前阶段尚无实例时明确说明原因，不能把类别本身当成实例。
父类的推导实例不自动混入显式实例数量；如将来增加继承展开，需另行明确口径。
Datamind 导航、建模输入与确认按钮承载现有流程，图谱详情承载完整定义、来源和待明确项。

6. **正确表达本体语义与业务状态。**
类别关系、继承、实例归属、实例事实及数据值连线有可辨识的类型和说明。
保留已支持的 unionOf 等表达式语义，不能把多个定义域当作任意等价含义，也不能将类别关系当作实例事实。
设计建议、已确认骨架、候选产物、发布／生命周期和应用可用性继续分别表示。
画布出现内容不产生确认、发布、模型调用、任务执行或隐式写入。

7. **数据本体完整接回现有交互。**
问数召回范围与最终 SQL 使用表分别呈现，清除高亮恢复当前本体视图；高亮不更改关系证据状态。
保留 verified、asserted、inferred、candidate、gap 及语义检查结果的区别，颜色与线型有对应图例和文字说明。
节点详情保留定义、绑定表、字段、指标、来源及现有动作入口；关系详情保留角色、证据、字段关联和评审入口。
确认、否决、改动词及撤销沿用 Datamind 现有服务、审计和新鲜度约束，成功后再同步画布。
同端点不同角色分别展示、查询详情与评审；歧义引用拒绝执行，不任选一条关系。
数据本体双击默认可定位或查看详情，不自动将绑定表全量读为本体实例。

8. **构建结果与跨页面一致。**
数据构建仍由现有作业及终态判定完成，恢复、取消、失败处理保持有效。
有效完成结果在共享画布预览，打开主图时保持相同对象身份、关系角色和证据含义。
图谱预览不改变当前数据源、发布资格或问数范围，也不把后续修改的最新图冒称为历史构建快照。
已有固定快照时按快照读取；只有 legacy key 时明确显示为当前有效图及修订，不声称可复现历史产物。

9. **按规模展示并保证生命周期隔离。**
默认先展示类别或业务概念，实例按类别展开；大规模时允许分批、筛选和局部视图，但必须显示已显示数／总数及继续查看入口。
“所有实例”表示对应固定范围内的显式实例均可访问，不要求所有节点同屏，不允许静默截断或近似数量冒充总数。
每个画布实例隔离 SVG 标识、事件、动画与尺寸观察器，多个构建预览并存时不相互影响。
销毁或离开页面释放资源；快速切换、请求失败和资产删除时按当前上下文处理，不展示旧图作为成功结果。
加载失败提供明确错误与重试，不静默回退到 demo 或第一张本体。
继承 DR-157／DR-158 的生命周期、固定版本读取和当前数据库范围规则。

10. **规约与验证先行。**
两个 IR 分别在 T01 冻结视图契约和测试夹具，再按 RED、人审、GREEN、全量回归、人审交付推进。
当前仅编写 DR／IR 和计划验收映射，后续测试函数尚未存在时不得登记为正式已覆盖 requirement。
性能验收在 T01 用代表性本体和固定浏览器环境确定节点／边规模、加载及拖拽响应指标，并在实现前记录具体阈值。
浏览器验收必须实际检查拖拽联动、双击、修订更新、切换及布局，不以源码包含关键字代替行为测试。

## 后果 / Consequences

用户能在同一画布理解机器人本体的逐步形成，并用一致交互浏览两类本体。
领域数据与显示组件分离，后续新增领域可以复用画布并单独实现适配器。
需要承担 SVG 布局性能、视图状态保持、稳定身份、角色关系和业务操作回接的维护成本。
新增／改动影响主要落在共享前端组件、机器人设计与关系页面、数据图及结果预览、投影接口和相关测试。
机器人固定版本已有详情投影可作为数据基础，但须核对表达式和完整 IRI 信息是否足够，缺失时补只读投影而不猜测语义。
本决定实施后局部替代 DR-150 第 2 条的“仅实例”展示范围与第 4 条的 G6 选型；其固定版本、只读和不展示来源行为树的约束继续适用。
任务生成结果的行为树画布不属于共享本体图替换范围，仍按现有任务应用流程验收。
