# DR-095 · 多数据库上下文与可视化切换

状态：已实现，验收记录见报告。日期：2026-10-12。
关联：DB-SCOPE-01、DB-SCOPE-02、DR-080、DR-093；[复核报告](../../docs/audits/2026-10-12-multi-database.md)。

## 问题

原来的 SQL 和可视化工具可以单独选择连接，但总览、目录、图谱、指标和部分辅助功能仍采用默认库。
不同库有同名表时，这种不一致可能返回另一个库的数据，表名存在检查无法发现错误。
200 表库的可视化快捷选项原先只显示前 120 张表。

## 实现

- 侧栏选择已登记、文件可用的 SQLite 数据库。页面请求以 `X-DataMind-Source` 传递来源；`/api/data/context` 返回表数及该来源的本体。默认库继续使用 `demo`。
- 每个请求独立解析来源，不修改进程全局数据库路径。工作线程沿用请求上下文；无效来源返回错误，不自动执行默认库查询。
- 本体按 `build_manifest.source` 对应的实际文件匹配。重复登记同一文件视为同一来源；来源失效或跨库混选本体时拒绝问数。
- 总览、目录、质量、术语、图谱、指标、SQL、同步及流式问数、构建和本体编辑使用当前来源。未构建本体的库可预览、查询和可视化；问数及本体编辑提示先构建。
- SQL 与可视化允许明确选择另一来源。看板的每张图保留自己的来源，页面显示来源名称；所有物理表均可选择。
- 超过 120 个节点的图谱默认采用力导向全图显示，用户仍可手选其他布局或放大查看；单值指标不再标为“末期”。
- 全局切换重新加载页面，保留路由及各来源的表单草稿。会话、SQL 技能、反馈、动作记录、评测文件和数据统计按来源筛选或分开缓存；可视化局部切换丢弃旧请求的晚到结果。
- 非默认库的内置评测问题由本库生成简单行数检查，并单独标识为功能检查，不作为业务问数准确率或论文实验。
- 连接配置、模型配置、任务管理和通用技能仍是工作区级功能。来源选择用于避免数据混用，不替代身份认证或租户权限控制。

## 验证与边界

先用两个含同名表、不同数据及独有表的合成库复现错误，再覆盖并发请求、工作线程、来源失效、显式覆盖、缓存、会话和晚到结果。
场景回归增加 A→B→A 的目录与问数验证。
真实部署验收使用 108/200 表库，查询 200 表库独有的表，检查可视化、图谱、指标及切回后的目录，并校验源库文件未修改。

SQLite 源库始终只读。其他类型连接保留各自已有功能，不在全局 SQLite 选择器中冒充可直接读取的数据库。
本次真实浏览器检查不调用模型；自然语言答案及构建链路的来源一致性由固定模型回复的隔离测试验证。
