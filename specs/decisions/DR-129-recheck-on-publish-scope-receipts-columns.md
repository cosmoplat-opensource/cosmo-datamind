# DR-129 · 发布重新验收、读数前校验范围、无回执的服务端错误、列名匹配、候选可用键盘选

状态：已实现。日期：2026-11-15。
关联：RELEASE-03、ACTION-EXEC-03、QA-SCOPE-01、ANSWER-RECORD-03、EVIDENCE-CARD-02；DR-115、DR-119、DR-124、DR-125、DR-128。

## 背景

对 DR-124 至 DR-128 的独立评审复现了五处问题：

1. 发布接口的说明写的是按当前内容重新验收，实际用的是构建时存下的质量结论。修订号按编辑后的内容算，质量结论却是编辑前的。
2. 执行器返回 HTTP 500 且没有回执时，记录为「失败、未写回」。执行器中途崩溃或前面的代理超时都会产生 5xx，这时业务操作可能已经提交。
3. 使用者只选了部分数据表时，查数路径会拦截范围之外的读取，判定、异常汇总、追踪和试算取参不受这个范围约束。判定是先求值再校验。
4. 数值匹配不看列：同一行里「库存 9.0」能让「覆盖 9.0 天」通过。
5. 依据卡上的候选是没有 `href` 的 `<a onclick>`，键盘聚焦不到。

## 决定

- **发布**。构建之后有人工编辑（编辑后内容的修订号与构建产物不同）时，发布前对编辑后的内容重新执行验收检查，有阻断问题返回 409，并列出阻断问题。
  只看阻断问题：待评审事项和验收问题覆盖不因编辑重算，记录里的质量结论仍是构建时的。没有编辑的图谱按构建时的结论，行为不变。
- **人审否决不算证据冲突**。健康检查里「同一对对象之间既有 verified 又有 rejected」原本一律算阻断。被人否决的关系是裁定结果，不再计入；
  自动判定产生的 rejected 仍算。不改这一条，正常的人审（否决反向候选、否决两条角色关系之一）会让图谱在发布时验收不通过。
- **服务端错误**。5xx 且回执里没有明确的 `ok: false` 时记为「结果未知」，是否写回记为未知，等人核对后处置。
  4xx（请求被拒收）和带明确 `ok: false` 的回执仍是失败。
- **范围**。问数入口把所选范围交给决策层。判定、异常汇总、追踪、试算取参在读数之前先查要读的表：
  判定的规则表在范围之外时说明缺哪张表，不读数据；异常汇总只判定范围之内的规则，其余列出名称说明没有判定；
  追踪要求整条主线（根、各跳、名称表）都在范围之内；试算的参数取值表在范围之外时不取参、不调用动作。判定改为先校验 SQL 再求值。
  没有限定范围时行为不变。
- **列名**。一句话里点了某个数值列的名字（列名本身、去掉单位后缀的列名、三个字以上中文列名的前两个字且只对应一列），
  紧随其后的数字要出自那一列；数值只在别的列里出现的，报告为「属于另一列」。句子里没点列名时不检查。
- **候选**。依据卡上的追问和候选改为原生 `<button>`，页面跳转改为带 `href` 的链接，都有可见的聚焦样式。

## 没有做的

- 发布状态（草案是否可用于问数）仍按构建时的质量结论。非严格模式下，编辑后验收不通过的草案仍可问数，只是不能发布。
- 数据日期表（`clock`）不受所选范围约束，它不是业务数据。问句分型为了认出追踪对象会读根对象的标识列，这一步在范围校验之前。
- 幂等键仍是记录号，重新提交会生成新记录；迟到回执与人工处置的先后没有处理。
- 列名靠文字匹配。英文列名（`late_days`）在中文说明里通常不出现，不会触发检查；同一列的不同时间窗口分不出来。
- 弹窗的焦点圈定与关闭后恢复焦点、图谱对象级深链接没有动。
