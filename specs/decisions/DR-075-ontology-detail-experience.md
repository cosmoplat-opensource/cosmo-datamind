# DR-075 · 本体详情与应用修复体验

- **状态 / Status**：proposed（待方案评审）。
- **日期 / Date**：2026-11-12。
- **关联 / Refs**：[IR-029](../iterations/IR-029-ontology-detail-experience.md)、[总方案](../../docs/datamind-application-contract-design.md)。

## 上下文 / Context

新机器人详情虽然已经展示 TBox、ABox 和覆盖信息，但长表格、原始字段和缺少任务导向的层级使内容难以理解。

## 决定 / Decision

以下为建议方案，用户方向已明确，具体接口和取舍仍待评审。

1. 复用平台现有卡片、边框、间距、主色和按钮规范，统一详情框架；按载荷渲染，不把数据本体强制展示成 RDF，也不改变图谱只显示实例的口径。

2. 首屏展示名称、领域、固定版本和构建方式；机器人详情提供“基于此本体生成行为树”主按钮，未经契约检查或已有缺项均可点击进入检查／补全流程；四张计数卡区分类别、关系定义、实例、实例关系。设计有效、应用可用、任务就绪、执行验证分别显示，不使用一个绿色成功概括。

3. 详情分概览、类别与关系、实例、应用、来源与版本。表格支持搜索、类型筛选、分页和空状态；原始 JSON／覆盖细节放高级折叠区。下载完整 JSON 与 OWL 放固定动作区。

4. 本体构建完成直接入库，无应用选择向导。入库、浏览目录或打开详情不发起应用检查；应用区域仅显示已有检查历史，无报告显示“尚未检查”。点击行为树按钮才自动检查对应契约并进入准备流程；结构检查通过且未提供任务时文案为“可准备任务”而非“可生成”。缺项按层聚合，可展开定位证据；修复按钮深链绑定 asset/version/issue，完成后明确选择新版本并复检。

5. 缺项修复保留任务上下文、返回位置和用户输入；旧版本结果仍可查看且标为历史。加载、空、失败、部分覆盖和检查过期状态各有清楚反馈。状态颜色配文字，表格及按钮支持键盘焦点。

6. 删除入口放“更多操作”，展示影响预览与确认；业务对象删除仍保留原有语义。初期可独立改善详情布局，再接契约和生命周期 API。

## 后果 / Consequences

布局可先实施；应用和删除动作分别依赖 IR-025／IR-028，完整端到端验收在 IR-026／027 之后。
需要版本化检查和修复记录，增加维护成本；换取构建自由、应用诊断和执行一致性。
不改变 IR-024 已交付范围，按新迭代实现并回归。
