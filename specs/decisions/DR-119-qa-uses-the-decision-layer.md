# DR-119 · 问数使用决策层

状态：已实现。日期：2026-11-15。
关联：QA-DECISION-01、DR-117、DR-028、DR-098。

## 背景

DR-117 让图谱能声明约束、工艺路线和数据接入情况，但问数没有用到它们：
上下文里没有约束和规则；「哪些任务拖期了」这类按规则就能判定的问题仍交给模型写 SQL；
「为什么要等 72 小时」这类问依据的问题，模型只能从表结构里猜；
问到还没接入的数据（如实际完工时间）时，模型会拿计划值顶替。

## 决定

问数在生成 SQL 之前先过一遍决策层。每一项都依赖图谱里的声明，图谱没有对应内容时不起作用，问题照常交给原来的流程。

**上下文。** 作用在本次锚定对象上的约束和判定规则全部带入，不靠关键词匹配。

**未接入属性拦截。** 问句包含未接入清单里的属性词时不生成 SQL，直接说明缺什么数据、需要接哪个系统，不用别的字段代替。

**业务词解析。** 概念的别名按最长匹配换成筛选条件；图谱声明了时钟时，把「本周」「下个月」换算成日期区间。

**问题分型。** 确定性规则，不调模型：

| 类型 | 触发 | 求解 |
|---|---|---|
| 查数 | 其余全部 | 原来的 NL2SQL |
| 判定 | 问「哪些、有没有」且命中一条规则，只问一件事 | 规则条件编译成只读 SQL 计数并取样；不能编译时逐行求值，有上限并标明 |
| 解释 | 问「为什么、依据是什么」且命中约束或规则 | 引用约束的内容、参数和依据 |
| 追踪 | 问进度且问句里的编号在主线根表里存在 | 沿图谱声明的主线逐跳查询，每一跳须是已验证或人工确认的关系 |
| 异常汇总 | 问「有哪些异常」且有规则 | 规则本逐条判定计数 |

排名、汇总、一句问两件事、问数据变化原因的，一律交给查数。求解出错或被本体约束校验拦下时退回查数，原因写进执行记录。
非查数类型的答案不进缓存。

**依据卡。** 每个答案附一张卡：结论、依据（实际执行的 SQL、用到的约束、命中的规则、沿途的关系）、关键值、提示、下一步。
查数答案也有：列出 SQL 实际用到的对象上的约束，指标口径未核验、对象数据只部分接入时给出提示。
卡片内容全部来自结构化结果，不由模型生成。

规则在 `qa_decision.py`，不依赖 Web 层；界面模块是 `ui/modules/evidence-card.js`。

## 从演示分支带过来的范围

带入了上述各项。没有带的：

- **推演**（新增一单能否按期、设备停机影响谁）：需要调用排程执行器做试算，主线没有执行器。
- 应用内的 Copilot、口述判断转规则、规则的定时监控。

## 没有做的

- 表格、问数叙述和依据卡的数字还不是出自同一条结果记录。依据卡只保证自己列出的 SQL 和计数是实际执行的。
- 分型用的是固定词表，换一种问法可能落回查数。落回查数不会答错，只是少了确定性求解。
- 工艺路线（`routes`）是概念层的声明，追踪用的主线（`main_chain`）是数据层的声明，两者还没有打通。
