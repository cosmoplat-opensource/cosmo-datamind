# DR-105 · 构建页凭作业号接续，可取消

状态：已实现。日期：2026-11-13。
关联：BUILD-UI-02、DR-101、DR-103。

## 问题

构建已由服务端作业持有，但构建页只认自己打开的那条事件流：
连接一断就显示「未收到完成结果」，尽管构建在服务端照常完成；刷新页面后进度和结果都看不到，
只能去已构建本体列表里找。页面上也没有取消构建的入口。

## 决定

- 发起构建后，页面把响应头里的作业号连同本轮诉求记在浏览器本地存储里；构建以完成或失败结束时清除。
- 事件流中断时，不直接报失败：按已收到的事件数向 `/api/build/jobs/<id>` 长轮询接续，直到作业结束。
  构建自身的失败（error 事件）不接续，照常报失败。
- 进入构建页时，如果本地记着一个作业：仍在运行就跟到结束；已完成就显示结果；
  已取消、已中断或失败就显示原因。作业记录不存在时如实说明「未确认完成」。另一个数据来源下发起的作业不在当前来源下接续。
- 构建进行中显示「取消构建」按钮，调用取消接口；取消在当前步骤完成后生效，页面上如实提示。
- 连不上服务（网络错误）时保留作业号，稍后刷新可再次接续。

## 边界

- 作业号只存在发起构建的那个浏览器里；换一台设备看不到进行中的构建，只能在已构建本体里看结果。
- 接续时过程输出从头重放，量大的构建会重新渲染一遍。
- 按计划逐轮构建时，接续的只是当前这一轮；计划本身不恢复。
