## 上下文 / Context

DR-064 统一了方法。本轮让电子制造与能碳两个场景各自带着**原始资料**(数据、代码包、Word 文档)
从头走完平台流程——接入、体检、取证、提议、裁决、复核、问数——逐环节看哪里不通用。
发现的断点几乎都是两边共有的:

| 环节 | 断点 | 影响 |
|---|---|---|
| 取证 | 上传的 zip 与 docx 不读 | 两边最强的证据(后端 SQL、前端代码、接口文档)上传后未进入构建 |
| 取证 | 代码只当普通文本 | 连接、码表契约不参与裁决 |
| 裁决 | 「子键 = 修饰词 + 父键全名」不算键名相容 | 设备 → 类型目录、系统 → 类型目录这类关系不满足命名条件 |
| 裁决 | 父键不唯一的成因只认软删除与少量版本重复 | 维度表按租户(工厂)复用编号、字典编码按分组复用,相关关系均被拒 |
| 兜底 | 模型超时后回退构建全库 | 分轮构建时把 594 张表全建一遍,湖仓会更严重;还把注释元数据表建成对象 |
| 问数 | 只在主库与上传库执行 | 用抽样库建的本体(两边都是)不能问数 |
| 问数 | 口径校验只认示例本体的关系形状 | 自建本体上的异名键 JOIN 均被拦截,包括已验证的关系 |
| 问数 | 中文问句只做整词匹配 | 「计量器具」召回不到「能源计量器具」 |
| 问数 | 按编号关联不带租户 | 不同工厂同号区域被串在一起,实测计数虚高 |

## 决定 / Decision

1. **读取 zip 与 docx**(`code_contracts.read_zip / read_docx`):内存中读取,只取代码与文本类成员,
   单成员 1MB、总量 4MB 上限,不落盘;兼容 GBK 文件名;docx 去掉域代码,表格一行一条。
   **读入时去除 URL 主机与 IP 地址**,不让内网与测试环境地址进入提示词。
2. **代码契约**(`code_contracts.extract / resolve / resolve_codebooks`):SQL 的 FROM/JOIN 别名与 ON/WHERE 等值条件
   → 连接契约;字典表按字面量分组过滤 → 码表契约(按子句配对);前端的接口路径与 dictCode。
   代码表名按词根后缀对到库表(t_line_zone → dim_line_zone;DR-067 改为更短后缀覆盖整族时取整族),列名去掉 ≤3 字母前缀再对(wd_zone_sn → zone_sn);
   信封列连接(租户、部门)不作为业务连接。连接契约在裁决中**只替代命名证据**,重叠率、父键唯一门槛不变;
   契约写入关系证据与 `scenario.code_contracts`,交叉复核把它算作一条独立支持。
3. **有效行四规则**(交叉复核):软删除;版本重复(重复 ≤5%,或同键名称一致 ≥80%);**租户作用域**(父表「租户 + 编号」
   唯一且子表按租户对得上);**分组编码**(按代码码表契约限定分组,可叠加租户)。有效行上父键唯一且键名有据
   (含代码契约)的候选升为已验证,原裁决与规则写入证据;验收规则承认这四种写明规则的有效行唯一。
4. **命名规则**:子键词根以「_ + 父键词根」结尾、且父键词根足够具体(至少两个词,或 ≥6 字母且非 status 等泛词)
   时视为相容。
5. **兜底构建守范围**:quick_build 接受本轮表范围,并排除 `_dm_*` 元数据表。
6. **按来源库问数**:所选本体都来自同一个已登记的 SQLite 数据源时,本次问数(可用表、口径校验、执行、上下文统计)
   都在该库上进行,请求结束即复位;图谱列表按来源库判断可否问数。
7. **口径校验与 JOIN 提示**:按统一的关系规范化读取自建本体的关系;代码契约关系不因键名不同被丢键;
   租户作用域与分组编码写进 JOIN 提示(`AND a.租户 = b.租户`、`AND 字典.分组 = '值'`),SQL 缺了就拦截并说明。
8. **中文召回**:本体中文名里有连续三个汉字出现在问句中即算命中。

## 后果 / Consequences

两个场景各带原始资料,用同一组技能(三个通用 + 各自领域)构建一轮并问一个问题:

| | 电子制造(业务采样 + 后端代码包 + 接口文档) | 能碳(实库抽样 + 前端代码包) |
|---|---|---|
| 读到的契约 | 连接 26 条(对上库表 6 条)、码表 3 条、字段含义 101 条 | 前端字典引用 1 处(能源类型)、接口 7 个 |
| 字段中文名 | 按代码注释补全 21 个(zone_sn = 线别ID 等) | 库表注释已有 |
| 已验证关系 | 4 条:过站 → 工单(版本重复)、过站 → 区域(代码契约 + 租户作用域)、过站 → 字典(码表分组 + 租户)、直通率 → 区域(租户 + 编号) | 11 条,其中 2 条经软删除、2 条经版本重复复核成立 |
| 问数 | 在来源库上执行;各线别过站记录数与库内直接统计一致 | 在来源库上执行;各类计量器具台数与库内直接统计一致 |

修复前的同一问题:电子制造按编号关联区域、不带工厂,线别过站数被算成实际的两倍;能碳关联类型目录不排除
已删除行,液体流量计台数被算成实际的两倍。现在两者都会被口径校验拦下并提示补上条件。

- 新增单测 27 项(967 总数)。模块与技能不含客户、厂区、库名或主机地址;读入的代码与文档已去除内网地址。

## 备选与不做 / Alternatives

- **契约直接判定已验证**:不做。代码可能过时或只覆盖部分场景;契约只替代命名证据,数据门槛不变。
- **租户作用域时自动改写问数 SQL**:不做。改写会掩盖模型生成的问题;拦截并说明,让模型按提示重写。
- **外部 Hive/Paimon 抽样**:仍未做,需要内网与驱动;两场景其余环节已一致。
