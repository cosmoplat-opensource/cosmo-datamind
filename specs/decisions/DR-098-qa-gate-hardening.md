# DR-098 · 问数校验补漏：连接写法、范围、不存在的列、降级与投票

状态：已实现。日期：2026-11-13。
关联：QA-GATE-02、QA-GATE-03、QA-DEGRADE-01、JOB-01、DR-055、DR-069、DR-080、DR-081；来源为 2026-11-12 代码审查。

## 问题

本体约束校验用正则读 SQL，只认 `ON a.x = b.y` 这一种写法：

- 带括号的 `ON (…)`、`ON` 里 `AND` 之后的第二个等式、逗号连接或 `CROSS JOIN` 配 `WHERE`，都不经过键校验，也不触发扇出检查。
- 逗号连接里第二张及以后的表、加了引号的表名不被解析，表白名单对它们不起作用。
- SQL 注释里出现的词被当成表名，造成误拦。
- 列名写错的语句显示「本体校验通过」，到执行时才报错。

另有四处：

- 模型发出的探查查询只检查只读，不受所选本体或数据表范围约束，可以读到范围之外的表并把结果送回提示词。
- 引擎超时后的内置模板答案写入缓存，之后同一问题直接返回它，看不出是降级结果。
- 多路候选投票时，两路各自查不出行的候选结果键相同，以 2 票压过唯一查出数据的一路。
- 评测线程、技能对比线程抛异常后，任务状态一直是「运行中」，之后每次启动返回 409，只能重启服务。

## 决定

- 校验前先规整 SQL 文本：去掉注释，去掉简单标识符外面的引号，单引号字符串原样保留。
- 逗号连接的各张表同样登记别名并过表白名单。
- 键校验看语句里所有「别名.列 = 别名.列」。紧跟 `ON` 的等式按原规则处理；
  其余等式只在两侧都是已登记别名且不是同一个别名时当作连接条件，同一张表内的列比较不算。
- 校验通过后用 SQLite 准备一次语句（`EXPLAIN`，不读业务行）；报「no such table / no such column」时在校验阶段拦下并说明。
  其他准备失败不在这里拦，留给执行环节。
- 范围检查拆成独立函数 `_qa_scope_check`，探查查询执行前同样调用；越出范围的探查返回「拒绝」及原因。
- 改用内置模板作答时，响应带 `degraded: true`，不写入缓存；答案卡片显示「引擎未响应·内置模板结果」。
- 投票时，只要有一组结果非空，空结果组不参与比票；全部为空时行为不变。
- 两个后台线程在入口捕获异常，把任务标回未运行并写明中断原因。

## 没有改的

- `USING (…)` 连接、未带表名前缀的聚合列（`SUM(col)`）仍不在键校验和扇出检查之内。
- 校验仍基于正则，不是完整的 SQL 解析；子查询里的别名与外层同名时可能误判。
- 精确作答模式在所有候选都被拦下时，仍会执行第一条被拦下的查询并标注未通过校验（DR-086 的既定行为）。
- 内置模板里针对示例库写死的 SQL 未改。
- 外部库（MySQL、PostgreSQL）的只读保证仍只靠关键字检查。
