## 1. 现状、问题与实施顺序

`ui/modules/robotics-assets.js` 的 `designDetails` 一次生成所有类别、实例和断言行，即使折叠也已写入 DOM。
当前页面没有详情标签页、搜索和分页，完整覆盖报告也直接序列化进页面。
`application_design` 已从服务端返回，但详情只在 `d.design` 存在时展示类别与实例。
若直接展示应用版本的 `origin.design_snapshot`，会把历史设计误当成当前应用事实。
应用摘要已有 `not_assessed / supported / unsupported` 及 `freshness`，目前页面没有统一的过期状态反馈。
继续沿用旧详情会让大本体难以浏览，也难以区分设计、应用、任务和执行的不同状态。

按 2026-11-16 用户人审调整采用四标签页和四张摘要卡方向；不增加另一套设计系统。
本轮先完成详情展示与现有机器人检查／修复导航；IR-028 的数据问数适配、IR-029 的删除恢复另行交付。
删除 API 未交付前不展示可执行的整份资产删除／恢复按钮，不复用旧文件物理删除接口。
未来删除入口放更多操作，接入影响预览、revision 和确认；T04 可验证“未提供能力时无写入入口”，不能宣称完成 IR-029。
数据本体继续使用现有数据图谱／问数入口，不改成机器人 RDF，也不为浏览新增应用检查。

## 2. 页面结构与动作

固定入口为 `#library?asset=<ontology_id>&version=<version_id>`，继续使用 `RoboticsAssets.page('library')`。
头部显示名称、领域、固定版本序号、构建方式和发布状态。
机器人主动作保持“生成行为树”，绑定所选固定版本并进入 `assess=1` 检查流程。
未检查、有缺项、过期均允许进入诊断；按钮可用不表示允许直接生成。
2026-11-13 用户确认的后续优化：点击后仍先应用预检，新鲜检查通过即直接进入任务对话，不再停留成功中转页或要求点击“继续描述任务”。
任务对话页内展示“可准备任务”和独立的执行验证状态，具体任务补全与生成前复核继续保留。
缺项、过期或失败留在诊断页，分别提供修复、复检或重试入口；此优化由 T04 RED／T05 GREEN 落地；T04 已审，T05 实现及全量回归通过，T06 的 20 项真实副本技术验证已通过，已于 2026-11-16 获用户确认交付。
下载完整 JSON、OWL 与打开图谱保持固定版本；历史版本不自动解析成 latest。

头部之后为四张摘要卡，辅助技术名称为“类别数”“关系定义数”“实例数”“实例关系数”。
随后为“概览”“类别与关系”“实例”“来源与版本”四个 tab，首开“概览”。
每次仅挂载活动 tab 的表格／原始详情；不在隐藏容器内预先渲染全部行。
切换 tab 不改变本体版本，不创建任务、适配或检查记录。
T05 完成 tab 的键盘方向键、Home/End、焦点与 aria-selected/aria-controls 对应关系。

## 3. 可信读取与详情投影（T02/T04 一并评审）

继续复用 `GET /api/ontology-assets/<oid>/versions/<vid>`，不新增存储 schema 或模型调用。
增量字段 `detail_view`，仅作为可信服务端验证固定载荷之后的展示投影；原有字段继续兼容。
投影的 `ontology_id / version_id / payload_sha256` 必须与版本外层一致。
展示投影不携带 ready 授权，不替代生成端的最终复核。

投影包含：

- `classes / object_properties / data_properties`：沿用设计术语的 id、label、definition 和父类／定义域／值域／数据类型。
- `individuals`：id、label、class_ids、group；group 为 business / skills / other。
- `object_assertions`：subject、property、object。
- `data_assertions`：subject、property、value；保留值类型和原始语义。

设计 v1 从通过完整性验证的当前 TBox/ABox 提取。
应用 v2 从通过 JSON/OWL 一致性验证的 `current` RDF 提取，不从 `origin.design_snapshot` 取当前事实。
旧 UR 从当前固定 RDF 提取，复用既有语义及分组规则；只有类别声明不产生实例。
同一实例有多个类型时只计一次，类型筛选使用完整类型 id，不按展示标签合并。
业务分组由可信类型／角色映射确定，不仅凭中文名或任意 namespace 的同名术语推断。
空或未知字段用明确的未记录状态；未知工件版本／损坏工件继续报错，不伪装成空本体。
T02 使用合成可信响应验证前端展示；T04 必须以真实持久化版本验证投影来源、身份和只读边界。

## 4. 计数与表格

类别数 = 当前去重类别声明数。
关系定义数 = 当前对象属性声明数；数据属性数单列于类别与关系 tab，不混入关系定义。
实例数 = 当前去重个体数，实例关系数 = 当前个体间对象断言数；数据断言与 rdf:type 不充当实例关系。
摘要反映整个固定版本，不随搜索、类型或分组筛选变化。
类别、对象属性、数据属性、实例、对象断言、数据断言分别展示，不能把“技能类别数”当作“技能实例数”。

实例表默认每页 25 行，按稳定 id 顺序显示；360 实例为 15 页，最后一页 10 行。
提供“搜索实例”（匹配名称或完整 id，忽略大小写）、“实例类型”（完整 id）及“展示范围”（全部／业务／技能／其他）。
多个筛选取交集；筛选／搜索变更回到第一页，清空恢复全量第一页。
上一页、下一页在边界禁用，显示筛选后总数和当前页。
类别和断言列表同样按需分页，不在首屏预生成全部原始 JSON。
空搜索结果显示“没有匹配的实例”；业务组为空显示“尚未包含业务对象与配置实例”，并说明类别定义不等于实例。
整个本体无实例时可显示“尚无实例”，不能仅因业务组为空就宣称本体为空。
名称、id、定义、值和报告消息均按文本转义；长 IRI 可换行或在表格内部滚动，不能撑破页面。

## 5. 检查状态与历史

| 已有摘要 | 应用展示 | 动作含义 |
|---|---|---|
| not_assessed | 尚未检查 | 可进入诊断 |
| supported 且 current | 可准备任务 | 点击入口后完成新鲜检查即可直接进入任务对话；没有当前任务时不显示本任务可生成 |
| unsupported 且 current | 有缺项 | 可进入诊断并查看问题 |
| 任意已存报告且 freshness 非 current | 检查已过期 | 历史结果可读，先复检再使用 |

过期优先于旧 supported，不保留当前可用的成功文案。
展示设计／结构、应用检查、任务就绪、执行验证四个独立维度；没有任务显示“尚未提供任务”，没有执行证据显示“执行未验证”。
不得从设计有效、结构通过、离线候选或应用准备可用推断现场执行已验证。
概览中的应用检查区域只读已有摘要；需要问题明细时只读既有 check_id 对应报告，不能发起新的检查 POST。
缺项、部分覆盖、加载和读取失败均带文字反馈，不仅靠颜色。
覆盖统计放概览，完整报告和原始内容只在高级区由用户展开时挂载。

### 9.1 新检查通过后进入任务对话

从详情或图谱点击行为树入口后先发起检查，仅 freshness=current 且 preparation_status=available 可自动进入任务对话。
任务页内显示“可准备任务”和独立执行状态，保留 check_id 用于追溯；不再要求点击成功页的“继续描述任务”。
已有会话复检后返回原 session_id、固定版本和未提交输入，不另建任务。
重复点击、检查回复丢失后重试、任务已受理但回复到达前刷新，均不得重复保存检查或创建额外会话。
切换本体版本后到达的旧检查响应不能触发跳转或任务受理。
报告过期时显示“检查已过期”并提供“重新检查”；检查请求失败时提供“重试检查”，保留明确错误反馈。

### 9.2 概览检查状态与已有记录兼容

按 2026-11-16 用户人审要求，详情仅展示应用检查状态，不提供“查看检查详情”和“查看任务与生成记录”入口。
既有报告路由继续只读已存报告，即使报告准备可用也不因查看而自动创建任务。
该只读查看意图必须与用户主动生成的检查流程区分；不要求新增 API，可使用已有报告读取路由并在导航中保留只读意图。
既有历史路由保持兼容；已有 session／run 绑定原固定版本，查看和下载不发起新检查、模型或任务。
可以复用既有历史页面，不强制新增历史查询 API；历史查看和新的任务准备是不同的用户动作。
缺项诊断沿用“修订本体骨架”和“核对角色对应”两条路径，分别绑定原设计会话和固定本体版本。
进入角色对应流程不冒充已经补齐骨架，也不在缺类时直接产生应用版本。
过期的修复深链必须由服务端拒绝，原本体字节保留。

### 9.3 固定版本与历史可用性

投影验证完整 IRI、类别／实例区分、多类型去重和分组语义，不按任意 namespace 的同名术语认定业务角色。
设计 v1 和当前应用版本分别与可信原工件／当前业务事实对照，固定 JSON／OWL 下载不能滑到 latest。
未知工件版本、损坏载荷、错误 asset/version 或历史工件篡改继续明确拒绝，不以改善可用性为由跳过完整性检查。
历史读取的文件校验延迟时，无关元数据写入应能提交；文件验证不应长时间占用 SQLite 读事务而诱发 database is locked。
并发测试只用受控延迟验证读事务边界，不将单次真实历史请求超过 20 秒解释为已冻结的通用响应 SLA。
真实大资产时延与用户副本仍留待 T06 记录基线；读取完成前后的固定身份和工件完整性必须继续验证。
数据图谱、旧 UR、加载／失败反馈和键盘 tab 保持回归；IR-029 生命周期 API 未接入时没有整份资产删除／恢复写入动作。
