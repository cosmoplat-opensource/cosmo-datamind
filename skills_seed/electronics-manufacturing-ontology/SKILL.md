# 电子制造(SMT/PCBA)本体半自动构建

通用做法见 `ontology-build-method`;本技能给出这个领域「建什么、以什么为枢纽、哪些陷阱先识别」。

## 1. 先归并再建

制造数据中台常把同一实体按「层级_厂区_来源约定_业务词根_变体」复制成几十张表
(多个工厂、贴源层(ODS)与明细层(DWD)、离线与备份副本、仓储站点分表)。一个表族建一个概念,
代表表取正本(明细层优先,其次维度层、贴源层);跨厂列名不一致不拆族。

## 2. 概念骨架(按需取用,没有证据就不建)

- 组织与产线:工厂、车间、产线、区域 / 工位、工序分组。
- 主数据:物料、物料清单、工艺路线、工序、设备、供应商、客户、不良代码。
- 计划与执行:生产订单、生产工单、生产项目(批次)。
- 过程事件:备料与上料、在制品(WIP)过站、测试(SPI 锡膏检测 / AOI 自动光学检测 / ICT 在线测试 / FCT 功能测试,各为独立概念,不合并)、
  不良与返修、完工出入库、包装与托盘。按「上料 → 过站 → 测试 → 不良 → 返修 → 包装 → 入库」建事件链。
- 追溯标识:产品序列号、板码与拼板码、双码关联、托盘条码。序列号贯穿各事件表,是追溯主线。
- 质量与效率指标:直通率(FPY)、不良率、设备停机率、理论效率。按指标口径建,口径从看板与接口文档中确认。

## 3. 枢纽与关系

- 工单号、项目号是最大枢纽:过站、测试、返修、包装等事件经工单号或项目号挂到工单、项目。
- 区域 / 工位、工序分组、物料是维度;事件表按区域编号、工序分组编码、物料编码关联。
- 键名不同但数据对得上(如区域序列号 ↔ 区域编号、生产物料编码 ↔ 物料编码)时,关系因键名不相容而停在候选:
  以代码契约或人工确认升级,不要为通过校验而改动键名。

## 4. 这个领域的常见陷阱

- **版本重复**:主数据在湖仓里多次入仓,工单号、物料编码看起来不唯一。按键取最新后再判唯一。
- **类型对齐**:贴源层字段全为字符串;物化到本地时若按整数存,取值重叠会假性为 0。
- **时点对齐**:月分区与日分区混存;子表按同一时段切片,父表取全量键集,否则重叠率偏低。
- **信封列**:租户、组织、公司编码、工厂编码、审计与分区列几乎每张表都有,共享它们不构成关系。
- **同族副本**:同一实体的副本之间取值必然重叠,这类边不是业务关系,标注后合并。
- **测试与临时表**:贴源层常混有测试、临时、个人备份表,不进入概念层。

## 5. 多源证据

- 后端代码:数据访问层 SQL 的 JOIN ON 就是连接契约,优先于命名猜测;视图对象与查询对象的字段给出中文口径。
- 指标接口文档给出术语与口径;看板口径表给出指标候选与计算逻辑。
- 验收问题示例:某工单的直通率;某序列号的全流程追溯(过站 → 测试 → 返修 → 包装);某产线某日的不良排行。
