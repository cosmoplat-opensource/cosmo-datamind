# 机器人领域内核 — DR-059 / DR-060 / DR-061 / DR-062 / DR-065 / IR-016 T09

当前提供离线构建、RDF 语义读取、OWL 发布与消费校验、固定模板实例化和符号检查。
公开调用入口接受显式输入，不依赖 yang 归档路径，不读取导入时资产，也不启动服务或连接机器人。

| 模块 | 职责 |
|---|---|
| importer、source_validation | 校验受支持的 XML/profile 与模型一致性，保存来源摘要并确定性构建 RDF |
| graph | 原领域词表与 RDF 构建原语，保留类、实例与类型化属性 |
| profiles/ur_pick_place | 四棵树的固定步骤、角色、复合接口、条件及未确认示例知识 |
| semantics | 只读 RDF 恢复执行树、节点契约及公开参数位置，不解析归档 sourceNodeXML |
| compiler | 基于明确基线和图中推导的位置绑定公开配置，输入模板不被修改 |
| validator、xml_contract | 模板一致性、数值/接口校验及符号数据流，不推断真实执行成功 |
| publisher | 核对并归一化重复端口属性，封装协议及规则；实际输出经消费复验后原子创建新文件 |
| consumer、artifact_contract | 自包含 OWL 加载、可信规则/条件检查、固定模板和数据流校验，不依赖相邻文件 |
| grounding | 按本体定位任务实体，检查业务确认、Profile 参数与适配证据，不回写知识 |
| generation | 严格任务生成与显式作者草稿入口，校验后写工件，区分澄清、缺知识、不支持、错误和成功 |
| demo | 显式演示补充：核对来源，仅修改业务映射、公开参数和模拟证据，返回独立图与变更清单 |
| offline_demo | 串联三类实际场景，核验工件、记录输入/输出摘要和结果，隔离每次运行 |

算法来自已在 T01 记录摘要的 yang 构建侧函数，按职责提取，未整包保留旧服务或通过 sys.path 转发调用。
源文件中未写类型的 SubTree 接口从内部原子端口唯一推导；原子端口模型的方向和类型冲突必须拒绝。
固定步骤定位只保留在受明确模板约束的 UR 来源知识抽取中，编译公开参数位置从 RDF 绑定推导。

compiler.instantiate 是结构性原语，不能直接作为面向用户的正式生成 API。
allow_unresolved 默认为 false；只有 create_authoring_draft 显式使用宽松选项，不能据此绕过严格任务证据检查。
离线演示命令见 [运行说明](../../docs/robotics-offline-demo.md)。
平台 API、知识编辑和 IR-024 模型辅助构建已接入，当前范围见 [双路径指南](../../docs/robotics-dual-build.md)。
`modeling` 包复用平台模型进行 TBox 设计，ABox 按确认骨架执行确定性规则；新设计候选单独验证，UR 行为树消费者保持独立准入。

发布采用 `ur-pick-place-owl-v2`，原子参数的名称、方向和类型从 mapsToPort 指向的端口读取。
构建草稿中的重复属性只有与端口值一致才可移除，矛盾数据拒绝发布，原图不变。
发布文件保存完成并通过消费复验后才出现在目标路径；目标已存在或并发抢占均拒绝覆盖，临时文件在结束时清理。
调用者须提供已存在的父目录；当前实现使用同目录硬链接，适用于支持硬链接的本地文件系统。
加载校验以一次读取的字节快照为准，摘要对应返回的图；不依赖之后路径中的文件内容。
发布/加载不意味着业务证据齐全；作者未解决值不能据此进入严格候选，执行状态始终未验证。

generate_task 接受 consumer.load_ontology 的上下文、六字段结构化任务、real/demo 模式和输出目录。
检查实体选择、映射、参数与证据后，复核已加载的图快照、发布协议、固定结构及数据流，再写候选。
草稿 create_authoring_draft 接受同样的加载上下文和公开参数字典；省略参数产生明确占位值，始终不声称已生成严格候选。
两个入口都不修改传入的图或配置，已有同名输出拒绝覆盖；调用者为新运行选择新目录。
XML 是生成工件，不作为独立可编辑知识源；缺口由工程师补充本体中的配置、映射和依据后重新发布生成。
本轮不包含在线 XML 编辑器，也不验证 LLM 提取与原始自然语言是否一致。
